# EMERALD DSH AI 平台原型 · v4

定位是企业 AI 工作平台，不是 Listing/DVP 专用页面，也不是插件介绍页。平台前端独立演进，后续通过版本化适配层接入 DSH。当前版本是**交互与状态原型**：不连接模型、不执行工具、不读取文件内容。

## 结构

| 文件 | 职责 |
|---|---|
| `app.js` | 路由、通用视图、事件与保存状态展示 |
| `applications.mjs` | 应用贡献（名称、用途、选项、资料角色、建议、预设方案、结果类型）与目录检索 |
| `model.mjs` | 项目、分项目/应用草稿、输入修订、归档、结果预览与校验的纯函数 |
| `storage.mjs` | v4 加载、v3 一次性迁移、异常隔离、保存与多标签冲突检测 |
| `tests/` | Node 内置测试，不依赖浏览器或真实数据 |
| `verify.mjs` | 语法检查与测试入口 |

界面不含 Listing/DVP 内部方法分支。新增应用只需提供贡献数据；第三测试应用和 100–200 条合成目录只用于测试，不发布为真实业务应用。

## 本版体验

- **应用中心**：按用途、名称或关键词搜索，支持收藏、最近使用与分页；工作区只展示当前应用和“更换应用”，不为每个插件增加导航。
- **分上下文草稿**：草稿按“项目 + 应用”分别保存，切换后恢复；重复选择当前应用不改变资料。新建工作时可继续已有草稿或显式清空。
- **工作与输入修订**：工作保存应用版本快照、项目配置快照、创建时间、输入修订、消息与来源。补充要求或增删资料形成新修订；结果预览绑定当时修订，旧修订不被改写。
- **归档只读**：归档与结果预览分开。归档后禁止补充与改资料，历史结果仍可在工作页和成果文件查看、下载原型说明；“基于此工作新建”建立新的工作区草稿。
- **保存可靠性**：顶部显示“已保存到本浏览器 / 仅本页保存 / 保存冲突 / 记录未载入”。失败时保留本页内容并提供备份下载；检测到其他标签页更新时不自动覆盖。
- **旧记录迁移**：v4 不存在时读取 v3，保留原 v3 缓存；Listing 类型转换为应用选项，DVP 丢弃无关类型。旧记录未保存项目快照、归档覆盖过的结果状态时明确“未记录”，不猜测补全。单条异常记录进入恢复区，不影响其他记录；整库无法解析时保留原始内容并可下载。
- **资料上限**：所有添加入口共用 30 个上限、同名去重与反馈。历史超限记录完整保留为只读，不截断。

## 原型与真实能力的边界

提交工作只保存草稿并显示预设方案；没有 AI 推理、执行、自动诊断或后台任务。示例结果只是界面示意，文件标为未生成；唯一可下载内容是明确标识的 Markdown 原型说明。

添加本地文件只使用浏览器 File 对象的名称，不读字节、不上传。项目目录只保存文本，不访问本机或服务器。浏览器缓存不是企业任务库，不支持多人协同。应用目录、搜索、收藏与归档只影响本机演示；浏览器筛选不是授权。

真实企业目录、工作/Run 持久化、身份与项目授权、DSH 执行接入均未完成。正式平台应读取服务端应用注册与工作投影；`packages/platform-control` 的现有合同仅作为对齐参考，本原型不直接连接其工具或数据库。

## 打开

预览配置为 `enterprise-workbench-prototype`，地址 http://localhost:3081。静态服务器只提供白名单原型资源与新增模块，不提供测试、备份或目录列表。

```bash
node scripts/preview-enterprise-workbench.cjs
```
