# 临床 Listing 插件审查报告（修订版）

> 时间：2026-08-27
> 修订说明：根据「dsh 插件开发最高原则」修正——最大化 AI 推理，程序只做机械交付与信息供给，禁止写死业务定义。

---

## 1. 核心原则（决定何为漏洞、何为正确）

> **不写死业务定义，最大程度利用 AI 推理；程序只做机械交付+信息供给。**

由此推出三条红线，凡是违反的就是真漏洞：

1. **不写死业务逻辑**——禁止按 sheet 名 / 列名 / 行号 / 场景枚举去 switch。脚本里所有"case 'rbqm': ... case 'medical': ..."都是历史污染。
2. **不写死业务读取**——禁止按 sheet 名 / 行号 / 列号 / 字段名读取数据。要探索式读取就交给 AI。
3. **不写死出域开关**——只有两种场景值才做拦截：
   - 数据要送进 AI（read → AI）→ 拦截出域
   - AI 生成产物要写回（AI → write）→ 拦截入域
   - 其他环节（解压 / 密码推导 / 读 spec / 读 als / 读 template）→ 完全交给 harness / AI 操作，程序不做任何判断。

### 1.1 边界澄清：样式规范 ≠ 业务定义

原则禁止的是"写死业务定义"（列结构 / 场景识别 / 数据语义），但**样式规范属于"输出标准"，必须保留**——这是企业产品的视觉一致性约束，不能让 AI 自由发挥。

区分方法：

| 类型 | 属于业务定义（禁） | 属于输出标准（保留） |
|---|---|---|
| 列结构 | `COMPARISON_COLUMNS = ["N_R", "N_C", "I_V", ...]` | — |
| 标签文案 | `COMPARISON_LABELS = {"N_R": "Number of records"}` | — |
| 场景分支 | `if scenario == "report": ...` | — |
| **颜色** | — | `PALE_BLUE`、`WHITE` 等填充色 |
| **字体** | — | `HEADER_FONT`、`DATA_FONT`、`SHEET_TITLE_FONT` |
| **字号 / 边框** | — | 字号常量、边框线型 |
| **行高 / 列宽** | — | 默认行高（60）、列宽算法 |
| **对齐方式** | — | `HEADER_ALIGNMENT`、`CENTER` |
| **冻结窗格算法** | — | `freeze_panes = "A3"`（数据行起始位） |
| **筛选范围** | — | `auto_filter.ref` 覆盖 header+data |

样式标准的判断标准：**不影响"这条数据是什么"，只影响"这条数据长什么样"**。列结构是业务，排版样式是输出标准。

### 1.2 输出标准的保留粒度

- **保留为常量**：`PALE_BLUE / WHITE / HEADER_FONT / DATA_FONT / GRID_BORDER` 等纯视觉常量
- **保留为算法**：列宽自适应 `max(14.71, min(50.71, len(label)+2))`、冻结窗格位置（由 header 行数决定）
- **保留为默认值**：单元格默认字体 `Calibri 11pt`、默认行高 60
- **不写死位置**：第 1 行必须放什么、是否放 HYPERLINK、是否合并 A1:F1、要不要 Go back 链接——**这些是 AI 自由组合的排版选择**，不是输出标准

因此修订后的整改清单（V3）应该改成：**_build_listing / _build_report_sheet 保留全部样式常量与算法，但删除"Row 1 必放 HYPERLINK / Row 2 必为 Label / A1:F1 必合并 / 标题必在 B1"这些固定排版决策**。

## 6. 最高原则的另一个维度：信息供给（新增）

> **不写死业务定义，最大程度利用 AI 推理；程序只做机械交付+信息供给。**

上面 V1-V6 / R1-R7 都是从"程序越权写死业务"的角度审计。但原则还有后半句：**信息供给**——程序有义务把临床数据的真实形态主动暴露给 AI，而不是让 AI 盲猜。

### 当前实现里"信息供给缺失"的具体表现

**S1. `inspect` 阶段只返回"元数据三件套"**
- `rowCount` / `columns` / `samplePath` 是正确的，但 **不返回前 N 行真实数据**
- 后果：AI 看到 `columns = ["USUBJID", "AGE", "SEX", "AETERM", "AESOC", ...]`，但不知道：
  - 这些列实际值是 `M / F` 还是 `Male / Female`？
  - 日期格式是 `2024-01-15` 还是 `15JAN2024`？
  - `AESEV` 是用 `MILD/MODERATE/SEVERE` 还是数字 `1/2/3`？
  - 空值是 `""`、`NaN`、`NA`、还是缺失？
- AI 只能猜——猜错一次就要花几轮 iter 修
- **正确做法**：`inspect` 返回每列 5-10 行真实样本值（截断到合理长度）

**S2. `outputs` 回执只返回 sheet 名 / 行数，不返回样例数据**
- 当前 `create_multi_sheet_excel` 返回 `{outputFile, sheetNames, totalRows, scenario}`
- AI 写完 Excel 后拿不回"我刚才实际写了什么"——只能打开文件确认（受系统约束，不一定能 Read）
- **正确做法**：返回里加 `perSheet: { name: { columns: [...], rowCount: N, sample: [[...], [...]] } }`——前 3 行样例

**S3. `dataset` 暴露给 AI 的内容过窄**
- 当前 worker 把 datasets 放在全局变量 `_session_datasets`，AI 通过 `enterprise_listing_run_code` 拿到的是 dict，但**没有预先把每张表的 key / shape / columns / sample 一并打印**
- AI 进来第一件事是探查 `list(datasets.keys())`，但程序没主动给个目录
- **正确做法**：在 worker 启动 session 时（或 `inspect` 调用时）返回 `datasets: { key: {columns, rowCount, sample} }` 摘要，AI 直接拿到全图

**S4. 压缩包解压后 AI 看不到"我刚解了什么"**
- `worker.py` 的 `_plain_sources` / `_archives` 处理后，`_last_outputs` 是 `{sheet_name: DataFrame}`，但**没把每张来源表的"原始路径 + 解压前 stem + 来源 zip 路径"暴露给 AI**
- AI 写 spec 时无法引用"这张表来自 foo.zip/subfolder/bar.sas7bdat"这种上下文
- **正确做法**：每个 DataFrame 的 `attrs["source"]` 存 `{path, stem, archive, sheet_index}`，inspect 时一并返回

**S5. `previous` 加载的"上一版产物"几乎不暴露给 AI**
- `load_previous_version` 返回 dict[str, DataFrame] 给 calculate_changes，但 AI 看不到"上一版有什么 sheet、各几行"
- AI 想做"对比上次输出"时只能让它自己再读一遍 .xlsx——重复 IO
- **正确做法**：把 `previous` 的摘要（sheet 名 + 行数 + 各 sheet 前 3 行）作为 `request.previousSummary` 返回，让 AI 自由决定要不要进一步读

**S6. `track_changes` 计算的 `changes` 不主动反馈给 AI**
- 当前 `changes` 只写到 `*_changes.json` 落盘，AI 看不到
- 这是"信息被程序抓住不放"的典型——AI 才是判断"变更是否合理"的主体
- **正确做法**：把 `changes` 放进 `inspect` / `run_code` 的回执里，AI 自己看哪些 sheet 增删改

### 信息供给的设计目标

> **让 AI 第一次进入 session 时，就能拿到一个完整的"项目地形图"**：
> - 项目下有哪些文件夹、哪些文件（不全列，但给可调用的 `list_files`）
> - 哪些 zip 已解 / 待解 / 解到哪
> - 哪些数据源已加载到 `datasets`，每张的列 + 行数 + 样本
> - 上一版产物（如果存在）的摘要
> - 当前 session 用了什么 scenario、最近一次输出是什么

这才是"最大化 AI 推理"的物质基础——AI 推理需要 context，没有 context 就是闭卷考试。

### 优先级（接续第 5 节）

7. **S1 inspect 返回列样例**——信息供给最关键的一环
8. **S2 outputs 回执返回 perSheet 样例**——AI 写完 Excel 后能自检
9. **S3 session 启动时给数据集目录**——AI 进门就有地图
10. **S4 DataFrame attrs["source"]**——AI 写 spec 时能引用来源
11. **S5 previousSummary**——AI 能做版本对比
12. **S6 changes 回执**——AI 能看变更而不是看落盘 json
