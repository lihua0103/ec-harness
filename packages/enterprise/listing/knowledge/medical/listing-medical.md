# 场景库：medical（医学核查 listing）

车道：`enterprise_listing_inspect → read_document → run_code → publish(scenario="medical")`。
**与 manual 分库**：需求文本可能相似，但审核对象（医学差异/数据疑问 vs 编程核查）、
输出口径（医学审阅工作簿 vs 核查 listing）不同——禁止互相代理口径。

## L1 写码前门禁（Gate）

- **GM0 继承 G0 通用**（值域核对/零命中即停/空表防御/单文件交付/中性代称——
  见 manual 库 G0，所有场景恒适用）。
- **GM1 需求定性**：先确认这是医学审核交付（reviewer 面向）而非 DM 编程核查；
  不确定→向用户澄清，禁止猜。
- **GM2 输出契约**：publish 场景固定 medical 的多 sheet 规范（见
  enterprise_listing_publish 契约/EDC 导出模板）；列集与样式以该场景模板为准，
  未沉淀前先跑 inspect 对齐结构。
- **GM4 修改轮全触点门禁**：改既有程序前通读其全部触点（数据日期/ALS 路径/
  输出路径/比对配置/插入位）；"字段移动"类修改必须检查 select 全列表无重复列
  （历史轮曾把移动实现成尾部追加），并全程序扫描 `filter("字面量"!=…)` 恒真
  模式——命中即报用户/DM 决策，禁止只修单点或擅自全局改写。
- **GM5 ALS 接入门禁**：ALS 先探文件头再交给 read_excel（SpreadsheetML 假 .xls
  的头是 UTF-8 BOM+`<?xml`，xlrd/readxl 全部报 corrupt）；此类文件用 Excel COM
  转真 xlsx 并验证关键页（Fields：FormOID/FieldOID/PreText）可读后才可更新
  alspath；修改轮列序以新 ALS 字段 Ordinal 为准。
- **GM6 字面量路径门禁**：既有程序里"承重"的目录名/文件名拼写（哪怕拼错）一律
  原样保留；正名必须 代码+服务器目录+本地镜像 三处联动，且由用户拍板时机。
- **GM7 比对配置门禁**：新增/修改 listing 必须同步补比对配置行；key 必须
  ⊆ 该 listing 输出保留列（对 select 后列清单核对），assign_subject/结构照既有行。

## L3 方法论（修改轮五步）

1. 定位输入：需求模板（高亮行=本轮范围）+ 新 ALS + 新数据包 + 既有单文件 R +
   比对配置 xlsx；服务器路径契约从既有程序内字面量读取（不从场景假设推导）。
2. U-Gate 理解矩阵：模板注释行、ALS Ordinal、数据集列名三方对表，逐条给
   E/I/U 置信级；U 级列待确认清单，不代理实现。
3. 映射表给用户确认后再动码（目标列序/新列/删除列/插入位/配置行一次说清）。
4. 本机验证法（服务器依赖程序无法本机整跑时）：`parse` 语法 + 目标 listing
   管道对真数据集结构级试跑——只打印列名/行数/类型，禁止打印数据值；
   助手函数从程序原文复制时注意补 purrr（`map_chr`）。
5. 交付三件套同步：程序、比对配置、（转换后的）ALS 按既有路径落位；服务器
   实跑回执回来后回填 L5 档案。

## L4 postmortem（信号 → 预防 Gate → 修法）

| 信号 | 根因 | 预防/修法 |
|---|---|---|
| ALS 报 "Unsupported format, or corrupt file: Expected BOF; found `<?xml`" | SpreadsheetML 伪装 .xls | GM5：探文件头→COM 转真 xlsx→验证 Fields 页 |
| 修改后输出比预期多出成段重复列 | 历史轮"移动"实现成"追加" | GM4：select 全列表查重；同类历史编辑全查 |
| 过滤条件写 `filter("列名"!="值")`（带引号） | 字面量误作列引用，恒真=过滤失效 | GM4：全程序扫描该模式，报 DM 决策 |
| 改拼写后程序突然找不到目录/配置 | 拼写错误已成"承重墙"（历史交付固化） | GM6：字面量路径原样保留，正名三处联动 |
| Rcompare 报 key 列不存在 | key 引用了被 select 丢弃的列 | GM7：key ⊆ 输出保留列 |
