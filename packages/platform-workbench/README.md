# @ec-clinical/platform-workbench

原生 WebUI 企业工作台集成包（任务书 T02/T06/T07/T09）。它在 DSH 原生会话上增加企业入口、
工作上下文、成果/输入批次视图与可访问的整页布局，**不实现第二套聊天内核、不导入私有 UI 组件、
不挂第二套 React**。

## 结构

| 文件 | 作用 |
|---|---|
| `src/index.ts` | Host 半：只注册 host row 与同源 `/platform-workbench` 控制面代理；不注册模型能力。 |
| `src/client/index.ts` | 浏览器半：注册 `sidebar.brand.*`、`sidebar.panellist` 与 keyed `main` 整页；注入并清理页面样式。 |
| `src/client/WorkbenchPage.tsx` | 企业信息架构整页：我的工作（AI 工作入口 / 运行就绪 / 工作队列）/项目空间/应用中心/待我处理/平台设置；工作控制台＝原生会话＋运行侧栏；工作详情含运行历史、成果、执行输入、输入批次与分页。 |
| `src/client/styles.ts` | `.ec-wb` 作用域样式：2026-11-13 概念稿视觉系统 + 宿主主题 token、紧凑密度、窄屏、暗色、reduced-motion、焦点环。 |
| `src/client/components.tsx` | slot occupant 组件（inline SVG 品牌 + 名称）。 |
| `src/work-context.ts` | 纯逻辑：校验 `resolveWorkContext`、决定打开哪个原生 Session、深链接校验。 |
| `src/reports.ts` | 纯逻辑：分页窗口、成果封存摘要、下载路径、运行状态标签/色调用、相对时间与标题字母块；不含 DOM。 |
| `src/api.ts` | 同源 `/platform-workbench/api/*` 客户端；错误保留控制面公开 code；默认 `fetch` 绑定全局接收者。 |
| `tests/*.test.ts` | work-context、api、reports、UX 契约、Host 代理与 client factory 测试（不依赖浏览器）。 |

## 设计约束（来自任务书与上游契约）

- **会话正文/实时流/队列/取消/问答一律原生**：本包不持有 Session、事件流或 composer；
  “打开工作” 只把原生选中定位到已绑定的 Session。
- **只注册上游已声明的 slot**：`sidebar.brand.*`、`sidebar.panellist`、`main`；不导入私有组件。
- **不打包第二份 React**：`build.mjs` 将 React 与全部 `@deepseek-ai/*` 置为 external，由宿主提供。
- **未绑定工作如实显示**：`resolveOpenTarget` 返回 `needs-binding`，不会静默新建会话。
- **成果只按控制面事实展示**：`sealedAt` 存在才叫“已封存”并允许下载；未封存只显示元数据。
- **分页不静默截断**：页码窗口由 `pageWindow` 校正，超出范围的 offset 回到最后一页。
- **错误可定位**：控制面公开 code 原样显示，每段读取有自己的“重试”，不用占位数据掩盖失败。
- **不修改原生聊天算法**：样式全部在 `.ec-wb` 下，卸载时移除 `<style>`。

## 视觉系统（2026-11-13 概念稿对齐）

页面按已评审概念稿 `prototypes/enterprise-workbench/design.html` + `design.css` 重做视觉与首页信息架构，
运行形态仍是单页 DSH 插件（无 iframe、无第二套聊天）：

- **外壳**：56px 顶栏（品牌标记 + EMERALD 字标 + 面包屑 + 连接状态 + 刷新/密度/设置图标钮）、
  210px 导航列（新建工作、五项导航含待我处理计数、最近打开、底部平台设置）。
- **首页**：问候 hero → AI 工作入口（快捷目标取自**员工最近使用的应用**，回退到已发布目录，
  不写死任何产品名）→ 工作队列表格（工作 / 专业应用 / 运行状态 / 最近活动）→ 画布脚注；
  右栏为需要你处理、运行就绪（应用目录 / 模型目录 / Worker 执行器三条**实测事实**）、我的项目。
- **工作控制台**：企业头（项目·应用·运行编号 + 状态胶囊 + 查看目标 / 请求停止）＋ 右侧运行侧栏
  （运行状态 / 文件成果 / 运行历史），**中间线程仍是上游 `conversation.content` 工厂**，
  流式、工具、队列、停止、问答与 composer 全部原生。
- **问答**：待答复问题渲染为琥珀色问题卡，选项为原生 radio/checkbox 芯片（键盘可达）。
- **归档**：首页队列默认只列进行中的工作，脚注提供“显示已归档 N 项”开关，归档记录不会被隐藏成不可达。
- **对比度**：概念稿的 8–11px 元信息灰实测只有 2.4–4.4:1，已统一为可读元信息墨色
  （浅色 `#5c7278` / 暗色 `#93a5ab`）；浅/暗两套主题、首页与控制台共 128 组文本配对实测全部 ≥ 4.5:1。


`dsh.client` 元数据由 web profile 装配。

## 2026-11-17 体验增补（已实现）

本轮针对员工路径做的改动，全部在既有单页插件形态内，未新增第二套聊天或 iframe：

| 问题 | 改动 | 事实来源 |
|---|---|---|
| 自动绑定会话不透明 | 工作详情新增四步状态条（项目与应用 / 工作目录 / 专属对话 / 可以开始）；自动创建前明确提示，失败保留原因并提供“重试创建对话”；缺少目录时说明不会猜测路径 | `workContext`、binding 与 workspace 事实 |
| 运行记录与实时对话切换隐蔽 | 控制台头部新增 `实时对话 / 运行记录` 分段开关（键盘可达、焦点环保留）；选中运行时中央显示“当前查看的是运行记录”横幅与“回到实时对话”；侧栏行仍可快捷切换 | 本地视图状态，不改变原生会话 |
| 历史会话无检索 | 历史会话页新增标题/目录搜索、运行状态筛选、两种排序与分页；“筛选出 N / 总数”如实显示 | Host 会话目录（不伪造服务端过滤） |
| 新建工作暴露过多基础设施概念 | 改为五步向导（项目 → 应用 → 工作目录 → 目标 → 确认），步骤间保留已输入内容；可在第一步内联创建项目；绝对路径收进“登记新的工作目录”折叠区；有未提交内容时刷新/离开会提示 | 既有项目/空间/应用接口 |
| 异步反馈分散 | 工作详情与控制台显示“最后更新 + 正在同步 + 刷新”；控制台运行记录、成果下载失败原样显示控制面 code | 请求完成时间与错误码 |
| 下载行为不一致 | 详情与控制台统一走“先 fetch 校验、再保存”的下载器，失败不落盘为伪文件 | `/api/runs/:id/artifacts/:name/download` |
| 模型可用性不透明 | 设置页在每个目录项显示健康事实（正常/降级/不可用及原因/未探测）与探测时间；未探测不显示为健康 | 控制面 `model_health` |
| 国际化缺失 | 新增 `src/client/i18n.ts`：界面语言（zh-CN/en-US）、时区（本机/UTC）与统一时间格式化；导航与页面标题走字典，缺失翻译回退中文；业务日期不做时区换算 | 本机偏好（localStorage，仅显示） |

验证：`npm run verify`（typecheck + build + 71/71 测试，含 i18n 与体验契约断言）。
未做：真实员工可用性实验、读屏器完整回归、真实 Worker 下的控制台体验复跑；这些仍属未验证项。

### 2026-11-17 第二批体验增补

- **业务复核卡**：工作详情显示“运行状态 / 复核状态”，SUCCEEDED 运行可发起复核，复核人可通过或驳回（驳回需原因）；明确“运行成功 ≠ 业务批准”。

- 测试：71/71（新增复核 API 客户端用例与状态字典用例）。
- 真实宿主 E2E（2026-11-17，最终构建）：22/22 员工路径 + 6/6 运行记录/复核专项，0 页面错误、0 失败请求；期间发现并修复 390px 控制台动作区超宽（535px→362px）与历史工具栏下拉占用整行。证据在 `.runtime/employee-ui-2026-11-17/`（临时）。
