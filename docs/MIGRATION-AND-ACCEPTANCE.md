# 架构迁移与开发交付验收

版本：1.0 · 2026-11-09 · 状态：实施清单，未执行代码迁移

依据：[ADR-0001](adr/ADR-0001-DEVELOPMENT-AND-KNOWLEDGE-ARCHITECTURE.md)、[平台1.1](ENTERPRISE-PLATFORM-ARCHITECTURE.md)、[Listing0.4](DSH-CLINICAL-ARCHITECTURE.md)、[经验库](PLATFORM-EXPERIENCE-KNOWLEDGE.md)。本轮只修改文档；以下目标状态不代表当前运行状态。

## 1. 迁移起点

69项旧测试/TypeScript/构建曾通过，其中真实运行的是人工R fixture，不是模型从任意项目自主生成的业务验收。当前新增Manual/PK/intake/scenario静态方法和4技能/两个经验工具接线尚未本轮验证。归档安全代码的命令未执行成功，源码、测试、UI、包入口仍有旧行为；没有公共KnowledgeService。

现有任务/工件/数据库必须原样保留。旧AI-DM-Agent仅只读参考，不改其源码、知识或项目文件。当前插件目录不是Git仓库，不以另一个上游仓库的diff/commit冒充插件变更。

## 3. 按依赖顺序实施

### M0：冻结文档与起点

本轮完成新版文档/状态核对。实施前保存旧版本文件清单、配置、依赖锁、测试证据及备份，注明现有新知识接线未验证。旧静态知识与安全设计不可作“目标已完成”的证据。

### M1：撤出旧门禁并恢复普通开发入口

先移除名称/类别拒读、逐文件内容批准、合成唯一入口、诊断扣留与旧UI文案。保留格式/限额、防误覆盖、运行互斥和版本校验。按新合同测试Cover/普通表/SAS可用、未知格式真实报错、分页完整、取消/超时和失败诊断。归档保留路径映射，不删除任务库，不执行格式迁移后的无备份覆盖。

### M2：平台知识服务与种子

单次注册通用KnowledgeService，由Listing注入；先实现schema、SQLite版本/CAS、结构/全文检索和幂等种子导入。两个测试插件验证分类/归属，不开发第二个业务产品。将三项目文本拆为有前提/反例/来源的候选记录，Manual/Medical引用去重。项目裁定与可推广方法明确分开。

### M3：项目资料与R开发/服务器交付

接项目目录发现/版本批次、自主spec/ALS完整读取、haven读取SAS/XPT与其他实际支持格式；无固定六列、demo输入或只返回schema限制。多版本真正冲突才问。

R运行骨架只管参数/IO/依赖/日志/失败摘要，业务由Harness生成。以本地/服务器配置映射路径，交付单文件自包含R；多listing/Excel/RDS合同由spec决定，独立QC与输出打包接同一修订。不是把旧手写fixture当实际用户任务答案。

### M4：自主项目经验闭环

由真实运行/修订/QC/业务澄清事件捕获候选，绑定来源和摘要；正反/边界与相关回归实际运行后激活技术方法。项目业务裁定在当前项目生效，推广新条目需泛化验证。验证失败、冲突、正文修改、撤回、重启/并发、在途快照完整测试。

### M5：三场景和端到端验收

新建Manual、PK BE、PK SAD/MAD人工格式项目（Medical共用review核心另测输出差异），实际生成SAS/XPT/ALS/spec及ZIP等格式夹具。通过工具公开入口完成识别→读取→R编写/执行/修错→独立QC→打包→异目录/任意cwd单文件R复跑。结构/数据事实由夹具独立断言，不能复用生成程序同一helper充当独立答案。

模型冷启动需另列结果：不给旧业务程序/golden，让批准的模型仅看当前资料和经验完成任务；记录失败与修复轮次。模型、费用/外发和真实资料使用按用户具体授权执行，不偷偷运行。真实服务器连接缺失则只报告本机模拟服务器形态复跑。

## 4. 三项目方法迁移矩阵

| 经验 | 正例 | 错用反例 / 不适用 | 证据层级 |
|---|---|---|---|
| Manual标记不等于筛选 | 两重复成员标记，非重复保留 | 当前spec明确Output if duplicates才筛选 | 文本/接线→独立行为→模型项目 |
| 逐列职责 | 来源/范围/Condition/Column Heading/说明/输出分别解释 | 不强迫所有项目有相同表头，不将说明全部编flag | 表头保真、原文覆盖及业务例 |
| 连接与多选展开 | 明确粒度、join键/基数、匹配当前值 | distinct遮盖炸行、非适用行无条件拆分 | 正/负/空表/孤儿 |
| PK BE周期给药 | 受试者+周期匹配相应给药 | 仅按受试者用首剂套全周期 | 错周期、跨日、缺参照 |
| PK SAD/MAD参照 | 队列/名义日小时/基质分别解释 | 全局固定参照、负值默认截0、历史队列隐藏规则 | 多剂、不同基质、边界 |
| 输出与精度 | BQL/尾零、class/label/NA分别核验 | Excel相同便称RDS相同，字符数值归一抹差异 | 独立读回与值层比较 |
| 泛化与作用域 | 当前项目裁定只影响该项目 | 固定OID/列/阈值/样式推广到shared | 两项目与两插件负例 |

历史来源是旧`ec-harness/knowledge-v2`和`.zcode`方法记录，不等于当前验证。文档中的“旧项目实证”只说明来源，必须记录本库复现状态，不拿旧产物喂给生成器凑一致率。

## 5. 保留数据与回滚

1. 迁移前备份当前文件、配置、运行任务与工件清单；不同应用数据库不互换，不默认让TaskStore备份命令处理未来知识库。
2. 新服务使用独立数据库application/schema版本；明确迁移到新目录/快照，旧目录只读保留；升级失败不部分切换。
3. 旧任务保持版本化引用，旧安全库只保留追溯不重挂审批入口；重开任务先提示代码/合同差异，不能把旧fixture PASS升级为新项目PASS。
4. 种子升级幂等、新修订原子切换，动态项目经验不覆盖；快照引用保留，撤回不抹历史。
5. 回滚到原实现若恢复旧拒读/审批，必须明确提示合同不再符合本轮用户范围，不能静默回退又声称新流程可用。
6. 不提交/推送/删除原件或覆盖正式输出；实际发布由单独动作明确执行。

## 6. 验收分层与完成定义

| 层 | 可以证明 | 不可替代 |
|---|---|---|
| 文档检查 | 职责、状态、链接/术语一致 | 代码已实现或API已接入 |
| 工程回归 | 类型、公开工具/服务接线、重启/并发/错误处理 | 模型真实理解正确 |
| 方法验证 | 当前候选digest在正反/边界及回归中通过 | 其他场景无条件适用 |
| 格式夹具端到端 | spec/ALS/SAS→R→多工件→异目录复跑 | 真实项目/真实服务器已验收 |
| 模型冷启动 | 当前模型/上下文实际完成开发闭环 | 零bug或业务责任人批准 |
| 业务/服务器 | 指定项目/环境的实际运行与QC | IT生产安全责任或所有未来项目 |

阶段完成以可追溯证据为准，`NOT_IMPLEMENTED/NOT_RUN/FAILED/PASSED`分别记录。测试数量会随旧合同退役而变化，逐项记录覆盖替换，不以保留69项数字作为目标。

本轮文档修改不跑R业务、模型请求或IT集成，不宣称项目级自主流程已经完成。当前证据索引见 [开发交付状态](RELEASE-READINESS.md)。
