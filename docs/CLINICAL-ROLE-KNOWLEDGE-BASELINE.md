# 临床角色与循环工作知识基线

日期：2026-11-11 · 版本 0.1 · 研究候选，待公司角色核验。配套：[需求](CLINICAL-WORKBENCH-REQUIREMENTS.md) · [方案](CLINICAL-WORKBENCH-SOLUTION.md) · [评审](CLINICAL-WORKBENCH-REVIEW.md)。

## 1. 证据边界

这是公开行业知识整理，不是本公司项目经验实证，不是公司 SOP，也不是已完成法规条款核验。本轮研究尝试 WebSearch/WebFetch；搜索未取得可用正文，抓取被安全域名验证阻断。下列官方入口仅为待核验来源登记，不能作为已经阅读原文或符合规范的证明。实际条款、现行版本、地区实施时间及文献替代关系待补核。

经验必须区分：公开规范/标准、一般实践、公司 SOP、真实项目裁定、经过复现的方法。本稿只覆盖前两者的候选整理；不能把 AI 合成场景命名为“真实项目成功经验”。

## 2. 角色访谈与业务地图

岗位不是权限包；最终以公司授权、研究分工、合同和 SOP 确认。下表是访谈起点，不是所有企业统一分工。

| 角色 | 常见循环工作 | 工作台所需对象与证据 | 必须核实 |
|---|---|---|---|
| DM | 数据清理、Listing 审阅、质疑、外部数据核对、冻结/锁库准备 | 数据截点、规则/程序、发现、响应、复核及新批次差异 | DVP 定义、清理责任、锁库判断依据 |
| DBD | 公司缩写尚未确认；若负责数据库/表单，则涉及结构、规则、映射、变更及测试 | 结构/配置版本、影响分析、测试和部署证据 | 全称、与 DM/EDC 管理员边界；不得先固定职责 |
| 统计 | SAP、估计目标、分析人群/方法、盲态审阅、结果解释 | 方案/SAP/数据切点版本、分析决策、预先指定与探索区分 | 统计批准、揭盲、独立委员会与分析权限 |
| 统计编程 | SDTM/ADaM/TLF、派生、编程、重跑、QC、提交 | 输入/元数据/代码/环境/结果血缘、独立 QC 范围 | 标准版本、QC 方法、生产环境及交付规范 |
| PM | 里程碑、依赖、资源协调、交付跟踪、风险升级 | 负责人、阻塞、到期、交付版本和接收状态 | 项目管理可见性不等于所有临床明细权限 |
| CRC | 在研究者授权下协调访视、文件、录入和质疑响应 | 中心/受试者范围任务、来源、响应及交接 | 研究者职责不可被普通协调按钮代替 |
| CRA | 监查、发现跟踪、中心沟通与关闭 | 中心授权、发现、响应、证据及关闭版本 | 远程源数据访问、监查计划及系统边界 |
| CO | 公司缩写尚未确认 | 先确定岗位任务与交付，再建入口 | 全称、归属、是否与临床运营/其他岗位重叠 |
| 医学 | 医学一致性、事件/入排审阅、方案澄清 | 可定位上下文、医学裁定及适用输入版本 | AI 提示不等于医学确认 |
| PV/安全性 | 个例、随访、临床库/安全库核对及安全报告流程 | 对账来源、发现和移交、时限与实际系统引用 | 不并入普通医学权限；不替代报告系统和法定职责 |
| QA | 过程审计、偏差/CAPA、证据检查、用途风险判断 | 版本、操作事实、偏差、验证范围 | QA 审计不代替每版成果业务复核 |
| IT/系统负责人 | 身份、配置、权限、备份恢复、监控及变更 | 配置闭包、凭据引用、事件、恢复及撤权实证 | 技术管理与临床数据访问分别授权 |
| 申办方/研究者/服务提供方责任主体 | 委托、监督、真实研究责任 | 授权范围、交付和监督关系 | 岗位标签不能替代法律/合同责任 |

## 3. 共同经验候选

1. **持续工作而非一次生成**：资料更新、质疑响应、编码及修订会反复触发运行；一项工作应保留多次运行及交付。
2. **程序成功不是数据清洁**：技术检查与医学/统计/DM 判断不同，不能用单一绿灯合并。
3. **版本是复核对象的一部分**：已审 B1 不能证明 B2；复核转移需要影响判断和明确记录。
4. **文件路径不是数据版本**：同一路径可被替换；需快照或摘要、源版本及可重取条件。
5. **差异不等于异常**：记录减少可能来自修正或匹配失效；必须说明键、范围和不可比较项。
6. **方案修订不是单纯换文件**：可能影响访视、终点、分析及规则；AI 可提候选影响，不自动代表真实角色认可。
7. **盲态是执行与组织边界**：覆盖输入、日志、摘要、缓存、通知、导出与模型，不靠提示词和隐藏按钮；现行公司管理员政策与盲态安排必须显式评审，不自行改写。
8. **独立 QC 必须明确对象和范围**：上一版证据、固定 helper 单测、模型自评都不能证明任意本次成果正确。
9. **撤回不是删除历史**：错误包标记撤回/替代并追踪接收对象，不能静默换文件。
10. **复现有范围**：记录随机性、模型/外部服务变化及环境；不能承诺未验证的逐字节一致。

这些候选进入平台经验库时仍需来源、适用前提、反例、范围和验证回执；不自动标记 ACTIVE，不导入真实临床正文或跨项目常量。

## 5. 公司访谈最小问题集

- DBD/CO 的全称与职责？哪些部门实际使用哪些应用？
- Listing 的复跑频率、稳定键、需求形式、独立 QC 与交付对象？
- DVP 的正式定义、模板、EDC 范围、方案并行版本及 UAT 职责？
- 权威数据截点由谁建立？当前目录能否改动？哪些资料留本地，哪些可以进入中心/模型？
- 复核意见何时可沿用，谁负责影响评估？何时需要电子签名而非普通复核记录？
- 项目阶段、成员、中心、盲态与公司超级管理员范围由哪个系统/合同提供？
- 正式记录源、保留期限、交付更正和备份恢复负责人是谁？

未获得回答不捏造既定事实；可以先形成可走查的合成案例，但相应需求保持待确认。
