# Emerald Clinical Guard — 来源域架构（Provenance-Based Data Plane）

设计日期：2026-08-21
定调依据（用户，最高依据）：

> data 数据不允许外泄露给 AI。本地是可以程序处理的，查询匹配都可以，
> 唯一底线是不允许出域给对接的 AI 模型。

---

## 一、为什么现有架构必然陷入补丁竞赛

现有实现（`smart_guard` + `patterns.py` + 三车道扫描）的判据是**形态识别**：
拿到一段字符串，问"它像不像受试者号/日期/测量值"。

这个问法在原理上不可判定：

- `101-110` 是中心编号范围，还是受试者号？形态完全同构。
- `USUBJID=f'{STUDYID}-{site}-{i:03d}'` 是代码模板，还是数据赋值？
- `五.零分级管理表` 是中文文档，还是被编码规避的 `5.0`？

三个都是本周真实发生的事故。每修一个就多一条判据，而形态全集是开放的——
新编号规则、新日期写法、新编码方式，永远有下一个。更糟的是它诱发**规避**：
上一轮会话里 agent 自己写了 `dumpxl.py`，把阿拉伯数字映射成中文大写，
脚本注释直言 `so the auto-redaction layer doesn't eat the output`。
守卫越严，规避越强，这是机制性的，不是纪律问题。

**换一个可判定的问法**：这段字节**来自哪个文件**？

来源是确定的、可枚举的、不随内容变化的。基于来源做隔离，判据数量恒定，
不随数据形态增长。这是本设计的唯一核心。

## 二、三个域（Plane）

把文件系统按**来源**切成三块，权限不同、面向对象不同。

### 数据域（Data Plane）— 模型永不可见

- 内容：`.sas7bdat`、`.xpt`、原始 EDC 导出、`data/` 目录、数据 zip 包。
- 谁能读：**本地执行器**（trusted executor），完全不受限——按字段读、
  join、匹配、聚合、算 KRI、写 Excel，都放开。这就是用户说的
  "本地程序处理、查询匹配都可以"。
- 谁不能读：**模型的通用工具**（`read` / `pwsh` / `bash` / `glob` 的内容读取）。
  不是"读了再脱敏"，而是**读不到**——路径包含检查，fail-closed。
- 判据：路径前缀包含（`resolve()` 后比较，防 `../` 穿越）+ 数据类扩展名
  兜底（`.sas7bdat` 无论放在哪都属数据域）。

### 文档域（Document Plane）— 分两级，默认只出表头

用户 2026-08-21 补充定调：

> 文档 excel 只有 spec/ALS/template 才允许全量读取内容，
> 其他都只允许读取表头字段信息辅助识别逻辑。

因此文档域**不是**一块统一的"全文可读"区，而是两级：

| 级别 | 判据 | 处置 |
|---|---|---|
| **规格文档**（spec/ALS/template/方案/需求说明） | **配置显式声明**：`specDocuments[]`（文件路径清单）或 `specPlaneRoots[]`（专用子目录） | **整表全文可读**，不脱敏 |
| **辅助文档**（文档域内其余 Excel/CSV） | 落在文档域但未被声明为规格 | **仅表头字段名**（沿用现有 `runExtractor`），数据行不出域 |

**判据必须是显式声明，不能靠文件名形态推断。** 出事那份 KRI 台账叫
`test_Final.xlsx`，名字里没有任何 spec 字样；反过来一个叫
`ALS_data_export.xlsx` 的文件完全可能是数据导出。文件名判据是
ST-D-5 已记录的泄露通道，此处不复用。

**默认落"仅表头"这一档**：未声明 = 不放宽。安全侧默认，声明才放宽。

- 纯文本类规格（`.md`/`.txt`/`.docx`/PDF 提取文本）落规格级即全文可读——
  它们不具备"表头/数据行"结构，表头档对其无意义。
- 明示接受的风险：若把真实受试者数据放进**已声明的规格文档**，它会出域。
  这是配置责任（用户已定调 spec 整表可读），不再用模式匹配替用户兜底——
  那正是误报的来源。辅助文档档位不承担此风险，因为数据行本就不出域。

### 产物域（Output Plane）— 模型只见收据

- 内容：执行器写出的交付物（Excel / CSV / 日志）。
- 处置：模型可见**路径、文件名、行数、校验报告**，不可见内容。
  要看内容，走 `dataset_profile` 拿聚合，或由用户自己打开文件。

## 三、模型触达数据的唯一通道：五个工具

模型不再"读文件然后被脱敏"，而是**提交计算、领取收据**。
（compute-to-data 模式，同 DataSHIELD / OHDSI 的思路。）

| 工具 | 输入 | 返回给模型 | 不返回 |
|---|---|---|---|
| `dataset_schema` | 数据集路径 | 字段名、标签、类型、长度、codelist、总行数 | 任何单元格值 |
| `dataset_profile` | 路径 + 字段 | 每字段：缺失数、distinct 数、数值/日期的**分桶**极值、top-k 类别及计数（受 k-匿名阈值约束） | 原始值、低于阈值的小单元格 |
| `synthetic_sample` | schema + n | **合成**行（符合 schema 与 codelist，值随机） | 真实行 |
| `run_local_job` | 脚本/规格 + 输入集 + 输出目录 | `{exit_code, rows_in, rows_out, files_written[], validation, stderr_class}` | stdout/stderr 原文 |
| `validate_output` | 产物路径 + 规则 | 逐规则 pass/fail + 计数 + 定位（行号、字段名） | 违规行的值 |

`synthetic_sample` 是**反规避设计**，不是附赠功能。agent 写 CJK 转换脚本的
真实动机是"我需要看清结构才能编码"。给它一条合法的看结构的路，规避动机消失。
堵通道治不了这个，给出路才行。

`run_local_job` 是"本地程序处理"的落点：模型写脚本，执行器带着数据权限跑，
产物落盘，模型拿一张收据。**stdout 绝不原文返回**——这一条同时废掉了所有
编码规避（中文数字、base64、拆分空格……），因为脚本打印什么都到不了模型。

## 四、执行点：两个，而不是三车道扫描

### 执行点 1：域准入（Plane Admission）— 主防线

拦在工具**调用前**，判据是路径，不是内容。

```
generic read/pwsh/bash/glob 的目标路径 ∈ 数据域
    → deny，回执指向正确工具：「数据域只能经 run_local_job 处理」
```

关键：这不是"扫描参数里有没有数据形态"（现在的 quickGuard，它误拦了
`USUBJID=f'{...}'` 和 `101-110`），而是"这个工具够不够格碰这个路径"。
路径包含检查是判定性的，误报为零。

shell 类工具无法靠参数判断（`cat $(...)` 可绕），所以：
**agent 的 shell 与执行器的 shell 是两个权限域**——agent shell 跑在
数据域不可见的沙箱里（不挂载 / 无读权限），执行器 shell 才有数据权限。
两者不共享进程与凭据。这是整个设计成立的前提。

### 执行点 2：出域形状校验（Egress Shape Check）— 保底

`llm/stream` 出境前，校验载荷是否**符合已声明的安全形状**：
系统提示、用户消息、文档域内容、五个工具的**类型化返回**、模型自己的输出。

这是**白名单形状**，不是黑名单模式。不认识的形状 → 拦。
因为经执行点 1 之后，模型面向的表面已经是一个**封闭的类型集合**，
校验从"在自由文本里找数据形态"降级为"检查结构是否合规"——
后者判据数量恒定，不随数据形态增长。

模式库（`patterns.py`）保留但**降级**：只用于两处窄面——
用户手贴内容的最后提醒、错误消息脱敏。不再承担主防线，
因此它的误报不再有钉死会话的代价。

## 五、威胁模型与残余风险（明示，不掩盖）

| 风险 | 处置 |
|---|---|
| 数据域根配置错漏 | 默认拒绝；必须显式声明；数据类扩展名全局兜底；启动时校验根存在且与文档域不重叠 |
| 文档域内混入真实数据 | 明示为配置责任（用户已定调 spec 全文可读）。提供 `audit_document_plane` 离线体检工具，报告"文档域内出现数据集形态文件"，但不阻断 |
| 聚合小单元格反推 | 任何计数/top-k 施加 k-匿名阈值（建议 k=5），低于阈值的单元格抑制为 `<k` |
| 模型把数据编码进它自己写的脚本 | 脚本是模型**产出**（控制面），入向无害；风险在收据回传，故收据严格类型化，`files_written` 校验命名模板 |
| 执行器报错信息带值 | `stderr` 只回错误**类别**与行号，原文落盘由用户查看 |
| 用户手工粘贴数据进对话 | 来源域管不到。保留轻量提醒，不 fail-closed（用户自己的数据、自己的选择） |
| 执行器沙箱逃逸 | 执行器无网络、无模型回调通道；即便脚本恶意，数据也无出口 |

## 六、迁移路径（不推倒重来，分阶段让补丁退场）

现有仓库有 59+18+3+12 条通过的测试，不能一次性替换。分四阶段，
每阶段都可独立验收：

**阶段 1 — 建域与准入（本次核心）**
- 配置项：`dataPlaneRoots[]`、`documentPlaneRoots[]`、`outputPlaneRoot`。
- 实现 `planeOf(path)`：路径前缀 + 扩展名兜底。
- 通用工具准入：目标落数据域 → deny，回执指路。
- 文档域：Excel 分支跳过 `runExtractor` 表头提取，**整表原样**返回，
  不过 token 化。← 直接解掉"表头/spec 被脱敏"与 CJK 规避的动机。
- 现有 `smart_guard` 脱敏**保留为纵深防御**，但不再是主防线。
- 验收：出事的 `session-dc1055fc` 载荷全程无拦截；数据域读取被 deny 且
  回执可读；spec 整表可见。

**阶段 2 — 执行器与收据**
- 注册 `run_local_job`，独立沙箱进程，带数据域权限、无网络。
- stdout/stderr 不原文回传，改类型化收据 + 落盘日志。
- 验收：agent 能端到端产出 KRI Excel；模型上下文中零数据值。

**阶段 3 — 元数据与合成样本**
- `dataset_schema` / `dataset_profile`（含 k-匿名）/ `synthetic_sample`。
- 验收：agent 仅凭 schema + 合成样本即可正确编码，无需窥看真实行。

**阶段 4 — 出域收窄与补丁退役**
- 出域校验改白名单形状。
- 模式库退到"用户消息 + 错误串"两处窄面，删除工具结果的形态扫描分支。
- 验收：历史全部事故用例（本文件第一节三例 + 记忆里 8-20 各例）
  不再需要任何专用判据即自然通过。

## 七、这套设计如何终结补丁竞赛

| | 现架构 | 本设计 |
|---|---|---|
| 判据问的问题 | 这串像不像数据（不可判定） | 这字节来自哪（可判定） |
| 判据数量 | 随数据形态增长，无上限 | 恒定：域数 × 工具数 |
| 漏认后果 | 泄露 | 无——数据根本没进模型通道 |
| 误认后果 | 会话钉死 | 无——路径判据无歧义 |
| 规避激励 | 强（守卫越严越要绕） | 无（有合法看结构的路，且 stdout 不回传） |
| 本地处理能力 | 被连带限制 | 完全放开（执行器域） |

底线的守法从"努力认出所有数据形态"变成"数据在结构上到不了模型"。
前者是无穷任务，后者是有限工程。
