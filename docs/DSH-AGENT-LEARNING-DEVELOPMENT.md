# DSH 企业智能体持续学习平台开发设计

版本 0.1 · 2026-11-21 · **待评审的开发设计，不是已上线能力或业务签收。** 适用全部纳管 DSH 插件。读者：平台、插件、工作台、IT、QA 和领域负责人。

**交付目标：甲在项目 A 的纠错，经过验证后能帮助乙在未参与沉淀的项目 B 少犯同类错误；甲的习惯仍是私有的，A 的裁定仍只属于 A。全过程不重新构建或发布 DSH、工作台或业务插件。** 这里说的“不改代码”指平台能力建成后的日常学习，不是省略首次接线、测试或新能力开发。

## 1. 决策、依据和现状

| 决策 | 现有依据 | 本次要补，不要重做 |
|---|---|---|
| 保留原生会话、按插件提供领域能力 | 已核对 DSH `0.2.2-rc.1`，commit `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的[服务注入合同](../upstream/deepseek-harness-git/docs/user/develop/framework/service.md)；[项目开发规范](DSH-PLUGIN-DEVELOPMENT-STANDARD.md) | 在现有公共服务上扩展，不给每个员工起常驻模型，不给每个插件起数据库，不规定模型工具调用顺序。下文接口均为**企业拟议接口**，不是 DSH 上游接口。 |
| 知识由服务统一写，按部署数据单元管理 | [知识库配置](../packages/platform-knowledge/src/cordis.ts)、[控制面快照接线](../packages/platform-control/src/bootstrap.ts) 默认指向 `DSH_HOME/platform/knowledge.sqlite` | 使不同客户端经认证访问同一权威服务；远程部署时控制面也通过受信服务口绑定快照，不依赖同机读文件。不能据默认路径断言员工已互通。 |

| 经验共享不等于训练模型 | [当前知识模型](../packages/platform-knowledge/src/schema.ts) 的 scope 为 shared/plugin/project；[控制面存储](../packages/platform-control/src/store.ts) 有员工模型选择，但非个人工作记忆 | 增加私人偏好、项目证据到公共方法的晋升、跨员工分发与独立效果评测。权重训练是独立、可选的后期能力。 |
| 运行事实不等于已学会 | [控制面事件投影](../packages/platform-control/src/cordis.ts) 把失败、未知和 QC 结束记为 `PENDING_ANALYSIS`；[原交付计划](DSH-ENTERPRISE-KNOWLEDGE-DELIVERY-PLAN.md) 区分工程与业务验收 | 补可信消费与补投、复核、独立验证、发布、新 Run 复用和效果回写。`ACTIVE` 表示指定声明通过技术验证，不代表企业标准或人工水平。 |

本设计沿用[企业知识体系](DSH-ENTERPRISE-KNOWLEDGE-SYSTEM.md)、[存储演进方案](ENTERPRISE-KNOWLEDGE-ARCHITECTURE.md)、[验证合同](PLATFORM-KNOWLEDGE-VALIDATION-CONTRACT.md)，不另设知识状态机。若批准改变授权、持久化或包边界，实施前记录 ADR 并修订对应权威合同。本文件不改变现有生产配置。

## 2. 四类信息：所有权和适用性分开

| 信息 | 可以记录 | 谁能使用、怎样变化 |
|---|---|---|
| 个人习惯 | 输出语言、先摘要后明细、排序、常用复核视图 | 默认关闭持久记忆，员工显式开启；按 `组织 + 可信主体` 隔离，可适用全部或指定插件。本人可预览、编辑、停用、删除。本人一条明确选择即可生效，不需要公共验证或管理者批准。 |
| 个人方法草稿 | “我遇到某类问题时这样排查”；允许带反例或标记未经验证 | 私有，不当作事实、组织标准或默认操作。来源涉及项目时仍需项目权限，不能复制项目内容到个人空间。员工可选择贡献一个新候选。 |
| 项目裁定 | 项目负责人的有效决定、适用输入版本、例外及依据的受控引用 | 授权项目成员在对应项目、地区和有效期内使用；同一个人换项目不继承。知识服务不冒充项目裁定系统，不因模型建议自动生效。 |
| 公共方法／标准引用 | 插件领域验证过的方法、跨插件通用方法；受控 SOP 的生效版本引用 | “公共”指获授权的受众，不是全公司全球可见。方法由领域方验证发布；SOP 的权威仍在文控，不能通过投票、训练或候选发布修改。 |

**查询先求授权交集，再判断适用性。** 所有权/可见性（本人、项目、批准的组织受众）与适用维度（插件、场景、EDC、语言、地区、版本）分开建模。地区既可能是驻留边界，也可能是方法的业务适用条件；两者不得互相替代。项目事实受有效裁定限定，方法只能建议，个人习惯只改变允许的协作方式。本次用户对呈现方式的明确要求优先于个人默认；强制标准和权限不能被偏好覆盖。两份有权来源矛盾时返回冲突与受控引用，不静默取“最新”或相似度最高的一条。

**界面例子：** 甲说“以后我先看异常”。工作台提供「仅本次」「记为我的习惯」；只在甲选择持久保存后，后续新会话默认摘要优先。甲说“这个项目本访视不适用”不是偏好，系统提供项目裁定入口而非写入个人习惯。甲点击「贡献方法」时先看到将提议的去项目化文本、范围和用途；不把甲的原始记忆变成公共记录。不开启个人记忆仍可完整使用业务插件。不得从使用习惯推断敏感属性、做员工画像或绩效排名。

## 3. 系统与数据库：先实现共享，再按负载选引擎

| 组件及负责方 | 读写职责 | 不允许做的事 |
|---|---|---|
| DSH 原生会话与工作台 | 控制个人设置、展示本次知识依据、发起纠错；按现有身份调用服务 | 浏览器直连数据库、从客户端参数推断 owner、把缓存当授权 |
| `platform-control` | Run、发布、工件摘要、复核和事件的真源；创建 Run 时绑定知识/偏好/模型版本 | 解析临床原文、执行插件代码、直接更新知识修订 |
| `platform-knowledge` | 每个数据单元唯一的知识状态写入方；经过授权的读取、快照、候选、发布清单、撤回与影响查询 | 将全组织数据拉到客户端再过滤，或给业务插件数据库写凭据 |
| 插件知识智能体 | 提炼领域假设、提供适用条件、测试输入类型和指标；可得出“不可复用” | 自报测试通过、定义自己的用户权限、读取其他插件私有表 |
| 独立验证及可选训练执行域 | 处理获准样本，与冻结测试集对照；交回受信回执或模型制品引用 | 使用训练输入作盲测，直接切线上版本，外送项目原文 |

**部署选择**：第一阶段在同一批准区域部署一个经认证的服务实例，服务本机 SQLite/FTS，工作站和 Worker 只用服务接口。不通过共享盘、云盘或文件复制同步活动 SQLite。若试点之初就要求多实例故障切换、并发写或集中恢复，可直接选该区域 PostgreSQL；否则先记录峰值写入积压、检索 p95、恢复时间及业务 RPO/RTO，再按与 IT 冻结的预算决定迁移。全文检索先按语言、缩写测试；只有召回不达标才评估向量索引，索引不得越权，也不是第二个真源。国际部署按组织及驻留政策设区域数据单元；跨区默认不复制，只有批准的方法包可定向分发。区域失联不自动改走其他地区。

**迁移**：清点已知库和记录所有权 → 隔离环境备份与恢复复验 → 只读导出修订/事件/回执/快照 → 对账条数、摘要、撤回状态和引用 → 停写切换唯一写者 → 新连接端到端复验。未确认归属的旧数据进受限待分类队列，不归为公共；不能把电脑用户名当企业主体。切换前可回到旧单写者；切换后有新写入时先停写和对账，不用旧备份覆盖新事实。知识库、控制面和受控制品分开备份，恢复时检查跨库引用。

## 4. 数据合同（逻辑结构，非现有数据库 DDL）

复用现有修订、事件、回执和快照表；新增对象或新字段前按公开接口做映射，不创建平行知识库。标识为不透明 ID；时间用 UTC，显示用用户时区。

| 逻辑对象 | 必要字段 | 关键约束与索引 |
|---|---|---|
| `PersonalSetting` / `PersonalPreference` | org、区域单元、owner、enabled、key、typedValue、可选 pluginId、revision、状态、updatedAt | 值按批准的偏好键 schema 校验（如语言枚举、布局枚举），不接受脚本、系统提示词或权限开关。唯一 `(tenant,owner,plugin-or-global,key)`，版本比较更新，区分全局默认与插件覆盖。 |
| 私人方法草稿 / 知识修订 | recordId、revision、audience、适用条件、pluginId、projectRef、有效期、来源引用、digest | 私人草稿绑定 owner；项目记录绑定 project；公共对象不得携私有正文/可反查个人标识。扩展示意不替代现有 scope；迁移显式映射。读取先按租户/区域/受众做索引过滤，再按主题检索。 |
| `LearningCase` | caseId、sourceEvent、runRef、领域、纠错类别、依据引用、处置结果、投影版本 | 存放最少必要元数据；沿用现有投影去重，区域/组织隔离命名空间；单事件可分多个假设，按 case、假设键去重。未能判断和无需复用都是有效结局。 |
| 公共候选与验证 | 新 recordId、derivedFrom 的受控关联、claims、适用与不适用条件、反例、验证器版本、数据集摘要、receiptId | 去项目化后**新建**候选，不原地改可见性；公开侧只展示允许的来源说明。一次性回执绑定候选修订及摘要，覆盖不足不激活。 |
| `KnowledgeRelease` | releaseId、org/region、受众、插件兼容范围、固定 `(id,rev,digest)` 集合、评测报告引用、批准人、前版、manifestDigest | 发布清单不可变；当前版本指针带 expectedVersion，原子切换。按受众、插件和区域建索引。回滚只切换到仍获准的清单；撤回条目不得复活。 |
| `LearningBinding` | runId、知识 release/快照摘要、私有偏好修订的受限引用、agent/plugin/model 版本、评测时的输入摘要 | 区分“已绑定、实际返回、最终引用”。共享运行记录不能暴露私有偏好文本；撤权或删除后不得重取正文。 |
| `EvaluationSet` / `ModelRelease` | 数据集版本、用途授权与到期、分割摘要、指标定义；模型或适配器 ID、基座版本、制品摘要或供应商不可变版本、区域、评测、回退目标 | 数据集授权和使用模型的授权分别记录。训练制品保存在批准制品库，关系库只保引用；无法冻结供应商版本要明确标为不可精确复现，不伪造摘要。 |

数据标签、发布清单与偏好值仅为数据。**不能把任意代码、提示词覆盖、验证器下载地址或可执行 SQL 当作热更新内容。** 新的数据用例可引用已安装、已有输入契约的验证器；确实需要新的工具/运算语义才走软件变更流程。

## 5. 服务操作与失败语义（拟议，不是现有 URL）

请求主体、租户和区域来自验证过的身份连接；Run 引用必须在服务端还原并检查归属。Worker 身份与员工身份分开，不把 Worker 的宽权限传给用户。普通授权读取不加人工审批。以下是行为合同，传输可以是服务调用或经认证 API；插件调用现有服务公开面。

| 操作 | 请求 → 结果 | 核心校验 |
|---|---|---|
| `preferences.getMine/setMine/pause/deleteMine` | key、类型化值、插件范围、expectedRevision → 新修订或状态 | owner 从身份派生；暂停后不再注入；删除清理正文、缓存和索引，重复删除幂等。个人设置不因读取历史对话自动恢复。 |
| `learning.proposeFromCase` | caseRef、适用性、声明、反例、幂等键 → candidateRef 或无需复用原因 | 检查来源访问和用途；私人贡献需显式选择；拒绝直接设 `ACTIVE`、复制受限正文或指定任意受众。 |
| `knowledge.validate` / `release.publish` | 候选修订、验证回执、目标受众、评测证据、expectedVersion → 发布清单 | 沿用现有验证合同；技术激活与业务放行分开。发布角色有权决定目标受众，不能凭模型评分放行。 |
| `run.bindLearning` / `knowledge.searchPinned` | 已授权 runRef、收窄查询 → 绑定版本／返回结果与证据 | 快照由服务端按 runRef 解析；不信任客户端自带的 scope 或快照。项目/插件可见性与当前撤权均重新检查。 |
| `release.withdraw/rollback` | 受影响对象、原因、预期指针 → 影响范围、处置回执 | 先阻止新取用，再失效缓存，并列出受影响 Run 待复核。保留原运行事实；不重写历史结论。 |
| `evaluation.compare` / `model.promote` | 冻结配置、盲测集版本、对照组、报告 → 对照结果／区域模型发布 | 训练方不能读取盲测答案，模型发布须独立复核、兼容性验证和回退目标；此接口不要求所有供应商支持微调。 |

例：甲显式保存 `{key:"review.summaryOrder", value:"exceptionsFirst", applicability:{pluginId:"dm-listing"}, expectedRevision:3}`。服务从当前可信身份确定甲；返回 `{revision:4}`。另一设备以甲登录可读到修订 4，乙即使提交相同请求或猜到 ID 也不能看到甲的设置。重复事件/同幂等键同内容返回原回执；相同键不同内容或过期修订返回冲突，不使用最后写入覆盖。越权和不存在对无权限方不可区分；错误日志不得泄露候选数量、查询词或正文。

**故障处理**：偏好服务不可用时，可按标准呈现继续工作，并标明“未应用个人习惯”；强制依据不可验证时，不产出依赖它的已验证结论；普通知识不可用报告降级，不改读未授权库。事件消费者采用持久游标、有限重试、死信与人工重放；按来源事件与投影版本幂等。业务成功不得因提炼失败而改判失败。缓存键至少覆盖租户、区域、主体/受众、项目、插件、快照及授权版本；撤权要求重新校验，不能只依赖 TTL。

## 6. 项目经验如何变成下一次工作的能力

1. **盲生成。** 冻结输入版本、模型配置、插件制品和知识快照；人工参照在初次生成期间不可检索。保存受控产物引用，不向知识库拷贝交付物。
2. **在授权环境比较。** 本地比较人工参照和 AI 产物，记录等价、措辞、逻辑改变、漏项、误增、未决、解析失败。历史人工定稿也可能有错，由有权复核人裁决；无法自动判定不能算通过。真实临床文档、逐条报告、行级差异和映射表不进入模型上下文，只输出允许的汇总类别和统计；小样本组合有识别风险时抑制外显。
3. **分流。** 个人偏好由本人保存；项目裁定绑定项目；可复用的假设才提出公共候选；证据不足记为待分析或无结论。模型可协助提炼，但无权发布。
4. **在独立样例上验证。** 候选说明什么时候适用、什么时候不能用；验证器执行正例、反例和边界。一次修正如果只能在来源项目上通过就留在项目层。新规则可用既有验证器读取版本化数据夹具，不要求为每条经验提交源码。
5. **发布、消费、回看。** 将已通过的修订加入面向目标受众的知识清单；新 Run 绑定新版，同一旧 Run 不漂移。比较前后未参与学习的项目表现，保留失败与未决。出现关键退化先停用该发布，定位受影响运行；不抹掉原证据。

**可重复的合成例**：DVP 插件在模拟项目 A 把“字段缺失”与“表单不适用”混为一类。项目负责人确认 A 的具体裁定；插件另外提出抽象声明“有显式不适用证据时，不将该项计为缺失”。正例有显式证据，负例仅缺值无证据，边界例证据互相冲突应转未决。对另一模拟项目 B 盲测，使用新方法后检查漏报、误报及未决分母。原记录不转成全局规则；若该声明只适合特定 EDC，则发布清单保留 EDC 前提。Listing 可以用相同发布合同验证异常标记，但不用 DVP 的验证器。

## 7. 权重后训练：完全独立的数据与模型发布路径

**进入条件**：多个独立项目重复出现同类能力错误；已有知识确实被正确检索和使用；补知识、改表达或修工具缺陷不能解决；有权使用的训练材料和支持训练的模型。任何条件不满足，继续经验蒸馏，不启动权重训练。

- **建集**：数据负责人登记用途、来源、授权、地区、保留期与删除条件。优先合成、公开或明确批准的材料。禁止默认导出员工对话、私人记忆、项目文档或完整人工定稿。严禁为建集把原始临床内容暴露给未授权模型。
- **训练**：将经复核的任务输入、目标结构、关键判定及反例做成版本化数据集；不把教师模型输出天然当作真值。按项目/协议族分割训练、调参与最终盲测，查近重复和翻译副本。训练在受控执行环境独立运行；保存基座、适配器、数据版本、配置和回执。不是每个插件或每个人都要有一份权重。
- **登记与试点**：模型注册表登记不可变版本和兼容工具协议。离线对照通过后，在批准区域/插件/模型策略内小范围路由，记录命中版本、错误和成本。员工个人模型选择不能绕过批准范围。旧模型继续可回退，不在进行中的 Run 中静默替换。
- **退出**：关键指标退化、授权失效、制品无法复现即停止新流量，恢复上一获准路由并审查已产生的结果。删除原训练样本不能保证从已有权重中遗忘；撤销用途授权时应隔离受影响制品，依协议重训或退役，不能承诺“删一行就遗忘”。

**版本独立**：软件版本回答“系统有哪些工具”；知识发布回答“本次可用哪些已验证方法”；个人记忆版本回答“怎样与这个人协作”；模型版本回答“哪个模型执行”。日常学习当中前者不动，其他版本按需独立变化，并随 Run 留证。

## 8. 如何判定达到人工标准

**先冻结任务范围和阈值，再看结果。** 每个插件由领域负责人和 QA 定义任务、关键错误、评价单位、有效分母、未决、容忍差及所需有效项目数；未定阈值、样本不足、未签收都不能写“达到人工水平”。不能按规则条数简单平均，让大量重复易例淹没少数关键漏项。

| 对照组 | 固定与变化 | 回答的问题 |
|---|---|---|
| H：独立人工基线 | 同一留出任务、输入和交付要求，独立产出；盲评并处理复核分歧 | 有经验人员实际能达到什么水平，而不是历史定稿是否逐字重现？ |
| B：现有 AI | 固定模型、工具、输入、预算、基线知识；关闭待测新增方法及个人偏好 | 未学习前的表现如何？ |
| K：知识学习后 AI | 相对 B 仅改变知识发布版本；保留失败与未决，随机模型按预定次数重复 | 改善是否来自知识？ |
| M：可选后训练模型 | 相对 K 仅改变模型/适配器版本，再跑独立冻结集 | 权重训练相对于已有知识是否有额外收益？ |

按项目配对、按语言/地区/EDC/难度分层报告，给出样本数、分子/分母和以项目为单位的不确定性；正式“达到人工标准”要求主要质量指标相对人工基线的置信界不越过预先批准的非劣界值，且关键错误与安全门禁满足冻结要求。测量返工分钟数与交付时间，效率不得抵销关键质量退化。评价人不知产物来源；答不出来、解析失败和未决单列不丢弃。个人习惯另测被正确应用、编辑和停止，不以界面偏好满意度替代业务质量。

| 领域 | 首批领域指标 | 必测反例 |
|---|---|---|
| DVP | 关键规则漏项、误增、逻辑等价、证据支持、未决和人工返工时间 | 措辞不同但语义等价；源材料没有阈值时不得编造 |
| Listing | 关键异常漏报、误报、同输入复现、复核工作量 | 干净对照、缺失字段；不把某项目例外扩散到其他项目 |
| 参与者／可视化 | 字段来源、映射或指标绑定正确率、可复现性 | 同名不同义、缺少数据、跨项目串读 |
| 平台类插件 | 有效指引率、故障恢复结局、过期指引拒用 | 已撤回指引、状态未知，不虚报恢复成功 |

## 9. 工程拆分与提交边界

下表是执行依赖，不是 Agent 运行时的工具顺序。每组文件只设一个写负责人；开始前核对未提交改动与其他写入范围。首轮只做 **DVP + Listing** 的学习试点；原计划 DVP + 工作台的真实宿主验收仍须单独完成，不相互替代。不得因两插件试点在公共包中写两个业务分支。

| 工单 / 依赖 | 主责与主要落点 | 完成定义 |
|---|---|---|
| L0 基线和 ADR | 平台、IT、QA、领域负责人；现有知识/身份/发布合同 | 冻结区域、两名试点用户、两独立项目、隔离环境、领域基线和盲测分割；记录共享服务与个人数据保留策略、非劣界和中止条件。 |
| L1 权威服务 / L0 | 知识包负责服务与存储边界；控制面负责快照适配；身份方提供可信主体 | 两台客户端访问同一区域服务；组织、区域、主体和项目隔离覆盖列表、直接 ID、计数、分页、快照和日志；网络中断不访问其他库。 |
| L2 个人记忆 / L1 | 知识包：类型化设置、私有草稿与删除；工作台：我的习惯及本次使用说明 | 甲跨设备可读，乙不可见；开关关闭后不再取用；删除后备份恢复也不复活；不影响普通授权读取。 |
| L3 复盘与发布 / L1 | 控制面：可靠投影与重放；知识包：候选、验证、发布指针；插件：领域验证 | 可信观测→处理结局→新候选→独立回执→不可变清单→新 Run 引用全链路可对账；技术激活不是发布批准。 |
| L4 双插件盲评 / L2、L3 | DVP 与 Listing 各自维护测试素材、指标和验证器；QA 独立持有答案 | 两插件分别跑 H/B/K 并报告全部结果；发布知识前后 DSH/插件/工作台制品摘要完全相同。没有观察到收益也如实记为失败或不足。 |
| L5 运维及扩大覆盖 / L4 | IT、运维、发布负责人；装配清单与发布门禁 | 做并发、撤权、回退、灾备、区域隔离演练；下一纳管插件只登记能力、方法和评测，不改公共业务分支。按批准的区域/插件逐个放行。 |
| L6 可选权重训练 / L4 证明有剩余问题 | 模型负责人、数据负责人、QA；模型目录、执行与路由适配 | 训练数据用途可审计，M 对 K 有预设收益且无关键回归；新旧模型可在不修改 DSH、不重建插件的条件下切换并回退。 |

## 10. 放行清单与证据

以下均为**拟议验收，尚未执行**。现有 A01–A16 继续有效。技术验证、领域质量、部署运维三项分别签收。

| ID | 必须实际执行的场景 | 放行事实 |
|---|---|---|
| T01 | 甲设备一保存偏好，设备二创建新 Run；乙猜 ID、搜索、导出、查看共享 Run | 甲新 Run 应用偏好；乙得不到甲的正文、ID、计数或私有引用。 |
| T02 | 同一个甲从 A 切换到 B；本人偏好与项目裁定同时存在 | 私人呈现偏好保留；A 的事实不进入 B 的检索、日志或绑定；越区同名项目同样隔离。 |
| T03 | 默认关闭、临时使用、开启、暂停、删除后恢复备份 | 临时选择不落长期库；暂停/删除后不再检索注入；删除墓碑或等效机制在恢复时先重放。仅保政策允许的最小审计。 |
| T04 | 同一人工纠错重复投递、消费者中途崩溃、有人同时改修订 | 恢复后无丢失、无双候选；冲突提示明确，回执不重用，业务 Run 状态不变。 |
| T05 | 项目或私人经验提议公共化；覆盖不足、无权发布、证据冲突 | 原记录权限不变；未验证、未批准或可反推项目身份的内容不能公共发布。 |
| T06 | 发布知识前启动 A，发布后由乙启动 B；再撤回条目 | A 不自动换版，B 绑定新发布，查到实际返回/引用；撤回后新旧 Run 都不能重取失效正文；回滚不能恢复撤回内容。 |
| T07 | 隔离环境固定软件制品，完成一次项目复盘与跨员工消费 | 提交发布前后软件制品摘要、知识版本、绑定、命中与评测记录；无 Git 变更、无重编译、无新插件版本、无手工改 profile。 |
| T08 | 新留出项目上分别完成 DVP、Listing 的独立盲评 | H/B/K 各自有分层分母、关键错误、未决、返工与签收；仅在达到冻结条件的领域/范围宣称达标。 |
| T09 | 知识服务断连、撤权、区域故障和恢复演练 | 无越权降级或跨区回源；仅一名权威写者；按冻结 SLO、RPO/RTO 实测并对账。 |
| T10 | 有训练资格时发布、撤停模型并回退；无资格时请求训练 | 合法路由仅影响新 Run；证据可追溯，旧路由可恢复；用途不符不训练。未启用训练则记不适用，不据此声称验证了模型发布。 |

证据包最少含：场景 ID、环境与制品摘要、知识/模型/数据版本、输入与结果摘要、使用的身份角色、实际分母与错误数、复核人、结论（通过/失败/阻塞/未执行）及理由。不得放凭据、受试者信息、个人习惯明文、逐条临床差异或原始提示词。面向员工提供来源说明；面向运维监测事件积压、验证失败、被撤回版本仍被请求次数、发布回滚和知识服务可用性，不记录私有正文。

**实施门禁**：使用项目支持 Node（>=24.9.0）执行 `node scripts/verify-all.cjs`；其覆盖的包、规范与黄金检索只证明实际跑过的工程检查。另需真实 DSH 宿主、多员工/设备、独立留出项目和运维演练证据。**首个里程碑是 T01–T08 有可复核结果，不是采购数据库、增加知识条数或启动模型训练。**
