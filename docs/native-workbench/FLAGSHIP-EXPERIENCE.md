# Emerald 旗舰工作台：从续作到可信交付

2026-11-19 · 产品与交互设计稿，非实现或发布批准。配套：[双屏视觉样张](FLAGSHIP-EXPERIENCE.svg)。样张用公开研究名称与虚构批次、时间和交付状态演示界面，不表示实际 EMPA-KIDNEY 工作已有正式交付。

## 设计主张

**让需要处理的工作在首页被发现，让正式交付在工作页被认出，即便最新运行失败。** 服务对象是做临床数据工作的操作者和复核者，而不是平台管理员。首版只改两条高频路径：首页续作、工作页核对与交付；不另起应用、不复制聊天、不用绿灯装饰治理能力。

第一轮考虑过「大标题＋状态卡墙」和「工作清单＋项目侧栏」。最终保留清单，把大标题换成一条具体待恢复工作；工作页也取消等权卡墙，仅给**当前交付**带浅绿底的纸签样式。临床文档贵在准确识别版本，这个视觉重心只在其指针真实可确认时使用；无交付、读取失败、撤回均不着正向颜色。

| 设计令牌 | 取值 / 用法 |
|---|---|
| 石灰纸底 | `#F2F5F1`，页面与工作区间隔 |
| 文档白 | `#FFFFFF`，列表、原生 Chat 和证据正文 |
| 深松墨 | `#182B26`，标题与主文；用字号区分层级，不靠淡字堆层级 |
| 翡翠墨 | `#11604A`，主操作、键盘焦点和已确认交付；不用于尚未复核的运行 |
| 旧纸绿 | `#E0EEE6`，当前交付底色，不代表最新一跑成功 |
| 陶棕 | `#8B421E`，失败／需要注意，必须伴随状态文字 |
| 字体 | `Source Sans 3` + `Noto Sans SC`，使用部署方批准的本地字体或系统回退；正文 14–16 px，列表标题 16 px，页标题 28–32 px；批次号、版本和时间用等宽数字而非等宽字体 |

内容左对齐，主操作在所在区块末侧；不把标签居中做海报。桌面导航约 200–224 px，工作页证据栏 320–368 px；窄屏先折叠导航，再把右栏变为可显式打开并返回焦点的面板，不能挤压 Chat 到不可用。实机校验 1440、1024、390 px，并做 200% 缩放；暗色跟随宿主，必须单独实测对比、焦点与主按钮。

```text
首页    [平台导航] [我的工作      项目筛选  + 新建工作] [项目空间]
                   [优先处理：工作 / 原因 / 查看失败]   [当前项目]
                   [最近工作：名称 · 项目 · 状态 · 动作] [待我处理]

工作页  [返回我的工作  /  项目  /  工作名称]   [运行记录]
        [原生 DSH 会话                       ] [当前交付]
        [消息与原生交互继续留在这里           ] [正在使用的输入 / 最近运行]
        [原生输入区                          ] [结果与复核 / 运行历史]
```

## 首页：从工作开始，不从平台健康开始

- 首项「优先处理」最多一条：服务端有明确可处理的待办时优先展示；否则可提示最近可查看的未解决失败，并明确这不是待办。不把所有历史失败都纳入首页焦点。若没有待处理或可恢复失败，移除该块，让最近工作自然上移。
- 「待我处理」只消费服务端分配给当前身份的真实事项；空态为「没有待你处理的事项」。失败是运行事实，不是工单；归因尚未确认时只写「运行未完成，查看运行记录」，不编造缺文件或权限错误。
- 行级操作使用「打开工作」「查看失败」「继续复核」；后两者进入同一工作原生会话，并定位右栏对应运行或复核。无法打开会话或加载证据时显式说明并可重试，不偷偷新建第二个会话。新建工作保持全页唯一主操作；只有空列表才把新建作为空态主按钮。
- 项目筛选切换时同时更新可见队列和项目上下文；保留真实项目名。连接状态与执行器型号放设置／诊断。搜索、待办、列表和详情以服务端授权为准，不通过前端显隐实现授权。

## 工作页：四个事实，不共用一个「最新」

| 显示 | 数据语义 | 缺失或异常 |
|---|---|---|
| 当前交付 / Current delivery | 由实际交付决定与有效包确定，展示包版次、关联运行、输入批次、时间；不从成功或复核通过推断 | 分别显示未交付、已撤回、读取失败；权威结论不明时不显示为当前有效；历史包遵守其下载授权和撤回规则 |
| 输入基线 / Input baseline | 正在使用的输入批次；运行详情另显该次运行冻结使用的批次 | 未登记、登记失败、读取失败分别显示；重跑不改写旧批次 |
| 最近运行 / Latest run | 工作最近一次受治理运行，失败仍在此；详情可定位任何已选历史运行 | 排队、运行中、失败、取消、失联／读取失败有不同文案；断线不伪造终态，重新连上后对齐服务端 |
| 结果复核 / Result review | 选定运行及其准确产物版本对应的复核，显示独立于交付 | 待复核、通过、退回、读取失败分开；复核通过不自动等于已交付 |

右栏顺序：当前交付、输入与最近运行、选中运行的结果／复核、可展开的历史／诊断。打开旧运行时提示「正在查看历史运行」，不能挪动“最近运行”或“当前交付”指针。下载指向确切交付包；详细证据才显示来源、摘要、运行标识及允许可见的诊断。换批重跑要让操作者先看清新批次和旧交付会保留；提交中防重复，服务端仍是并发与幂等权威。若批次登记成功但运行未创建，保留已登记批次并允许针对它续跑，不再登记一份。发生并发复核／撤回冲突时刷新实际状态，不用客户端最后写入覆盖。

## 旗舰验收：同一工作，两次交付，中间允许失败

| 场景 | 通过条件 |
|---|---|
| 续作 | 公开或合成夹具中，批次 01 已交付、批次 02 最新失败。首页能通过一个明确动作打开原来的 DSH 会话并聚焦失败运行；真实待办为零时仍为零。刷新与返回不产生第二会话。 |
| 复核 | 以批次 03 重跑成功但未复核时，仍只认批次 01 的有效交付。用独立预期结果核对产物；复核准确绑定运行和产物版本。复核通过但未交付时，当前交付仍不移动。 |
| 交付 | 正式交付批次 03 后只移动当前交付指针。批次 01 按策略保留可追溯；两版分别核对批次、运行、复核和摘要。刷新后仍能读到同一权威指针。 |
| 失败与断线 | 复核服务不可用不显示「未复核」或沿用旧绿灯；事件断线不变成失败；交付冲突需重读；无授权不能从列表、搜索、事件或下载间接取到数据。 |
| 双语与可用性 | 中文和英文分别实走同一流程；键盘可定位失败、进入侧栏、回到原生输入；焦点不被轮询抢走，无横向溢出；错误和状态变化可由读屏理解。 |

验收证据应包含宿主与应用版本、测试身份及权限、运行/包 ID、冻结批次和摘要、期望对照、关键截图与结果日志；只存经批准的公开或脱敏证据。**体验验收与企业部署验收分开**：真实身份、项目与执行隔离、数据驻留/外发策略、独立临床质量回归与恢复演练必须另行通过。电子签名由实际用途与 IT/QA 确定，审计链不替代签名。
