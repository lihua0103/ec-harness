# T08 集中（hosted）部署逐条核对 — 2026-11-12

状态：**BLOCKED（未达到集中部署验收）**。本文件逐条列出已实现、已验证与缺失的能力；
不以本地形态结果冒充集中部署。

## 1. 已实现并可复现

| 能力 | 结论 | 证据 |
|---|---|---|
| 集中描述符（control URL、允许 Origin、域列表、端口） | 已实现 | `node scripts/native-workbench-deploy.cjs --mode hosted ...` 生成 `.runtime/nw-t12-hosted/native-workbench.deployment.json` |
| 控制 URL 含凭据/query 拒绝 | 已实现 | 同脚本 `--control-url https://user:pass@...` 报 `controlUrl` 并退出非 0 |
| 单一权威控制进程 | 已实现 | `scripts/native-workbench-start.cjs` hosted 模式只接受 `--role control` |
| 拒绝第二个进程共用同一 store | 已实现 | 同一脚本对非 `control` 角色打印拒绝说明；控制库层唯一写入约束已有测试 |
| 允许 Origin 白名单校验 | 已实现 | `platform-control` `workbench-deploy.test`（4 项） |
| 浏览器同源写代理 | 已实现（本轮） | `platform-workbench` host half 的 `handler` 路由；`POST /platform-workbench/api/works` 实测 201；跨站 Origin / `..` 路径 / 超限 body 负例测试 |

## 2. 缺失（blocked 依据）

| 集中形态必需能力 | 现状 | 为什么不能标记通过 |
|---|---|---|
| 认证入口（SSO/BFF） | 本地固定 operator principal；`platform-identity` 只有测试目录适配器 | NW11/NW12/NW13 全部 BLOCKED；不能把测试身份当 SSO |
| 域代理入口（HTTP/WS/文件/问答） | 未实现 | `native-workbench-start.cjs` 明确不启动该入口；脚本只启动控制面 |
| 两个隔离执行域（独立 home/附件/身份/凭据） | 只有两个 `ExecutionDomain` 记录，没有第二个真实 DSH 进程/家目录 | NW14/NW20 需要真实隔离，不能用 domainId 参数冒充 |
| 撤权后流撤销 | 未接 `remoteAccess.invalidate` 往返 | NW12 BLOCKED |
| 非 owner 问答/审批 | 上游 README 明示 owner-only | NW13 BLOCKED（见 CONTRACT-MATRIX §2） |
| 跨域 Session 路由 | 只有单控制面 + 单 web 进程 | NW10 用两个域记录 + 两个原生会话验证了**切换与隔离**，但不是两个真实集中域 |

## 3. 结论

- hosted **描述符校验**与**单控制进程约束**：已实现并实测。
- hosted **运行形态**：BLOCKED。缺少认证入口、域代理、两个隔离域与撤权往返；在这些能力未实现前，
  不把本地 `127.0.0.1` 形态的通过结果扩大为集中部署通过。
- 复现命令见 `docs/native-workbench/IMPLEMENTATION-2026-11-12-T12.md` §T08。
