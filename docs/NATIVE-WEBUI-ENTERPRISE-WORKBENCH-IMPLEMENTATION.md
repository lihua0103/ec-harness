# 原生 WebUI 与企业工作台：开发实施任务书

日期：2026-11-12 · 版本：1.0 · 状态：**待开发；不是实现完成、部署验收或生产批准**。

读者：接续开发的模型、工程师、测试人员。本文独立于聊天记录，规定目标、推荐设计、任务依赖、文件责任和验收事实；不限制开发者为实现目标自主选择工具和纠错路径。

## 0. 接手说明

### 0.1 用户确认的目标

1. 保留 DSH 原生 WebUI：真实流式输出、工具活动、原生输入/队列、问答、停止、连续会话、历史和故障反馈。
2. 同一个产品提供企业工作台：项目、应用、长期工作、资料基线、成果版本和待办。不是两套聊天系统或 iframe 拼接。
3. 优化员工使用体验，减少重复填表和工程字段；不牺牲真实可观察性，不用假进度和打字动画。
4. 员工独立执行环境与集中部署都要支持；共用客户端、业务能力和核心合同，不是只预留集中模式配置。
5. 已有企业用户权限系统，后续通过适配器接入；不另建用户、组织、角色管理系统。真实协议尚未提供，测试身份通过不能写成 SSO 已接入。
6. 保留 Harness 自主规划、工具选择和纠错。业务插件不增加普通读取/R 开发审批，不按文件名或资料类别拒读；领域专属合同仍有效。
7. 不未经请求提交、推送、改生产 profile、删除历史记录或用户数据。

## 1. 目标架构与禁止事项

```text
同一 EMERALD WebUI（DSH 原生宿主）
  ├─ 企业导航：项目 / 应用 / 我的工作 / 待处理
  ├─ 原生 Conversation + Chat + composer + 文件/工具视图
  └─ 企业贡献：工作上下文 / 输入基线 / 成果版本 / 检查范围
             │
     可信连接与执行域定位（本地或集中）
             │
  执行域中的原生 Gateway / Session Controller / Agent
      ├─ 平台 Host 集成：授权、Work 绑定、事实投影
      ├─ 业务插件：工具、Skill、领域验证与展示贡献
      └─ 独立会话/附件存储与获准执行环境
             │
  企业控制面：工作关系、发布、执行记录、成果封存、审计
             │
  现有企业身份/项目权限/数据系统（适配器接入）
```

职责边界：
- DSH 持久 Session 是会话事实来源；原生临时流只服务当前展示。
- 控制面是企业工作/发布/成果事实来源，不执行领域解析或 Agent loop。
- 同一个 Session 只有一个写入所有者。不得另起 Web Host 争抢 SDK 活跃会话写柄。
- 交互使用原生 Host/Client；批处理继续使用 SDK Worker，不能同时拥有同一 Session。
- 对话轮结束、执行结算、进程退出、成果审核是不同事实。
- 不导入私有 UI 组件、不挂第二套 React、不替换根 DOM、不发明第二套会话流协议。
- 不设置臆造 token 百分比，不把工具错误一律升级为任务失败，不把网络断开显示为取消。
- 不以“未来扩展”为由引入消息总线、微服务或重复状态机；先复用当前所有者。

## 2. 用户界面与行为合同

### 2.1 信息架构

左侧统一导航：新建工作、我的工作、项目、应用、待处理。应用目录按发布元数据组织，可搜索/收藏，不为每个插件新增顶层导航。

工作页上方展示项目、工作标题、应用、执行位置。中央始终使用原生会话；右侧上下文/成果与原生文件、浏览器面板复用布局服务。窄屏使用抽屉/视图切换，不缩成不可用三栏。

“工作视角”和“详细过程”只是同一 Session 的信息密度选择。不得切换时创建另一个会话、删除错误或阻断实时更新。平台级扩展统一承载业务入口，领域插件不各建一个聊天面板。

### 2.2 关键操作

| 操作 | 预期行为 | 禁止 |
|---|---|---|
| 从项目开始 | 继承已选项目/合法空间，选择应用，主要输入目标 | 默认写入仓库根、伪造企业项目 |
| 首次空间选择 | 明确选择本地或远程实际目录，服务端验证 | 浏览器本地路径直接当远程路径 |
| 发消息 | 原生 composer 提交到绑定 Session，收到接纳再交接草稿 | click 即显示已执行、双写 SDK 与 Host |
| 执行中输入 | 使用已验证的原生 queue/steering，明确显示模式 | 按钮说发送实际只存草稿 |
| 停止 | 原生取消当前执行，等待实际结算 | 立即标 CANCELLED 或默认销毁整个 Host |
| 后续追问 | 同一 Session 保留上下文 | 单纯拼接前次 finalResponse 冒充恢复 |
| 换批次 | 新输入基线和执行尝试，保留旧成果 | 覆盖旧文件、承袭旧批准 |
| 模型选择 | 当前实际模型与待生效选择分开，默认在空闲执行边界生效 | 修改已冻结执行记录、共享默认串用户 |
| 文件查看 | 原生文件预览；正式下载沿用授权与摘要校验 | 将所有可写工作文件称作封存成果 |
| 重连 | 恢复订阅与历史，输入未知时先对账 | 自动重放未确定副作用 |

默认值减少操作但不替代授权。标题可取可编辑目标摘要，不为命名增加一次模型调用。工程信息折叠可查，不强制员工填写 profile、provider、路径映射等内部字段。

## 3. 数据与接口合同（目标，不是已存在 API）

下列名称是项目内建议命名，实施者可以沿用已有等义模块；不得把它们宣称为上游 API。

### 3.1 核心对象

| 对象 | 最低信息 | 所有者/不变量 |
|---|---|---|
| ExecutionDomain | id、归属、local/hosted、受控部署引用、能力、健康、revision | 域注册服务；公开信息不含密钥和任意代理地址 |
| WorkSessionBinding | workId、domainId、sessionId、workspaceId、发布摘要、primary/fork/reopened、来源、revision | 控制面；同一 Work 最多一个当前主绑定；旧关联不覆盖 |
| Submission | 稳定 requestId、Work/Session/域关联、输入摘要、可信提交者、接纳凭据/消费证据 | 控制面记录企业意图；原生日志决定接纳/消费事实 |
| Execution record | Work、Session、执行区间、输入基线、模型/发布快照、状态 | 复用/演进 Run；不承载聊天文本历史 |
| Input baseline | 输入版本/引用、摘要、代码来源、创建者 | 平台；新批次追加，不改旧基线 |
| Artifact version | 文件引用、字节摘要、输入/执行来源、封存状态 | 复用成果机制；业务审核另记确切版本 |

建议唯一约束：域内 Session 关联唯一（除明确只读引用）；一个 Work 一个当前 primary；提交 `(domainId, sessionId, requestId)` 唯一；原生持久事件投影以 `(domainId, sessionId, seq, projectionKind)` 去重，不能按文本内容去重。

同一个 Session 可覆盖多个 Run；一个 Run 可覆盖多个原生 turn/step，不能假设一一对应。业务追问允许无成果结束。企业工作中的原生输入仍需可关联执行/模型事实，不能成为未审计的旁路；不强迫用户手动选择每条消息的技术分类。

### 3.2 项目内服务操作

| 操作（拟议） | 参数/语义 | 并发与权限 |
|---|---|---|
| resolveWorkContext | workId → 项目、发布、域、空间、绑定与可用能力 | 每次服务端授权；不存在/无权一致 |
| ensureWorkSession | workId、期望 revision、幂等 operationId | 先登记意图、调用原生 create、记录实际返回 sessionId；重复不双建 |
| observeWork | workId → 企业状态观察 | 会话正文仍走原生 follow，不代理成 activities |
| correlateSubmission | 原生 requestId、已验证绑定、可信主体、输入基线引用 | Host 入口校验，不接受模型提供 actorId |
| requestWorkStop | Work/绑定 + 操作身份 | 原生 cancel；记录意图和结算，不直接终态 |
| prepareNextExecution | 新资料/模型选择、expectedRevision | 不覆盖在途快照；原生提交执行前重新验证 |
| registerArtifactVersion | 稳定快照引用、执行引用、摘要 | 受信执行服务提交，控制面复算；模型不能自报通过 |

不得把这张表机械翻译为另一套聊天 RPC。优先以 Host 集成消费现有服务，Client 继续使用原生会话方法。接口缺口必须登记具体公开入口、为什么现有机制不能实现、最小新增契约及回归用例。

### 3.3 企业库与 Session 日志的非原子提交

两者没有共享事务，必须处理中间失败：
1. 企业写入幂等创建/提交意图，冻结权限、发布和关联身份。
2. 通过已验证原生入口接纳，使用稳定 requestId。create 返回的真实 ID 为准，不能默认请求 ID 就是最终 Session。
3. 接纳回执/原生事件确认后更新企业关联；只确认接纳不能标消费。
4. 回执丢失时，按原生 inbox/日志与 requestId 对账；无法证明就保留未知，不自动重发。
5. 进程重启继续核对未结算意图；拒绝过期所有者回写。

至少覆盖四个故障切点：意图前、意图后原生前、原生接纳后企业确认前、消费后结果投影前。不要把所有失败都处理成新建 Session 或新 Run。

### 3.4 生命周期与发布组合

- 保留当前批处理 `RunSnapshot` 完成屏障；新增明确执行种类/合同版本后才演进交互结算，不给批处理默认 `cleanedUp=true`。
- 交互结束要求该执行区间输入/后代/结果状态可解释，不要求杀死整个 Host。
- 封存时稳定快照、原子发布或可证明无写者；复制后复算摘要。仅 turn/end 不保证后台工具不再写文件。
- AppRelease → RuntimeBundle/profile/preset 映射由受控部署清单提供。多个应用需要不兼容插件组合时定位不同执行域，不在会话运行中随意安装插件。
- fork/更换应用/执行域/运行组合产生显式关联或新工作。原会话不被静默转移，原生历史格式不自造迁移。

## 4. 开发任务清单

所有任务初始为 NOT_STARTED。每项开始时重新核对文件，按“事实、目标、验收”执行。文件路径为已存在路径或明确标为新增的推荐路径，不能把规划文件当作已经存在。

### T00 — 接手基线与写入所有权

**依赖**：无。

**范围**：只读工作区/上游/profile；新增 `docs/native-workbench/evidence/BASELINE.md`（实施时创建）。

**工作**：记录外层/上游 HEAD、dirty 文件、Node、依赖、当前测试命令和实际监听服务；确认其他会话写入范围。先看 diff，不覆盖未提交工作。记录任务唯一写入负责人；未收到回复不等于协调完成。

**验收**：基线可复查；未经授权未切分支/提交/清理；Node 支持 >=24.9；真实密钥不进入证据。

### T01 — 上游能力矩阵与 ADR

**依赖**：T00。

**范围**：新增 `docs/native-workbench/CONTRACT-MATRIX.md`、新 ADR（编号按目录分配）；修订旧补充方案、临床方案和运行合同中受影响段落。

**工作**：按 create/resume/prompt/queue/steering/cancel/follow/model/question/approval/upload/file/fork/archive 逐项记录公开 package export、签名、角色限制、profile 依赖、测试及本项目映射。核对 Client slots 与打包方法，明确跨进程控制服务接入方式。采用本文单宿主路线；首个集中参考实现使用两个独立执行域，而非共享全权 Host。

**验收**：区分“源码已核实、装配已验证、实际行为已验证”；未确认签名不得写实现桩蒙混。ADR 明确旧路线替代与保留数据策略。

### T02 — 最小原生 Host/Client 集成与集中风险探针

**依赖**：T01。

**范围**：新增 `packages/platform-workbench/` 的 manifest、Host/Client 入口、构建、locale、测试、README、bundle patch；隔离开发 profile 装配。不修改生产 home。

**工作**：复用 `ui-conversation`、`ui-chat`、`ui-session` 和 slots；注册品牌和最小“打开工作”入口；通过原生会话打开/创建做两轮真实交流、工具、流式、停止、刷新。开发构建分 Host 与 browser，宿主依赖外置，不打包第二份 React。记录实际产物/安装依赖，而非只跑源文件。

并行于本任务内部验证非 owner 授权、原生问答、审批、上传和附件。公开机制不支持的地方给出可重复失败测试与最小扩展设计；该分支不许以 owner 绕过。需要上游修改时独立说明改动和兼容证据，不假装仍是未修改的锁定版本。

**验收**：真实 profile Loader 加载；卸载清理 slots/连接；文本在最终消息前出现；两轮同 Session；刷新不创建新会话；未解决集中限制列 BLOCKED，不能标本任务完整通过。

### T03 — 企业对象与持久存储

**依赖**：T01；集成签名采用 T02 已验证结论。

**范围**：`platform-control/src/store.ts`、`works.ts`、`service.ts`、`index.ts`；按需新增 `session-bindings.ts`、`execution-domains.ts` 和对应 tests。

**工作**：实现 §3 的域/绑定/意图/输入基线关系及唯一性；复用 `WorkRepository`、`PlatformStore`、CAS/revision 模式；通过公共 exports 暴露所需能力。迁移使用当前 schema 版本机制，旧 Work 的新字段可缺省为未关联，不伪造 sessionId。

**验收**：并发创建仅一主绑定；两个域同名 Session 不冲突；重复 requestId 不重复提交；重启关系仍在；旧库/损坏库/中断迁移测试；只读历史不启动 Agent。

### T04 — 身份、政策和执行域访问适配

**依赖**：T01、T03；T02 角色探针结果。

**范围**：现有 `packages/platform-identity/src/index.ts`、控制面 `policy.ts`、新增集成包 Host 身份/权限适配模块；不要在 UI 内实现授权。

**工作**：复用已验证 assertion 派生与授权目录规则；transport 负责认证真实性，不能仅检查 assertionDigest 格式就认定登录。保留 orgId，拒绝跨组织碰撞/混淆。以企业目录适配器提供项目/应用/模型/域权限，映射至原生资源授权；权限缓存失效触发 `remoteAccess.invalidate` 并验证已有流撤权。所有原生 create/prompt/queue/model/fork/文件入口受覆盖，不能只保护企业按钮。

**验收**：双身份项目/列表/消息/文件/模型越权测试；撤权后旧连接不继续泄漏；模型参数 actor 不生效；本地模式明确本机信任边界。缺真实身份接口时测试适配器清楚标识，不提供可被误认为生产认证的默认允许入口。

### T05 — 交互提交与执行记录集成

**依赖**：T02、T03、T04。

**范围**：集成包 Host 操作适配；`platform-control/src/service.ts`、`runs.ts`、`models.ts`、`worker.ts`、`platform-runtime/src/run.ts` 中实际需要的部分。

**工作**：实现原生提交与企业意图关联、模型/发布快照、接纳/消费对账；保留原生 composer 和 requestId。原生发起路径若无公共前置接缝，先补契约，不用 DOM 拦截或事后审计冒充执行前授权。支持运行期原生 queue/steering，正确关联执行区间。停止取消当前执行而非整个 runtime；批处理停止保持原有严格退出证据。后台任务/子智能体存活时不回收域。

**验收**：§3.3 四个故障切点；重复点击/超时回执无重复执行；排队/steering/停止竞争；一轮结束可继续；UNKNOWN 不自动重放；模型默认不串用户；已有批处理测试不回退。

### T06 — 企业导航、工作列表和上下文

### T08 — 本地与集中部署装配

**依赖**：T02、T04、T05；集中限制必须已解决。

**范围**：新增参数化原生工作台部署/启动脚本、受控 profile 模板与部署说明；复用 `scripts/start-dsh-web.cjs` 的已核实官方启动方式，不继承仓库根默认权限。部署差异不写入业务插件。

**工作**：本地显式 home/workspace/port；集中注册受控域、HTTP/WS 连接路由、健康与停机；同一 UI 制品用于两形态。集中域采用独立 home、附件、进程身份/文件权限和凭据边界；不同进程不等于沙箱。入口只代理允许服务，不接受用户 URL，验证 Origin/认证/撤权，不把凭据放 query 或日志。转发原生协议，不解码改造成聊天事件。

集中控制数据指定一个权威服务进程，不让多个 Host 直接共享本地 SQLite 文件；执行域经认证平台接口访问既有服务逻辑。本地可在受控单所有者模式同进程装配。连接切换释放旧域资源；未验证的跨域平滑切换不用全局单例硬改，可经同入口受控页面导航进入目标域，不能产生两套聊天 UI。

**验收**：两个域相同 Session ID 路由正确；非授权域不可连；WS 断开恢复；普通文件/上传/问答不因反向代理失效；凭据/附件不跨域；集中 Host 持续运行时关闭浏览器不终止任务；本机睡眠不假报后台继续。

**验收**：边输入边流式；焦点/选区/草稿保留；错误可读且可定位；切换/重连无重复消息；窄屏和暗色主题；无隐藏后台工作被标完成。性能记录环境、输出规模和渲染表现，不能用未测数值宣称提速。

**验收**：历史审计/成果数量摘要一致；只读打开无副作用；旧链接不串工作；回退部署入口不降级 DSH 日志格式、不自动恢复旧数据库覆盖新写入。验证通过前不拆旧可用入口。

## 7. 集中部署与企业接口的明确阻塞规则

- 非 owner 问答/审批：锁定 `remote-access/README.md` 明确限制。先复现，再实现公开参与接缝；未闭合不得通过 NW13/NW20。
- 附件是存储级读取：独立 home 与执行身份是必要设计；不能以 sessionId 参数证明隔离。
- 非 owner Fetch：逐条核对上传/预览/下载路由的授权，不只测试 WebSocket。
- 既有公司系统未知：需要认证方式、受信 assertion 校验方式、项目授权查询、撤权机制、模型/数据授权边界；文档/测试 adapter 可先交付，真实接入列 NOT_RUN。
- 公共 slot 不足：先登记公开扩展缺口，不能导入私有组件以通过截图测试。
- 版本升级：若修改上游，制品标识为锁定基线加补丁摘要，不声称未经修改的上游通过。
- 服务部署：身份或域不可达时不静默回退 LocalOperatorPolicy、不自动选另一模型/目录。
