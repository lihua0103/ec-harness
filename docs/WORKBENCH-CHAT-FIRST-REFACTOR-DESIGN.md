## 0. 结论

**总评**：工作台的数据语义是诚实的（运行状态、封存、复核、交付各自独立留痕，三态分开，不编造成功），可访问性和恢复能力也有扎实投入。问题出在“把这些事实摆到用户面前”的这一层：界面是按**平台的概念模型**（工作 / 运行 / 绑定 / 批次 / 交付包）组织的，不是按用户的任务（**我在和智能体对话，顺手处理它交给我的事，必要时看结果文件**）组织的。结果就是列多、层多、入口多，而最常做的事——换一个对话——要两步且会卸载当前对话。

**三个结构性问题**

1. **对话不是主场**。1440 宽下中央对话 760px，1280 宽下只有 600px（47%）；两列辅助区 + 图标轨吃掉一半宽度；对话上方压着两条头部栏（141px）。
2. **同一个动作有三套列表**。工作索引（main 内）、历史会话（独立页）、运行历史（右栏最后一张卡，在 2.9 屏长的右栏里排最后）都能“打开一个对话”，交互各不相同。
3. **工程上把“防止副作用”做成了“多一步确认页”**。因为打开未绑定的工作会自动创建并绑定会话，方案 B 才设计了“索引只预览 → 摘要 → 进入会话”，并把“会话中点另一行 = 显式离开”写进了测试合同。这正好和现在的要求相反。

**重构一句话**：左侧一份会话列表，点谁中间就换成谁（对话和右侧资料一起换）；右侧收成一个分页资料面板；全局导航从 6 项收敛到 3 项；全部界面文字走宿主的多语言机制。

**先止血（P0，实测复现，不改架构即可修）**：窗口较窄时整个界面被挤成 284px 窄条或“工作资料”整栏不可达；全局字号被压到 8–11.5px；无运行的工作永远“正在加载…”。详见 §3.0。

### 3.B 会话切换（本次要求的重点）

| # | 问题 | 证据 | 影响 |

## 5. 目标设计

### 5.1 原则

1. **对话优先**：对话始终是最宽的一列，任何辅助信息都不得把对话挤到 600px 以下。
2. **点谁换谁**：列表、运行记录、收件箱里的任何一项，单击即让中央对话和右侧资料一起切换到它，原位完成，不经过中间页。
3. **一件事只有一个地方**：一份会话列表、一个输入框、一条头部栏、一种确认方式、一种语言机制。
4. **重要的事浮上来，其余收起来**：默认界面只有状态、待办、文件；批次、摘要、交付包、对账进“详情”。
5. **打开不产生副作用**：打开工作不创建任何东西，绑定发生在首次发送之后。
6. **数据诚实不变，表达换成人话**：事实语义原样保留，术语和解释默认收进“技术详情”。

### 5.4 会话切换模型（核心）

**目标对象**是唯一的路由状态，其余全是它的投影：

```ts
type ChatTarget =
  | { kind: 'work';   workId: string }                 // 工作对话
  | { kind: 'run';    workId: string; runId: string }  // 某次运行的对话
  | { kind: 'session'; sessionId: string }             // 未归入工作的原生会话
```

- **切换流程**：① 立即更新目标（列表高亮、头部、URL 同步，≤1 帧）；② 取会话引用：命中缓存则同步得到，未命中则 `ctx.sessions.retain()`（同步；仅冷启动目录未就绪时才等待目录刷新）；③ 中间挂到新引用，右侧面板按同一目标取数。旧目标进入缓存，不释放。
- **引用缓存**：以插件自己的 source 保留最近 5 个会话的引用，LRU 淘汰时才 `release()`。**[上游]** 宿主合同按引用计数，“最后一个引用释放才开始拆除”，所以多个引用并存是受支持的；现在的“单槽 + epoch + 同步换绑”可以整体删除。保留数上限是因为每个引用持有一份已打开的历史和订阅，需在实现时实测内存占用后定。
- **状态保持**：每个会话的滚动位置、View 标签（对话/轨迹）、未发送输入按 `sessionId` 存一份，切回来即恢复。
- **运行 → 会话映射**：`RunSummary` 现在不带 `sessionId`，每次都要多一次 `runDetail`。建议控制面在 `workRuns` 列表里直接带上 `sessionId`（小改动），切换即纯同步。未带上之前沿用一次预取。
- **无会话可切时**：中间保持当前对话不动，头部和列表同步标回真实目标，并在目标行上给出“该运行没有对话记录”的说明——不出现左右不一致（修 B6）。
- **打开无副作用**：打开未绑定的工作时，中间显示宿主的空白新对话姿态，**首次发送后**由提交观察器完成绑定（它已经只读地观察公开的持久事件，不拦截输入框）。宿主 `sessions.create` 支持复用可复用的空白会话。此点需先做一个小原型验证。
- **URL**：`#/c/<workId>`、`#/c/<workId>/r/<runId>`、`#/s/<sessionId>`、`#/inbox`、`#/workspace`、`#/settings/<tab>`；旧格式重定向。刷新和前进后退都由它恢复，运行对话也能正确恢复。
- **键盘**：列表内 ↑↓ + Enter；全局“上一个/下一个对话”；⌘K 里直接列出会话和动作；Esc 从运行对话返回工作对话。全部经 `ctx.shortcuts` 注册。**[上游]** 该注册表会做冲突检查、可自定义、有快捷键一览；现有的手写 Ctrl+K 监听应迁入。

### 5.5 资料面板（右侧）

| 页 | 内容 | 来源（现有卡片，只搬位置不改语义） |
|---|---|---|
| 概览 | 状态一句话；“智能体正在做什么”时间轴（由运行事件翻译成人话）；**需要你的决定**（有问题/复核时置顶）；输入资料；最近结果；交付状态 | 运行状态、RunEvents、InteractionPanel、ReviewPanel、工作指针 |
| 文件 | 最近一次运行（或当前运行）的成果，文件卡 + 下载；可切换运行 | 文件成果、成果版本 |
| 运行 | 该工作的运行时间轴；选中项可停止/重试；「＋ 发起运行」 | 运行历史、RunActions |
| 详情 | 技术信息，默认折叠：运行抄本与原始事件、知识依据、输入批次与换资料重跑、执行输入、交付包（封存/交付/接收）、确定性验证、结果视图与比对、工作说明 | RunTranscript、KnowledgeBasisCard、InputBaselinesCard、RunInputsCard、DeliveryPackagesCard、EvaluationCard、ResultViewsCard、DraftPanel |

规则：某一页没有数据时，该页不显示占位行和禁用表单，只显示一句空态；“详情”里的小节有数据才出现。

### 5.6 决定内联

有待答复的问题或待复核的结果时，在该对话的**输入框正上方**出现一条决定卡，按钮即选项（复核为“通过 / 驳回 / 写意见”），提交后收起并显示下一条。这与宿主自己的问答卡位置一致（**[上游]** `ui-user-questions` 在输入框席位显示）。同时：列表行和侧栏「收件箱」显示数量徽标；收起态图标轨也显示徽标（修 C8）。

### 5.7 新建对话

「＋ 新建对话」→ 中间立即进入新对话：顶部一个标题输入，下面是“项目”“应用”两个可点选的默认标签（取上次用的），输入框获焦。若项目或目录未就绪，就地给一句说明和“去工作区设置”的链接。首次发送时创建工作并发送。第一步可先做成一个三字段的小对话框（标题、项目、应用）以避开输入框集成，随后再演进为零表单。

「发起运行」保留为显式动作，但从常驻表单改为对话框（目标预填工作说明，场景、模型预填默认值，高级项“换资料重跑”折叠），入口在「运行」页主按钮和头部 ⋯ 菜单。界面上不再有第二个常驻文本框。

### 5.8 收件箱、工作区、设置

- **收件箱**：问题、复核、交付接收、模型审批的完整清单；点条目打开所属对话并把对应决定卡带到输入框上方。
- **工作区**：项目卡片 → 该项目的目录、应用、工作数；应用卡片带“用它开始”动作。登记目录的表单只在这里出现。
- **设置**：「个人」语言、时区、密度、默认模型、我的习惯；「平台」模型目录与健康、运营面板、审计、存储与配额、部署说明。现在的部署声明压成页脚一行，可展开。**[上游]** 宿主支持插件注册 `settings.section`，可以把“个人”页并进宿主设置，语言行只留一处。

### 5.9 反馈与文案规范

| 规则 | 做法 |
|---|---|
| 结果反馈 | 轻提示（宿主 `Toast`），2–4 秒自动消失；错误才常驻并可重试 |

## 6. 多语言设计

### 6.1 现状与目标

现状是 F1–F7：插件私有语言开关、主页面 657 处硬编码中文、布局按中文宽度写死。目标是：**一种语言机制、零硬编码文案、布局不依赖文字长度**，首发中文和英文全量，并可在不碰组件代码的前提下增加语言。

### 6.2 语言来源：跟随宿主

**[上游]** `@deepseek-ai/dsh-client-locale` 已内置中、英、日、西、法、德、俄、葡（巴西）8 种语言；用户在“设置 → 通用 → 语言”切换，立即生效并写入宿主设置；插件用 `ctx.locale.register(ns, { zh, en, … })` 注册词典（`zh`、`en` 为必填基线，其余可选），用 `ctx.locale.bind(ns)` 或框架注入的 `t` 取词；还可以用 `addLanguage` 追加宿主没有的语言，回退链必须终点为 `en`。

因此：

- 删除插件私有的 `locale` 偏好，插件语言 = 宿主语言。这样原生对话区和工作台外壳永远一致，语言开关只留宿主那一处。
- 词典按命名空间拆分注册：`workbench.nav`、`workbench.chat`、`workbench.panel`、`workbench.inbox`、`workbench.workspace`、`workbench.settings`、`workbench.errors`。
- 词典放进包内已有的 `locale/`（`package.json` 已声明 `./locale/*.json` 导出），不再写在 `i18n.ts` 的 TS 对象里，便于交给翻译流程。
- 保留的本地偏好只有时区和密度。

### 6.3 文案规则

1. **零硬编码**：组件里不出现任何面向用户的字面量（含 `aria-label`、`title`、`placeholder`）。加一条验证：扫描 `src` 中的字符串字面量，出现 CJK 或拉丁句子且不在词典文件里即失败。
2. **整句带占位符，不做拼接**：不写 `显示 + ": " + 数量`，写 `shown: '显示 {count} 项'` / `shown: 'Shown: {count}'`。各语言的占位符名必须一致。
3. **复数与列表**：宿主不提供复数和双向排版（**[上游]** README 明确写“不增加复数规则或双向布局”），由插件补一个很小的辅助函数：按语言选 `one / other` 词条（需要时加 `few / many`），列表用 `Intl.ListFormat`。
4. **键按语义命名**，不按中文原文：用 `inbox.emptyTitle`，不用 `noPendingItems`。
5. **不翻译用户内容**：工作标题、目标、消息、应用显示名、项目名原样显示。
6. **枚举在客户端映射**：运行状态、交付状态、事件类型等一律由枚举查词典，未知枚举原样显示并归入“技术详情”。
7. **服务端消息**：错误先显示本地化的一句话，原始 `code / detail` 进“技术详情”。中期把接口错误统一成 `code + params`，由客户端本地化。
8. **界面语言与内容语言分开**：智能体输出语言（“我的习惯”里的 `output.locale`）是业务设置，与界面语言互不影响；混排的用户内容加 `lang` 属性，保证屏幕阅读器发音和字体回退正确。

### 6.4 格式化

| 项 | 做法 |
|---|---|
| 日期时间 | `Intl.DateTimeFormat(locale)`，12/24 小时制随语言；时间点用用户时区，纯日期值不换算 |
| 相对时间 | `Intl.RelativeTimeFormat(locale)`；“今天/昨天”的划分按用户本地日界 |
| 数字、字节 | `Intl.NumberFormat(locale)`；小数点和千分位随语言 |
| 搜索与排序 | 先做 NFKC 规范化再匹配；排序用 `Intl.Collator(locale, { sensitivity: 'base' })`；中日韩按子串匹配 |
| 文档 | `<html lang>` 由宿主维护；新增 CSS 用逻辑属性（`margin-inline-start`、`inset-inline-end`），为以后的双向语言留余地 |

### 6.5 版面对文字长度不敏感

- 英文比中文宽约 1.6–2.2 倍（实测：`历史会话` → `Conversations`），德文、俄文更长。版式按“文字会变长”设计：定宽容器里不放文字（图标轨只用图标 + 提示）；按钮用 `min-width` 加自动宽度；列表行用省略号并带完整标题的悬停提示；面包屑可折叠中间段。
- 字体栈按语言回退：`system-ui, -apple-system, "Segoe UI", Roboto, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。中日韩正文行高 1.5，拉丁 1.4。
- 可翻译文字不用全大写和字距拉伸（对中文无效）；标题不要负字距。
- 验证时用伪语言（重音、加长）跑一遍，能直接暴露硬编码和溢出。

### 6.6 语言覆盖的交付顺序

| 批次 | 范围 |
|---|---|
| 首发 | 中文、英文全量（宿主要求的两种基线） |
| 第二批 | 日文、葡（巴西）词典；西/法/德/俄先用英文回退 |
| 持续 | 每新增一个键，测试要求所有语言文件键集合一致、占位符一致 |

### 6.7 自动检查

- 键集合一致：每种语言的键与占位符与 `en` 完全一致。
- 覆盖率：源码中引用的每个键在词典里存在；词典里没有未使用的键。
- 硬编码扫描（6.3 第 1 条）。
- 上游自带的 `check:i18n` 会拒绝语言资源里的零宽空格和 BOM，词典文件沿用这条规则。

## 7. 工程重构方案

### 7.1 模块拆分

`WorkbenchPage.tsx`（5,274 行、39 个组件）按功能拆，先抽能力再切视图，不在原文件里再叠一套并行实现：

```
src/client/
  app/          外壳、路由（ChatTarget ↔ URL）、侧栏装配、快捷键
```

### 7.2 数据层

- 删除“V5 direct-workbench alignment”覆盖块以及所有对同一选择器的二次覆盖，回到一份断点规则（§5.3）。这一步同时修掉 P0-1、P0-2、P0-4。
