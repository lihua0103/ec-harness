# DSH 企业级知识库体系设计

状态：设计稿 v0.1 · 2026-11-20。范围：本平台发布和治理的全部 DSH 插件；不是 DVP 专项，不要求上游或第三方未纳管插件自动拥有业务知识。本稿补齐[现有知识架构](ENTERPRISE-KNOWLEDGE-ARCHITECTURE.md)的逐插件智能体、运行接线和发布验收设计，不另立第二套知识存储或状态机。下文能力除明确标为现状外均为目标。

## 1. 总体决策：统一治理，逐插件拥有知识智能体

**一个纳管插件身份对应一个可发现、可版本化、可独立验收的知识智能体定义。** 智能体不仅是命名空间：它能在授权范围检索、回答并引用依据、分析反馈、提出知识候选和请求领域验证。多个 PluginPackage 若只是同一个插件的 Host/Client 构件，不为构件另造身份；一个 Application 可组合多个插件能力，应用首页不是智能体身份。独立纯库不算可装配插件，其知识由使用方插件消费，库维护者负责原始文档和版本。

共享 `platform-knowledge` 作为知识服务及唯一状态写入主体（按部署数据单元）；DSH Host 插件通过公开服务注入消费，复用 DSH 原生 Harness、工具和 Skill。工作台是统一入口，不另建聊天内核、不要求每插件启动常驻 Agent、独立数据库或模型实例。模型由平台已有部署/数据策略选择，不进入知识发布权威。技术基线：已核对锁定 DSH `0.2.2-rc.1` 源码 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的 [服务与依赖](../upstream/deepseek-harness-git/docs/user/develop/framework/service.md)；以下企业合同不是上游 API。

| 责任主体 | 负责 | 不负责 |
|---|---|---|
| 平台知识服务 | 目录、授权后检索、修订与快照、候选、验证请求/回执、审计与撤回 | 领域规则匹配、临床批准 |
| 插件知识智能体与维护者 | 主题、适用性、证据解释、反馈映射、候选提炼、领域验证器与黄金集 | 派生自己的授权、提交激活回执、重写 Agent 循环 |
| 控制面与执行环境 | 可信身份、Run/工件/事件真源、隔离执行、可信证据通道 | 解析领域原文、写第二个知识库 |
| 领域/治理负责人 | 项目裁定、企业标准发布、跨域提升、撤回与影响处置 | 用一次模型判断代替领域证据 |

## 2. 知识分层与权威来源

| 对象 | 权威来源 | 使用规则 |
|---|---|---|
| 企业标准和受控 SOP | 原有文控系统或受控发布制品 | 索引授权版本与定位；区分生效日期、地区和语言，不由智能体改写标准 |
| 参考语料 | 插件文档、公开资料、公司批准语料 | 授权摄取；分片引用原文，不把命中文段视为已验证方法 |
| 已验证方法与候选 | `platform-knowledge` | `shared / plugin / project` 为适用范围，不替代组织、区域、项目授权；`shared` 不等于全球可读可写 |
| 项目裁定 | 适当授权的项目责任人及记录 | 仅对指定项目、输入版本与用途有效；不是公共方法 |
| 执行事实与真实资料 | DSH Session、控制面及授权数据环境 | 记录受控引用、digest 与必要元数据，不镜像正文、对话或逐条临床差异 |

按主题与声明的适用性解析冲突，不靠相似度决定优先级：强制标准仍有约束力；有效项目裁定在其授权范围内解释项目情形；已验证插件和共享方法都是建议。范围不匹配或来源冲突不能无提示合并。真实临床文档和逐条对照留在授权本地环境；模型只能获得允许外显的汇总统计和类别计数，禁止原文、可回溯个体的抽样、映射表和完整差异报告进入上下文。对候选与日志也实施同样边界。普通读取仍沿用平台授权，不新增按文件名/类别兜底拒读或逐次审批。

## 3. 插件接入合同与工作台体验

在现有 `knowledge/manifest.json` 基础上演进，避免第二份主题目录。目标字段（非现行 schema）：插件身份与智能体版本、负责人、主题与工具映射、批准语料及作用域、反馈事件类型与证据投影版本、验证器与黄金集引用、无方法的局部能力及原因。制品发布锁定智能体定义、插件版本和验证器；停用清理注册，不抹掉历史记录。注册/撤回权限由平台管理，不接受模型自报身份。禁止用 `noMethodKnowledge` 让整个插件跳过接入；技术插件可用运维、安全边界、使用契约与故障诊断验收。

工作台复用原生会话：从当前插件/Run 进入「知识依据」，展示来源、适用条件、修订与验证状态，可追查本次实际返回的知识；独立治理区处理候选队列、冲突、撤回及受影响 Run。不把候选混在默认答案里，不把未绑定、未命中、降级、失效混为同一状态。跨插件发现只展示已授权目录和证据；跨插件调用走已声明依赖或平台代理，不直接相互 import。

## 4. 端到端链路与降级

- **创建 Run**：授权层从已验证 Principal、应用发布和 Run 派生组织/区域/项目/插件范围。提交可重放的快照引用、修订集合和摘要；摘要仅作完整性证据。普通 Agent 工具参数只能缩小查询，不能扩大授权。
- **检索与引用**：先做身份/区域/范围过滤，再在固定集合中做主题、关键词、词表和语言召回。记录「集合包含」「本次实际返回」「答案有引用」，不以返回推定模型采纳。原 Run 恢复仍依同一快照；撤权或撤回后保留原审计事实，不再返回失效正文，标明不可重取并允许有权限时以新 Run 重评，不静默替换。
- **观察与提炼**：合约化的运行/QC/复核事件写入控制面，使用现有事件/Outbox 能力承载重复投递；可信消费者查验来源，按发布版本投影最小必要证据。以来源事件、贡献者和投影版本形成去重键。知识智能体可提出候选，也可说明无可复用结论；运行成功不自动生成知识，候选失败不改写业务 Run 状态。服务不可用时如实标记知识不可用或候选待处理，不转查未授权库。
- **验证与激活**：复用[跨进程验证合同](PLATFORM-KNOWLEDGE-VALIDATION-CONTRACT.md)的请求/回执、版本绑定和唯一提交方。批准的验证器测试适用前提、正反例和边界；覆盖不足、超时或回执未知不激活。技术 `ACTIVE` 不等于业务批准。跨项目提升生成新的去项目化候选，重新验证并由有权人员批准；不是修改原条目的 scope。
- **反馈是否有效**：固定业务输入、配置、知识快照、评测器与模型配置，对照开启/关闭对应知识；沉淀样本与留出样本分开。记录运行版本与评测结果，不把历史定稿、模型自评分、点击量或入库数量当成质量结论。

## 5. 套到当前平台

| 当前接入面 | 对应知识域及首个验收例（目标，不是上线声明） |
|---|---|
| `dm-dvp` | 模板/规则；本地语义对比的漏项、误增、等价及未决率，原文不外送 |
| `dm-listing` | 业务条目生成和交付 QC；关键异常漏报、误报及结果可复现，沿用既定四类业务入口 |
| `dm-participants` | 档案语义和数据装配；字段来源、映射正确性与跨项目不串数据 |
| `dm-viz` | 配置、指标口径和渲染诊断；数据与图形绑定、配置可复现，不把某项目配置变成默认 |
| 平台 Host/Client | 工作台操作、运行恢复、发布、身份与知识治理等技术知识；用授予/撤销、故障恢复、错误指引等夹具验收 |

四个业务插件当前工作树均有 `application.json` 与知识 manifest；平台公共包须从实际装配/发布清单逐个判定为插件或纯库，不以目录数冒充覆盖率。现有知识服务已有 FTS、候选/验证、事件候选入口、运行摘要和黄金集等基础；**声明或单测通过不证明真实宿主接入**。本轮源码发现：通用入口从工具参数组装范围、控制面快照主要绑定摘要、DVP 检索直接读取活库，且未找到运行/QC 消费者调用候选事件入口。对应代码见 [`cordis.ts`](../packages/platform-knowledge/src/cordis.ts#L37)、[控制面接线](../packages/platform-control/src/cordis.ts#L79)、[DVP 检索](../plugins/dm-dvp/src/index.ts#L123)、[事件候选](../packages/platform-knowledge/src/service.ts#L155)。不据此推定线上已发生越权。

2026-11-20 更新：上述四项已按[插件知识智能体合同](KNOWLEDGE-AGENT-CONTRACT.md)实现修正——范围由部署声明派生且工具失败关闭、快照携带实际修订集合并支持固定集合检索、DVP 支持快照检索并标注未绑定、控制面把失败/未知运行投影为待分析事件；真实宿主与领域证据仍待补，不构成验收。

## 6. 实施次序与可复跑验收

| 阶段 | 交付内容 | 放行证据 |
|---|---|---|
| A · 可信底座 | 统一身份派生与可见性；可重放快照及授权后检索；受控路由和使用记录 | 合成双组织/双项目/跨区域夹具无串读；实体修订变更不漂移；撤权/撤回失败关闭；来源引用可核对 |
| B · 逐插件协议 | 智能体注册与版本锁定；事件投影、候选和验证接线；目录与工作台投影 | 一个业务插件和一个平台插件真实宿主双样本走通；重复事件/回执无重复状态变化；无证据或验证失败不激活 |
| C · 全平台覆盖 | 以装配清单为分母逐插件登记负责人、版本、证据及黄金集；升级发布门禁 | 所有纳管插件 100% 有定义、可调用、可回归；缺失项阻断相应发布。新插件不需要改平台领域分支 |
| D · 规模和运营 | 首期沿用现有 SQLite/FTS，权限、语言、噪声隔离后测负载；按实测演进中心存储/地区单元 | 双语与缩写召回、未命中诚实、峰值 p95、写入积压、备份恢复、区域驻留与删除演练；目标由容量/合规责任人按真实部署确认 |

迁移使用单一写者、版本映射、停写/切换、备份摘要核对与恢复演练；不以常态双写或兼容旁路绕过新授权。不在缺乏召回或容量证据时先采购向量库，也不以测试环境的性能或单区 SQL 过滤宣布国际部署就绪。发布前按[开发规范](DSH-PLUGIN-DEVELOPMENT-STANDARD.md)运行规范和全仓门禁；真实宿主、领域回归和部署验收分别留证。
