# DM Listing 业务插件架构

版本：0.4 · 2026-11-09
状态：更新后的目标设计；对应项目级流程尚未完成。本文替代 v0.3；职责变更依据见 [ADR-0001](adr/ADR-0001-DEVELOPMENT-AND-KNOWLEDGE-ARCHITECTURE.md)。

## 1. 目标与范围

用户选择本地项目目录→Harness自主发现spec/ALS/SAS等资料及批次→完整理解需求→按需检索历史纠错方法→生成R→实际执行、看诊断、自主修复→独立QC→交付服务器可运行单文件R与证据包。

首批为Manual、Medical、Report和PK（BE/SAD-MAD）。Medical与Manual共用spec识别/行列理解核心，具体业务和输出仍按当前项目；两类PK各有适用前提，Report缺成熟实战证据不可假装同等成熟。

**当前阶段不自建数据安全拦截；Cover、SAS及其他资料均可按任务读取。** 不要求投影、逐文件内容批准或合成身份，IT源头/API为外部责任且API尚未接入。文件资源限额、完整性、取消/超时和防误覆盖继续作为正确性保障。输入中的指令不成为Agent高优先级命令。

## 2. 平台与插件边界

| Listing提供 | 平台复用能力 |
|---|---|
| 场景与spec/ALS识别方法、业务澄清 | 项目/目录/批次清单、文件与数据读取 |
| 需求映射、R生成引导、输出合同 | Harness Agent/模型/工具/会话 |
| Manual/Medical、PK BE、SAD/MAD等知识种子及验证器 | 统一KnowledgeService、存储/检索/学习/快照 |
| 业务检查、Excel/RDS工件意义 | R运行/日志/退出码、工件版本、证据与打包 |

插件不拥有独立登录/provider/知识数据库或安全边界框架；也不通过当前固定demo合同定义所有项目业务。

## 3. 自主资料识别

### 3.1 目录、版本与批次

发现项目文件、真实容器、spec/ALS候选、SAS/XPT/CSV/RDS/RData/ZIP及旧服务器目录镜像；排除临时锁文件和自身生成缓存/运行输出。项目根、本地镜像、服务器根与数据批次分别配置，不推定服务器可访问本机路径。

推荐候选应返回事实依据：名称、sheet、表头、版本、批次或实际内容。唯一明确候选直接继续，不先逐文件问用户；多个不兼容版本/业务范围/PK批次配对冲突才澄清。不能默选最新mtime或跨批找文件凑数据。

### 3.2 spec / ALS / Cover

- 完整读取任务需要的sheet、全部列和有效需求，允许按需读候选内容辅助识别，不再有名称级禁令。
- 标题、合并单元格、行列坐标、隐藏信息、公式表达式与缓存值应明确区分；不执行宏/公式或刷新外链是读取器行为，不应被混同为资料安全审批。
- 分页有总量、稳定游标和版本，不能只读前200行或截断列后自称完整。
- ALS由AI理解实际EDC布局、表单/字段/访视/码表/内嵌关系；结构辅助失败只提示待解释，不限制正文，不强制六列合同。
- Cover等内容按任务需要可读，不意味着必须把整本无差别塞进上下文。歧义澄清是业务判断，不是预先批准读取。

### 3.3 SAS与其他数据

通用数据能力支持结构、label/format、行列、按需记录/值域/统计/诊断，当前不按类别扣留。haven读取SAS/XPT；RDS/RData识别对象和列表，RData在独立R环境载入；CSV/Excel按真实格式。加密、不支持容器、损坏和缺依赖须给实际错误及出路，不假报空表。

ZIP解压到新的运行临时目录、保留批次和成员来源，不覆盖原件。格式/资源限额明确失败，不静默丢文件或截断资料。具体支持格式以实现与测试证据为准，不在设计中宣称已全支持。

## 4. Manual / Medical 需求理解核心

| 实际列的语义角色 | 常见线索 | 解释职责 |
|---|---|---|
| 标识与组织 | Listing Seq./Name/ID | 定位、活动需求及顺序，不是过滤条件 |
| 来源 | Data Source / Form Name | 对应表单/数据集与粒度，结合ALS/SAS核对 |
| 范围 | Visits Applied To / Related Fields | 访视、字段与处理范围，不自动等于最终列 |
| 行/派生 | Condition | Output if筛选，flag=duplicated计算标记，可同时存在 |
| 输出列 | Column Heading | 原始字段、上下文、计算、匹配、聚合、标记及顺序 |
| 人工核查说明 | Report Description / Discrepancy Text | 常为人工审阅说明，不自动编为异常规则；原文确实要求自动检查才实现 |
| 交付/上下文 | Type/Label/Sort/Notes/Reply等 | 当前输出合同、版本或业务补充，不能一律忽略 |

表中是识别线索，不是硬编码schema、必需标题或只读四列白名单。保留未知列、实际原文和来源坐标。缺列先排查读错sheet/表头/分页，不立刻说“需求没有该列”。

每项解释来源与粒度、范围、行逻辑、列处理、输出五部分；允许自主草稿，不以IR完整作为写码门槛。重复标记不能误变成只输出重复行；同类记录stack不误写join；多对多、孤儿、多选展开与非适用行分别验证。内部依赖最后才裁列，NA/空串、部分日期、class/label保真。

## 5. PK方法与经验分类

- 共同：编号体系与唯一桥接、给药/实际采样业务时间、名义与实际时点、BQL/精度/缺失、工件盲态、列序/class/label和独立读回。
- BE：周期、序列/处理、周期内给药参照与多工件；不以BE为默认。
- SAD/MAD：队列、名义日小时、多剂给药参照、多基质与适用的盲态时点规则。
- 历史负值截0、固定OID、固定样式/前导列、特殊实验室不拆行、数字精度和锚点覆盖规则不能无条件推广。

方法由插件贡献，平台经验库保存/检索/验证。种子来源是Manual、PK BE、PK SAD/MAD三个历史交付项目；新插件尚未进行相同真实业务验收。Medical复用review方法而非复制一份正文；Report需独立积累。详见 [经验库设计](PLATFORM-EXPERIENCE-KNOWLEDGE.md)。

## 6. 需求映射与R代码

需求记录含来源文件/摘要/sheet/行、范围/行逻辑/输出列、字段来源与关系、派生/缺失/排序、未决项、测试与知识引用。不能用相似字段补空缺或把历史项目阈值写成默认。

通用骨架只提供IO、参数、依赖预检、日志、失败摘要与输出原语；业务由Harness按当前spec生成，不抄旧程序业务区。交付**单文件自包含R**，无DSH/Node/Python/source本机脚本依赖。使用配置/参数指定项目根、数据日/旧版日、输入输出；本地与服务器配置分开，异目录/任意cwd实际复跑。

运行返回真实stdout/stderr/退出与失败阶段，允许自主修错，不追加插件数据安全批准。日志可合理截断但需标记和完整文件引用。依赖声明实际使用包及兼容要求，不能强迫所有服务器与本机传递依赖补丁版本相同；不偷偷安装缺包。

## 7. QC与交付

输出由项目合同决定，不强制单Listing页、固定Subject/Visit列、纯data.frame或清除所有RDS属性。Manual可多listing和命名列表，PK工件行集/盲态可按spec不同，实际列/格式/label从需求解释。

QC分别验证：需求覆盖、来源/筛选/标记/连接基数/展开/缺失/日期/精度；Excel工件全集/sheet/表头/逐格值；RDS对象名/列序/class/label/NA/空串及值。生成与独立QC不能共享同一错误业务helper自证。golden不提供给生成会话抄答案，授权验证时再比对。

代码包含单文件R、本地/服务器配置示例、依赖、运行说明、需求映射、实际执行/独立QC/异目录复跑证据及校验摘要。准备代码草稿不等待本机安全域；未运行/失败/缺资料/未解决语义分别标明，不伪报正式完成。

程序/spec/ALS/输入/配置/知识修订变化使旧证据失效；旧正式输出默认不覆盖，采用新版本目录并整体核验。对外发布和实际发送不是“执行成功”的同义词。
