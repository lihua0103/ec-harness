# 企业级评审：按大型 AI 企业标准审当前工作台与改造方案

日期：2026-11-17 · 类型：批判性评审 · 状态：**评审意见，不是开发批准或企业验收**。
评审对象：当前运行面 `packages/platform-workbench` + `platform-control` 平台 + 我自己的 [改造方案](WORKBENCH-UX-RENOVATION-PLAN-2026-11-17.md)。
基准：你们自己的 [独立审查 §4「大型企业与国际化」](clinical-workbench-review/03-enterprise-architecture-and-ux-audit.md) + [需求 FR-19–29](CLINICAL-WORKBENCH-REQUIREMENTS.md) + [多插件架构 §14](ENTERPRISE-MULTI-PLUGIN-ARCHITECTURE.md)，叠加通用大型 AI 平台标准（治理/可观测/质量/成本/协作）。

## 0. 评审立场

用户要求"按大型 AI 企业来评审"。这意味着**不降低标准去迁就"单操作者首期"的冻结范围**。冻结范围是合理的工程排序，但它不是企业就绪的借口。本评审同时审两件事：当前系统离大型 AI 企业有多远；以及我上一份方案是否够格——结论是**它把企业命门往后放了，框定窄了**。

证据：通读插件源码 + 今日真实 E2E 截图 + 后端能力/路由核对 + 需求/架构。非真实员工实验、非渗透测试、非合规审计。

## 1. 总裁定

**当前系统不是大型 AI 企业平台，是"治理基座相当扎实的单操作者工程原型 + 一层原型级产品 UI"。** 离企业就绪（L3）有系统性差距，差距的一半在**平台**（身份/隔离/部署权威/质量/成本），不在 UI。

成熟度阶梯：**L0 缺失 · L1 原型 · L2 单点可用 · L3 企业就绪 · L4 规模化治理**。

| 维度 | 当前 | 一句话裁定 |
|---|---|---|
| 身份与访问 | **L1** | 固定本地操作者（`api-cli.ts:143`），identity 库未接 UI 路径，无 SSO/项目 ACL 落地 |
| 隔离与多租户 | **L0** | 单进程单操作者，无组织/项目隔离域；审查说"首期单企业也要明确隔离域" |
| 审计与不可抵赖 | 后端 L2 / UI **L0** | SHA-256 链+导出已有（`service.ts:1432`），UI 无查看器；无电子签名/保留演练 |
| 数据治理/驻留 | **L1** | 区域/外发/盲态有原则无落地；绝对路径外泄 |
| 模型治理 | **L1** | 目录+健康显示，无审批/区域/预算/辅助调用计量 |
| 成本与配额 | **L0** | 无每运行 token/成本采集，无预算执行 |
| 可观测/运营 | 后端 L2 / UI **L0** | metrics/doctor 已有，UI 仅"total 4·queued 0"工程计数；无 SLO/告警/runbook |
| 可靠性/恢复 | **L2** | 租约/outbox/备份函数已有；无恢复演练、无中心权威、两套默认库 |
| 企业 AI 质量 | **L0** | 无应用评测代表集/独立预期/模型回归/线上问题闭环 |
| 智能体目录/编排 | **L1** | 只读应用网格，无能力详情/评测/编排；视图贡献机制未行使 |
| 知识/RAG | 后端 L2 / UI **L0** | 完整知识服务但**无 HTTP 路由、无 UI** |
| 任务/交付体验 | **L1** | 聊天/表单优先；无基线/三指针/换批/差异/交付 |
| 协作 | **L1** | 仅复核卡；无共享/分派/转交/评论/权限化搜索通知 |
| 国际化 | **L1** | 部分 i18n，大量硬编码中文，无 RTL/术语表 |
| 无障碍 | **L2** | 标签/焦点/对比不错；无 skip link/快捷键/读屏回归 |
| 平台扩展 | **L2** | 接入合同已定义，UI 未行使应用视图贡献 |
| 部署权威 | **L1** | 本地 SQLite 两套默认库，会话本地，无中心权威 |

**要公平地说**：后端治理基座（审计链、审批/回滚、租约/outbox、备份/恢复函数、知识验证、子进程执行器、身份策略库）是**真资产**，不是 PPT。问题不是"没有"，是"没接成企业能用的样子"。这决定了改造是"接线+补口+重构"，不是推倒重来。

## 2. 最锋利的八条（大型 AI 企业会先问的）

**① "谁在操作、凭什么权限、和谁隔离？"——今天答案是"同一个本地操作者"。** 整个系统跑在固定本地 principal 上，本地 SQLite，identity 库存在但没接到 UI 请求路径，真实 SSO 明确未实现（身份合同 §6）。大型企业的第一个问题就答不上。这是 L0/L1，不是 P3。

**② 临床受监管域的命门是审计/溯源/复核/签名，我却把它放 P2。** GxP/Part 11 场景下，不可抵赖与证据链是**核心功能**不是"治理增强"。后端有审计链和复核，但 UI 看不到审计、没有电子签名、没有保留/恢复演练。对临床企业，这些必须前置到 E0/E1。

**③ 没有"企业 AI 质量"闭环——这是大型 AI 企业和玩具的分水岭。** 没有每个应用的评测代表集、独立预期输出、模型/插件版本回归、线上问题闭环。审查 §4 明确点了这条。大型企业**不会**在没有 eval/回归的情况下上线智能体。我上一份方案完全漏了它。

**④ 成本与模型治理缺位。** 无每运行 token/成本采集，无预算/配额执行，无模型审批/区域/辅助调用计量。企业 AI = 成本可问责 + 模型可治理。后端有 metrics 但没有每运行成本；模型健康显示有了，治理没有。

**⑤ 可观测是"工程计数"不是"运营"。** 设置页显示"total 4·queued 0·running 0·terminal 4"。企业运营要 SLO、p95 时延、错误率、告警、值班、故障 runbook。后端 metrics/doctor 都有，UI 一个没接，更没有告警/事件路径。

**⑥ 协作是"复核卡"不是"团队平台"。** 无共享/分派/转交/评论，权限没覆盖搜索/通知/导出。企业 = 受治理的团队协作者。需求 FR-13/SC-06 要求的人员交接、离职转交、并发复核冲突，UI 都没有。

**⑦ 部署权威不清。** 两套默认库（`control.sqlite` vs `workbench.sqlite`），原生会话存本地节点，无中心权威、无统一备份恢复。方案文档自己推荐"中心权威控制面"。企业不能把"本地 SQLite 放共享盘"当 HA。

**⑧ 产品体验：聊天优先 + 基础设施外泄 + 无任务模型。** 这条我上一份方案讲透了，但它只是企业差距的**一条**，不是全部。把 UI 修好 ≠ 企业就绪。

## 3. 对我自己方案的批判

上一份 [改造方案](WORKBENCH-UX-RENOVATION-PLAN-2026-11-17.md) 诊断对了 UX，但作为"大型 AI 企业"评审，它有五个不足：

1. **框定窄了。** 标题是"UX 改造"，但企业差距的一半在平台（身份/隔离/部署权威/质量/成本）。只改 UI 会产出一个"好看但仍不是企业平台"的东西。
2. **治理放 P2 是错的。** 对临床受监管域，审计/溯源/复核/交付应前置，不是体验做完再补。
3. **完全漏了企业 AI 质量/评测。** 没有 eval 代表集、模型回归、线上问题闭环——这是审查 §4 明确的企业维度。
4. **对身份/隔离太 deferential。** 我用"本期不做 SSO"一笔带过，但审查说"首期单企业也要明确隔离域"。即使不接真实 SSO，也必须把 identity 库接到 UI 路径、明确隔离域、让授权在搜索/下载/事件流上真正生效。
5. **漏了部署权威与成本治理。** 两库统一、中心权威、备份恢复演练、每运行成本采集——这些是企业地基，不是 P3 点缀。

一句话：**我上一份是"产品体验改造方案"，用户要的是"企业级平台评审"。标准抬高后，方案要重写成"平台可信基座 + 产品体验"双线，而不是 UI 单线。**

## 4. 企业级修订路线（每阶段都带治理，不降标准但排序）

可行性前提：DSH 锁定上游、不建第二套引擎、模块化单体、受监管临床域。这些是真约束——**不降标准，但按依赖与风险排序**，并明确"在 X 之前不得宣称企业就绪"。

### E0 · 可信基座止血（地基，必须先做）
- 把 identity 库接到 UI 请求路径；明确单企业隔离域；授权在搜索/下载/事件流真正生效（不只是页面显隐）。
- 统一部署权威（收敛两套默认库）；会话存储位置与恢复限制如实标识。
- **审计/溯源前置**：接 `audit/export`，UI 可查 actor/action/target/correlation；运行事件历史+SSE 替换轮询。
- 修三缺陷 + 去基础设施外泄（保留专家诊断抽屉）+ 首页续作优先 + 深链接（不扩大授权）。
- 出口：每个动作有可查审计；"谁在操作"有真实答案；员工面不见原始路径/ID。
- **不得宣称**：企业 SSO/多租户/合规签名（仍未实现）。

### E1 · 任务/交付 + 临床证据闭环（产品核心 + 命门）
- 工作详情→任务工作台（基线+三指针+分页签，聊天降辅助）；换批次重跑闭环（接已有 `POST …/input-baselines`）。
- 复核/交付分离 + 交付包 + 版本链/替代/撤回；差异/影响视图（应用贡献业务键）。
- 应用贡献结果视图（Listing/DVP 声明表格/代码/证据，平台不硬编码）。
- 出口：同一工作跨两批两次交付，证据链可查，旧交付不覆盖；复核绑定确切版本。

### E2 · 企业 AI 质量 + 模型/成本治理（大型 AI 企业的分水岭）
- 每应用评测代表集 + 独立预期 + 失败分类；模型/插件版本回归比较；受控发布。
- 每运行 token/成本采集（后端先行）+ 预算/配额执行 + 模型审批/区域/辅助调用计量。
- 出口：模型变更可回归、成本可问责、超预算可拦截；不以模型自评代替 QC。

### E3 · 运营 + 协作（企业可运维、可协作）
- SLO/p95/错误率 + 告警 + doctor/健康面板 + 备份恢复**演练** + 故障 runbook。
- 团队共享/分派/转交/评论；权限覆盖搜索/通知/导出；统一待办 inbox（澄清/授权/故障/复核/交接）。
- 出口：跨项目访问拒绝、并发不串资料、离职转交不删历史、恢复实测通过。

### E4 · 规模化 + 国际化 + 编排（按 IT 合同与真实负载）
- 真实 SSO/OIDC + 多租户/组织隔离 + 中心 Worker 隔离（容器/VM 实测）。
- 服务端过滤/游标 + 完整 i18n/术语表/RTL + WCAG 2.2 AA 读屏回归。
- 声明式跨应用编排（输入/输出/授权类型），不做通用低代码。
- 出口：多地区驻留、撤权即时、规模负载实测、无障碍认证。

## 5. 企业就绪门禁（不得提前宣称）

- E0–E1 完成 ≠ 企业就绪：身份/隔离/质量/成本未闭合前，不得称"大型企业平台/生产可用"。
- 真实 SSO、容器隔离、电子签名、合规（GxP/Part 11）是**独立验收**，由 IT/QA 按用途判定，不被 UI 改造冒充。
- 工程门禁（verify-all）只证明实际执行的检查；企业就绪要真实角色评审 + 部署验收 + 恢复演练。

## 6. 裁定

**架构方向保留；后端基座是资产；但当前是单操作者工程原型，不是大型 AI 企业平台。** 我上一份方案够"产品体验改造"，不够"企业级"。按本评审，改造应升级为**平台可信基座 + 产品体验双线**，治理/质量/成本前置，身份/隔离即使不接 SSO 也要先落地隔离域与授权生效。先做 E0（地基止血）+ E1（任务/证据闭环），E2 质量与成本治理紧随——这才是大型 AI 企业的及格线。
