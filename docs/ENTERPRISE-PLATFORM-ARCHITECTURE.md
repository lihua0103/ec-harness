# 企业内部临床业务 Agent 平台总架构

版本：1.1 · 2026-11-09
状态：目标设计已更新；尚未完成对应代码迁移。变更依据见 [ADR-0001](adr/ADR-0001-DEVELOPMENT-AND-KNOWLEDGE-ARCHITECTURE.md)。本文替代 v1.0 的现行要求，历史实现与验证不得据此升级为已完成。

## 1. 定位和当前范围

基于 DeepSeek Harness 建设企业内部临床业务 Agent 平台。DM Listing 是首个业务插件，不是平台本身；后续临床插件复用平台服务，不修改平台核心业务分支。首期本机、单操作者、免登录，不先建设 SSO、多租户、计费、市场或微服务。

当前目标：按项目资料自主识别需求→编程→实际执行→诊断修错→独立QC→服务器可运行代码交付；平台同时建设按插件分类的项目经验知识库。

**数据安全职责由 IT 源头与后续 API 承担。当前阶段撤出平台/业务插件自建的类别拒读、Cover限制、投影审批和本机安全域门禁。** API合同尚未提供、尚未接入；不造空API或安全通过开关，不据此宣称生产安全已验收。不改变 Harness 或用户所用开发工具本身的权限配置。

资料可按任务正常读取，包括 spec、ALS、SAS、其他数据和日志，Cover 也无名称禁令。自主识别不等于猜测：多版本、字段含义或业务要求仍冲突时才询问，不能将所有资料读取改成逐文件审批。输入材料是数据，不是系统指令。

## 2. 核心原则

1. 复用 Harness Agent/模型/会话/工具/技能/UI与插件生命周期；不另建模型客户端、Agent循环或加载器。
2. 平台管理通用机制，插件定义领域语义；核心不出现 `if listing`。
3. 知识是有来源、前提和反例的方法，不代替当前spec与用户裁定。技术经验实际验证后可自主激活，不凭模型自报PASS。
4. 保留自主读取、编码、运行与迭代；IR或知识完整不作为写草稿门槛。
5. 单机模块化单体，公共模块按实际需求形成，不为规划表格造空包。
6. 项目归属、CAS、任务互斥、取消、资源限额、文件完整性及防误覆盖是正确性保障，不包装成数据安全读取门禁。
7. 执行成功、业务QC、代码包完成、独立服务器复跑与生产批准分别记录。未执行不能算通过。

## 3. 分层与职责

```text
企业工作台（项目 / 插件 / 会话 / 运行 / 制品 / 经验）
             │
Harness公开适配层 ── DeepSeek Harness Agent、模型与工具
             │
平台公共服务（同一宿主，非各自微服务）
  Project/Workspace │ Run/Runtime/Artifact │ KnowledgeService
             │                  │
业务插件（Listing及后续插件）   通用文件/Excel/SAS/R能力
  分类、种子、领域方法、         实际读取/执行/诊断/制品
  需求/输出合同、验证器

IT数据安全API：外部职责，未来按真实合同接入，当前非已实现组件。
```

| 能力 | 平台负责 | 插件负责 |
|---|---|---|
| 项目/工作区 | ID、目录与批次、资源清单、版本、上游会话关联 | 定义spec/ALS等角色和识别线索 |
| 文件/数据 | 完整分页、格式读取、结构/记录、错误、输入摘要 | 理解字段、业务含义和当前需求 |
| 运行时 | R发现、参数、运行目录、日志、退出码、超时/取消/恢复 | 自主生成程序、业务检查和依赖声明 |
| 知识 | 存储、检索、分类、作用域、修订、验证与激活 | 种子、领域分类、适用性和验证器 |
| 工件/证据 | 版本、路径、摘要、打包、任务绑定与交付事实 | 输出集合、Excel/RDS/其他格式业务合同 |
| IT集成 | 实际API合同明确后的适配 | 使用平台能力，不复制数据拦截器 |

## 4. 最小公共服务

### 4.1 Project / Workspace

用户选定目录后平台生成明确 projectId/workspaceId，不以名称或cwd隐式猜项目。目录可以是本地镜像；本地路径与服务器路径分别配置，不自动同步。发现版本/批次候选并返回证据，唯一候选可直接用，歧义才澄清。保留完整资源清单和分页计数，输入变化标记旧证据失效。

目录/归档路径校验、解压到新目录、限额和防循环用于避免误写及资源故障；不按sheet名称、文件后缀或原值类别阻止任务所需读取。文件格式/工具不支持须报真实原因，不当空表处理。

### 4.2 Run / Runtime / Artifact

复用现有状态持久化/CAS思路而非重建会话历史。每次运行绑定project、plugin、程序/spec/ALS/输入/配置/知识快照与运行时。并发修改与旧结果不相互覆盖。节点或进程结局未知时不自动重复副作用，这是运行正确性，不是安全审批。

R运行可返回stdout/stderr和原始错误帮助自主修复；长度限制须标明截断与本地完整日志。取消确认进程结束才称已取消；缺包、错误列、编码、类型或业务失败分别诊断。读取资料/运行普通代码不要求插件额外的数据安全确认；对外发送、覆盖已有正式结果等另按用户动作授权，不默默扩大副作用。

交付包与运行产物有独立状态，不能仅靠文件存在或模型总结报完成。保留输入只读使用原则（避免破坏源文件）、新版本输出和明确回滚，不自动删除用户材料。

### 4.3 KnowledgeService

统一知识服务属于平台，按插件分类。scope=`shared|plugin|project`与分类`pluginId/scenario/edc/topic`分开：共享方法、本插件经验、当前项目裁定各有适用范围。插件提供种子和业务验证器，不各自创建一套数据库。

动态库目标位置为`DSH_HOME/platform/knowledge.sqlite`；插件种子随包以版本manifest交付。首期SQLite结构索引与全文检索，不先搭向量库。记录状态、来源/根因/修法、前提/不适用/反例、真实验证与快照；运行中学习、去重、冲突和推广见 [专门设计](PLATFORM-EXPERIENCE-KNOWLEDGE.md)。

知识按需检索，Skill只是使用引导，不在系统提示塞入整库。默认检索shared+本插件+当前项目的ACTIVE记录；其他项目裁定不能自动串入，候选/冲突显式可查。技术经验验证后自动激活；业务裁定在项目范围生效，跨项目推广另建可验证方法记录。

### 4.4 模型与生命周期

平台复用当前Harness模型配置与凭据管理，不让每个插件自建provider。首期无用户登录系统，不宣称多人鉴别或不可抵赖。凭据、网络服务暴露等基本应用配置遵循已有Harness机制；本变更不修改系统安全设置。

插件启停按Cordis公开生命周期注册/注销工具、技能和UI，平台知识服务独立存活；卸载不自动删除项目经验/工件。版本变化不能静默替换在途任务使用的程序或知识快照。

## 5. 通用对象与状态（拟实现合同）

| 对象 | 必要内容 |
|---|---|
| Project / Workspace | 明确ID、目录/服务器映射、插件上下文、上游会话关联 |
| ResourceRevision | 路径、格式/角色线索、摘要、批次、读取状态 |
| PluginContribution | 稳定pluginId、兼容版本、taxonomy、种子manifest、验证器、公开入口 |
| Run / Execution | 项目/插件/程序/输入/配置/知识快照、运行时、退出/诊断及状态 |
| ArtifactRevision | 运行、工件名/格式/摘要、输出合同、检查结果和打包记录 |
| KnowledgeRevision | scope、分类、内容digest、状态、来源、验证与替代/冲突关系 |
| VerificationReceipt | 候选版本/摘要、执行器/验证器版本、实际测试结果与证据引用 |

运行状态：`CREATED/RUNNING/WAITING_FOR_USER/SUCCEEDED/FAILED/CANCELLED/UNKNOWN`；业务阶段放插件命名空间。状态名称不是权限判定。缺语义不等于工具故障，取消未知也不等于失败已终止。

## 6. 平台经验库分类示例

```text
shared: R运行与编码、格式/缺失、通用数据连接及验证方法
plugin dm-listing:
  intake / als / sas / runtime / output-qc
  review: manual + medical（同一记录多场景引用）
  pk: common / be / sad-mad
  report: 独立分类，成熟经验不足如实标注
project <明确projectId> + plugin dm-listing:
  当前spec版本裁定、字段映射、例外和本项目纠错记录
```

按插件分类不能变成按插件复制平台服务；两类PK不能无条件互套，项目字段/OID/阈值不自动升为共享经验。

## 8. 当前实现差距与迁移顺序

现有TaskStore、R/Excel/RDS合成测试和打包能力可复用。**现有入口仍是demo，Cover/辅助表拒读、审批、投影及旧readiness仍在源码/UI中**；静态经验文本新增接线未验证，公共经验库未实现。69项旧基线不能证明新项目流程完成。

实施顺序：撤出旧门禁/冲突提示→公共知识服务和三项目种子→项目发现/完整资料和SAS读取→通用R自主执行与单文件服务器交付→实际学习闭环与三场景端到端→独立检查。详见 [迁移清单](MIGRATION-AND-ACCEPTANCE.md)。

本轮仅更新设计文档，不改业务源码、不运行模型业务请求、不迁移旧数据库、不配置IT API/VM。未来多人/远程、认证、数据API或企业部署按实际合同另定，不作为当前本地开发前置。

## 9. 验收边界

- KnowledgeService在两个插件分类中可用，核心无Listing分支；项目裁定不串线。
- 知识种子幂等、经验持久、修订/撤回/冲突/快照和并发可验证；不信模型自报测试通过。
- 数据与程序工具无自建类别拒读和旧审批，资料完整，异常诊断可修复。
- 独立R程序在新目录、不同cwd和服务器配置下实际复跑，Excel/RDS分别QC。
- 当前测试、历史项目证据、模型自主冷启动、真实服务器验收及IT责任分别记录，不承诺零bug。
