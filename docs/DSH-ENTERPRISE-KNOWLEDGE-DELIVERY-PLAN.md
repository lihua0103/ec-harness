# DSH 企业级知识库：开发与验收计划

状态：实施中 v0.2 · 2026-11-20。依据：[体系设计](DSH-ENTERPRISE-KNOWLEDGE-SYSTEM.md)、[开发规范](DSH-PLUGIN-DEVELOPMENT-STANDARD.md)、[知识验证合同](PLATFORM-KNOWLEDGE-VALIDATION-CONTRACT.md)、[智能体合同](KNOWLEDGE-AGENT-CONTRACT.md)。本文件定义交付顺序、验收与证据，不表示任何阶段已通过；§5 记录已实现的工程合同与仍未执行的验收。

## 0. 2026-11-20 实施快照（工程合同，不是验收）

已完成并过本机包测试与门禁的**代码合同**：智能体定义 v2 与注册表、可信范围派生、快照实际消费与固定集合检索、证据/引用对账、事件投影幂等、一次性回执、发布覆盖门禁（`knowledge-assembly.json` + `scripts/verify-knowledge-coverage.mjs`）。7 个纳管插件（4 业务 + 3 平台）均有 v2 定义与黄金集；平台控制面/知识服务/工作台在本轮补齐运行与故障处置种子后登记为 `managed`。

**未完成、不得报告为通过**：A01–A16 全部 `NOT_RUN`（除 A15 的本机工程门禁部分）；真实宿主双样本、工作台知识依据界面、身份接线与验证执行器部署、区域/恢复演练、领域黄金集扩充与领域负责人签收。工单级状态见 §5。

## 1. 范围、基线与排期

**最终交付：每个纳管 DSH 插件都有可注册、可调用、可审计、可独立验证的知识智能体。** 分母来自批准的装配/发布清单，以插件身份去重，核对所有发布版本的兼容性；Host/Client 若属同一插件只算一个身份，纯库不计入，技术/平台插件不得因没有业务工件而跳过。灰度只覆盖明确列出的插件和环境，不等于全平台发布。

复用现有 `platform-knowledge`、SQLite/FTS、控制面 Run/Outbox、DSH 服务注入和原生工作台。以锁定的 DSH `0.2.2-rc.1`（`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`）为兼容基线，开工复核对应的上游公开契约；Node 使用项目支持版本 `>=24.9.0`。不自建 Agent 循环、不复制知识库、不绑定供应商、不预先迁库，不变更生产 profile。

| 阶段 | 初估 | 依赖 | 结束标志 |
|---|---:|---|---|
| M0 基线冻结 | 0.5 周 | 获得开发装配清单和隔离环境 | 覆盖分母、初始验证、所有权及测试口径确认 |
| M1 可信检索与快照 | 1–2 周 | M0 | 授权、快照和真实宿主检索验收通过 |
| M2 治理闭环与双样本 | 2–3 周 | M1 的授权/快照合同 | DVP + 工作台从证据到复用在真实宿主跑通 |
| M3 全插件接入 | 2–3 周 | M2 协议稳定；夹具可先准备 | 纳管清单逐插件通过、发布门禁阻断缺项 |
| M4 运维验收与试点 | 1–2 周 | M3；区域、SLO、数据与回滚责任人确认 | 隔离环境演练、获批范围试点及独立签收 |

关键路径初估 **6.5–10.5 周**，按有平台与插件开发人力、QA/IT 可参与估算，不是承诺工期。M0 后按实装分母、身份接线、验证执行器部署成熟度及既有未提交改动重估。可并行准备不同插件的夹具和种子，所有共享合同、检查脚本、公共包各只有一个写入负责人；开始前按文件明确范围，不把他人排队消息当协调成功。

## 3. 验收矩阵

每条结果写 `PASS / FAIL / BLOCKED / NOT_RUN`；未执行、无适用数据、判定未知都不是 PASS。以下测试使用合成夹具或批准语料；真实临床材料如有授权，只在本地业务工具处理，结果仅外显允许的汇总，不读原文、逐条报告或映射表入模型上下文。

| ID | 场景与操作 | 通过标准及证据 |
|---|---|---|
| A01 | 整理两份不同发布组合；复核上游合同、Node 和基线检查 | 所有纳管插件可从制品追溯，例外是明确的非纳管/纯库分类，不是缺项豁免；保留清单、基线版本、运行日志 |
| A02 | 合成同名项目分属两个组织/区域，覆盖检索、直接 ID、分页/计数、语料和候选 | 允许范围正例命中；无权限范围正文、ID、计数和引用泄露为 0；不以只测搜索列表代替所有入口 |
| A03 | 模拟身份缺失、授权撤销与未知归属旧条目 | 需要权限时拒绝，缓存不跨范围串用，公共种子仅按批准范围可见；留权限矩阵结果、不记录敏感正文 |
| A04 | Run A 固定版本后升级知识，再开 Run B；重启后重放 A | A 仍读取原修订，B 使用新修订；摘要由实际修订集合可核对；真实工具调用证明没有走活库 |
| A05 | 冻结后撤回知识、撤权或模拟快照不可达 | 不返回失效正文或改读活库；原事实可追溯；工作台区别显示撤回、不可用与未绑定 |
| A06 | 已绑定、未命中、仅候选、索引降级的成对用例 | `ACTIVE` 默认结果与候选分开；未命中诚实率 100%；实际返回与最终引用可对账，未引用不冒称采纳 |
| A07 | 注册、停用、重装、版本并存和重复标识 | 合法定义可发现，停用不残留注册，历史可追踪；同 ID 冲突被拒绝；Run 不默认换用新版智能体 |
| A08 | 同一 QC 事件重复投递、消费失败后重启、无可复用证据 | 同投影只产生一个候选；无证据输出明确结局；Run 状态和知识状态分离；留事件/候选 ID 与投递记录 |
| A09 | 独立验证执行域运行正、反、边界；另测覆盖不足、超时、过期修订和重复回执 | 仅可信且完整的匹配回执可激活；无证据激活数 0；重复有效回执幂等；有执行身份和版本证据 |
| A10 | DVP 工作簿盲生成后引入定稿/合成参照；覆盖等价、仅措辞、逻辑改变、漏项、误增、未决、解析失败 | 分母和未决单列；不强配、不以定稿自动裁决；对照报告与原始输入留本地，只把允许的汇总送模型 |
| A11 | 可重复的知识启用/关闭对照；固定输入、运行环境、模型配置和评测器，冻结沉淀/留出样本分割 | 至少双样本在同一口径下有可说明的收益且无关键回归；每个纳管插件均有领域黄金检验。报告同时给出通过/失败/未决计数，不以入库条数代替收益 |
| A12 | 在真实 DSH 宿主分别走业务和平台插件；通过 UI 查看证据与治理状态 | 两条链路均实证可发现→检索引用→候选→领域验证→新 Run 复用；无第二套会话内核；绑定、角色、交互与工件摘要可核对 |
| A13 | 用实际部署清单回放注册与评测；测试一个缺声明或测试证据的发布制品、再加一个合成新插件 | `通过插件 / 纳管插件 = 100%` 才能宣称全平台覆盖；缺项阻断对应发布；新插件不改平台领域分支 |
| A14 | 双语/缩写、区域隔离、目标并发与突发写入；演练备份/恢复和受控跨区分发 | 区域无泄漏、版本准确；记录 p95、积压恢复、RPO/RTO 与测试负载。以 M0/M4 冻结的环境预算为准，未定或未测不得放行对应部署 |
| A15 | 从锁定制品/依赖运行全仓门禁及真实宿主回归 | 规范、包测试、黄金检索与装配均通过；保存退出码和结果，分别标明工程、业务、部署三类验收 |
| A16 | 隔离环境迁移、故障停写、回退与对账；试点退出 | 任一时刻单一写者；恢复校验身份、修订、事件、回执和审计引用；窗口达标，无未解释的丢失/重复；有运维签字与停放行记录 |

**质量阈值规则：** 跨作用域泄漏、未授权激活、在途静默漂移、临床正文外显、关键领域回归都要求 **0**，不作灰度豁免。命中质量按术语/语言/插件分层报命中率、误召回和无命中样本；领域质量由领域负责人在评前批准分母、关键项与阈值。容量以 [已有目标架构参数](ENTERPRISE-KNOWLEDGE-ARCHITECTURE.md)为候选，M0 明确实际负载、冷/热、并发、机器与测试数据；不得把历史 20k 选择性查询数字当生产 SLO。生成模型若批准参与对照，记录实际模型及运行条件；结果有波动时多次重复并同时列出失败，不只选最好一轮。

## 4. 执行入口与交付证据

以下是当前已有入口；新增的身份/快照、事件回放、发布覆盖、真实宿主与运维演练用例须在对应工单实现并落下实际入口，不能把下列脚本宣称为所有 A01–A16 的替代。


```bash
node scripts/verify-knowledge-golden.mjs
```

```bash
node scripts/verify-all.cjs
```

验收证据最少包含：`验收ID / 插件ID与版本 / commit或制品摘要 / DSH与Node版本 / profile与环境 / 夹具版本和摘要 / 命令或实际宿主步骤 / 预期 / 实测与退出码 / 脱敏证据路径 / 执行人 / 复核人 / 状态 / 缺陷单`。记录不含真实正文、凭据、患者标识、映射表，运行证据以授权路径与摘要引用。检查和修复由实现负责人执行，QA 对照独立复跑，领域负责人复核质量，IT/安全签收身份和驻留，运维签收迁移/恢复，发布负责人合并签收证据。空签或缺证据不放行。

**发布与回退：** 使用隔离 profile、合成数据做首轮验收；禁止未经批准修改生产。泄漏、授权错误、版本漂移、业务回归或状态无法对账时停止该批次，禁用受影响的知识服务能力或回退到已验证的发布组合；撤权与保护措施不能因回退被绕开。迁移先备份和停写，数据改变后优先保持单写并对账，不能直接用过期备份覆盖新增审计。若不能安全回退，停止写入并保留证据，等运维与数据方裁决。

**首个执行批次：** 只开 M0：盘点实际装配、冻结基线与夹具、明确写入人与签收人；不把全平台功能拆成并行修改公共包的多个任务。
