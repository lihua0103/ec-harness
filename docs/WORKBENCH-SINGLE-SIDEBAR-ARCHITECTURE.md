# 员工工作台单侧栏架构

2026-11-21 · 设计方案 · 待隔离装配验证

## 员工界面

**员工入口只显示一套左侧导航。** 从截图左边开始，DSH 默认侧栏展示了新会话、插件、自动化任务和工作区，紧接着企业工作台又展示新建工作、历史会话和项目空间。员工为了同一件事要先在两套导航中辨认入口，两个侧栏也挤占了结果与会话空间。已审查的工作树移除了旧的 DOM 隐藏逻辑，保留了原生侧栏和工作台页内导航的同时挂载。此前开发计划把原生图标栏列作退路，现修订为企业导航独占员工界面的左栏位置。[工作台挂载入口](../packages/platform-workbench/src/client/index.ts:196) · [页内导航](../packages/platform-workbench/src/client/WorkbenchPage.tsx:4924) · [原生侧栏职责](../upstream/deepseek-harness-git/packages/client/ui-sidebar/README.md:14)

| 员工意图 | 入口和反馈 |
| --- | --- |
| 创建业务工作 | 左栏「新建工作」是唯一全局主按钮。从应用中心进入时预选应用，从项目空间进入时预选当前项目。 |
| 继续已有工作 | 「我的工作」按项目及最近活动查找，打开后进入该 Work 绑定的原生会话。最近工作都在这一页。 |
| 找回曾经的对话 | 「历史会话」是唯一会话目录。已绑定的会话显示可访问的工作或项目。未绑定的普通会话仍可在这里继续。点击打开时使用实际 Session ID。 |
| 找工具或处理待办 | 「应用中心」按项目授权显示已发布应用。「待我处理」直达该工作、待答或复核。员工侧栏的入口数随应用增加保持稳定。 |
| 看运行产物 | 工作页右栏显示当前输入、运行记录、成果和复核。切换历史 Run 时，原生会话保持打开。窄屏通过标题旁的「运行与成果」按钮打开抽屉。 |
| 设置语言及常用偏好 | 底部「平台设置」集中承载。插件安装、原生工作区树和自动化管理通过独立的运维入口提供，使用现有授权。 |

**视觉规格。** 企业标识只在左栏排一次，页眉从当前页面或工作名开始。页面标题、筛选和表格起点左对齐。以 DSH 主题 tokens 和字体栈为实现入口，建议浅色基准色为纸白 `#FFFFFF`、导航底 `#F4F7F6`、分隔 `#D9E3DF`、正文墨绿 `#182F2C`、主色玉绿 `#087D70`。产品标题约 24px，常用入口和行正文约 14–16px。玉绿集中用于创建动作和当前项，状态以文字加视觉标识表达。会话目录使用业务标题和项目名，必要的已授权路径收纳在详情。桌面沿用宿主的一列可折叠布局，窄屏使用同一企业导航抽屉，关闭后焦点返回打开控件。

## 装配设计

锁定 DSH 的 `ui-layout` 声明根作用域下的 `sidebar` 单渲染插槽。该插槽允许不同优先级的注册，数值最低的注册获得渲染位置，同优先级的重复注册才会冲突。现有 `platform-workbench` 通过 DSH 插件机制以 `priority: -1` 注册企业导航。企业导航随插件加载取得侧栏位置，并使用 `toggleSidebar()` 控制自身的展开与折叠。员工 Web profile 可选择叠加配置停用默认 `ui-sidebar`，使企业导航成为唯一的注册项。实际员工环境的装配仍需验证。[插件注册](../packages/platform-workbench/src/client/index.ts:81) · [插槽优先级规则](../upstream/deepseek-harness-git/packages/client/ui-slots/src/index.ts:1252) · [Web 布局合同](../upstream/deepseek-harness-git/packages/client/ui-layout/README.md:28)

| 所在层 | 目标职责 |
| --- | --- |
| 受控员工 Web profile | 保留 `ui-layout` 作为框架所有者，由工作台 Client 注册并渲染企业导航。可选的员工配置叠加层停用默认 `ui-sidebar`。验证实际加载顺序、渲染结果和服务依赖。运维 profile 可使用 DSH 默认导航。 |
| `platform-workbench` 的 `sidebar` | 独占企业品牌、全局创建、主导航及设置。使用宿主传入的列宽、折叠及抽屉属性。从此处处理键盘焦点。需要 `shell.leading` 时在同一企业导航架构下提供抽屉打开控件。 |
| `platform-workbench` 的 `main:emerald-platform` | 只渲染页面标题与主体、会话及右侧工作上下文，移出当前 `WorkbenchPage` 内部的导航组件及其布局轨道。以一份插件自有的轻量路由状态连接两个 slot，公用当前页、活动 Work/Session 和创建动作。原生会话通过显式 `SessionProvider` 挂载，工作台状态不存储消息和会话副本。 |
| DSH 原生组件和服务 | 保留 Session、Workspace、流式回复、Composer、附件、停止、工具活动和原生问答。`ui-workspace` 的服务和默认树是两个装配关注点，需在隔离 profile 检查依赖其服务的功能仍可用。移动端和快捷键只控制企业左栏。 |
| 控制面及业务插件 | 应用按批准发布进入目录，业务组件按声明进入内容区或右栏。工作台导航不决定权限。继续以已有注册、Work—Session 关联和 Run 事实为来源。 |

**技术验证顺序。** 先在隔离 profile 保留默认 `ui-sidebar`，验证工作台插件仅凭公开插槽优先级就能渲染唯一的企业导航。再叠加员工配置并重复检查。两种装配均验证 `emerald-platform`、Workspace、Session 和所需原生组件的加载。检查依附默认侧栏的 `sidebar.workspaces`、`sidebar.settings`、`sidebar.panellist` 和 `shell.leading` 贡献。仅将员工所需入口接入企业导航或已有页面，运维所需入口留在运维 profile。DSH 客户端的包名 `inject` 是一类元数据边，运行服务注入与 slot 声明各自核对。若发现锁定版的必需交互与默认侧栏存在硬依赖，记录缺口，评估通过上游公开扩展或版本化宿主适配分离该依赖，双侧栏或原生图标栏状态不通过员工版验收。[锁定版配置启停](../upstream/deepseek-harness-git/docs/cordis-tutorial/06-composition-and-hmr.md:9) · [侧栏注册](../upstream/deepseek-harness-git/packages/client/ui-sidebar/src/client/index.ts:88) · [Workspace 服务接线](../upstream/deepseek-harness-git/packages/client/ui-workspace/src/client/index.ts:98)

## 实施与验收

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 隔离装配探针 | 锁定宿主的员工 profile、最小 `sidebar` 占位、服务与 slot 清点 | 冷启动及刷新只有企业导航占位，首屏直接进入工作台。没有默认会话树或原生图标轨道短暂出现。会话和 Workspace 服务可用。 |
| 提取导航与迁移路由 | 工作台 Client 的导航组件和共享路由，内容页移除第二列导航，整合创建、最近工作和历史会话 | 我的工作、历史会话、项目空间、应用中心和待办可从唯一左栏打开。现有的 Work 与 Session 深链接可恢复，旧数据保持关联。 |
| 原生会话与右栏回归 | 锁定宿主内实际创建、恢复、回复与查看成果的浏览器证据 | 原生 Chat、流式、问答、附件及停止可用。切换右栏 Run 时保持同一 Session，并核对原生提交不重复。 |
| 发布前交互检查 | 用于发布验收的桌面、手机、中英、键盘和错误状态记录 | 桌面展开时只有一个主导航。桌面折叠及手机抽屉状态仅有企业导航控件。断网恢复、撤权、前进后退及退出抽屉时的焦点行为正确。 |
| 部署与回退 | 员工 profile 装配摘要、兼容记录及回退步骤 | 在隔离环境切换后核对既有 Work、会话和 Run。回退以启用前已核准的 profile 或入口为单位，历史记录保留。 |

此设计修订员工 Web 装配在 ADR-0003 中以 `toggleSidebar()` 收起默认侧栏的做法。ADR-0003 对 DSH 原生交互、单 Session 写入所有者和中心会话的决定继续作为合同。由工作台维护者按开发计划工作包 6 负责 Client 装配，由发布维护者负责员工 profile，接续工作包 3 的导航状态修改，避免重叠写入。[ADR-0003](adr/ADR-0003-NATIVE-WEBUI-WORKBENCH.md) · [平台开发计划](DSH-ENTERPRISE-PLATFORM-HARDENING-PLAN-2026-11-21.md)
