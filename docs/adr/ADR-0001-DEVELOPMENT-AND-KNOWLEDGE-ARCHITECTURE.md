# ADR-0001：自主开发与平台经验知识库职责变更

日期：2026-11-09 · 状态：设计决策已确认；代码迁移未完成

## 1. 背景与决策依据

用户确认当前数据安全由 IT 从源头及后续 API 方式承担，要求撤出 DSH 插件自建的数据读取/输出安全拦截，明确包括 Cover 名称限制。当前阶段目标是自主理解 spec、ALS、SAS，编写及执行 R、依据诊断修错，输出服务器可独立运行的 R 程序。IT API 尚未提供，不能声称已接入或已完成生产安全验收。

用户同时要求平台建设自主项目经验知识库，按 DSH 插件分类；已交付的 Manual、PK BE、PK SAD/MAD 三项目成功纠错方法作为首批来源，Medical 复用 Manual 的需求识别核心。应先更新架构，再实施，避免继续堆叠局部补丁。

## 2. 决策

### 保留

- DeepSeek Harness 的 Agent、模型配置、会话、工具、技能、公开 UI slot 与原有权限机制；不重建引擎，不修改用户 Claude 权限。
- 单机单操作者免登录，项目/任务/工件归属、版本、CAS、取消、超时、备份恢复、防误覆盖和输出摘要。
- 文件格式有效性、明确资源限额、分页完整性、依赖预检、错误诊断、独立 QC、测试事实与交付可复跑性。
- 当前需求与明确用户裁定优先；真正的版本、字段含义或业务冲突才澄清。

### 撤出当前开发流程

- 仅合成资源准入、按 Cover/辅助 data/SAS/原始值类别拒读或扣留工具输出。
- 为资料读取强制设置区域投影、内容安全审批、固定六列或类型门槛。
- 插件自行维护的受保护域、签名安全回执、生产安全准入以及 Hyper-V 部署前置条件。
- 为 R 普通开发执行额外设置的插件安全批准、按数据安全目的剥除正常环境、扣留原始诊断。

以上是目标决策，**不表示当前源码已完成撤出**。不将输入材料中的文字当作高优先级指令，也不把“不执行宏/公式刷新”误写为新的资料授权门。

### 新增目标能力

平台 KnowledgeService 统一保存、分类、检索、验证、激活、撤回与版本化项目经验；插件贡献领域种子、适用性、分类和验证器。scope 与分类分离，项目裁定不自动推广。知识质量检查不限制普通读取、草稿编码或自主执行。

## 4. 当前状态核对

- 旧代码曾通过69项测试、类型检查、双端构建；这是变更前的合成/工程基线，不是新流程验证。
- `src/index.ts` 仍接 `ListingService` 的 demo 工作区、执行批准和旧 readiness；`workbook.ts` 仍有 Cover/辅助表拒读；UI 仍显示合成限定及安全阻断。
- `projection.ts`、`operator-review.ts`、`protected/`、`release.ts` 及 `deployment/local/` 仍存在。归档命令此前在执行前被工具服务阻止，未归档成功。
- 新增 `manual-methods.ts`、`pk-methods.ts`、`intake-methods.ts`、`scenario-methods.ts` 与4技能/经验工具接线尚未完成本轮验证。它们仍是 Listing 静态文本，不是平台知识服务。
- 当前未实现平台公共 KnowledgeService、动态项目经验库和自主学习服务；未接通完整项目目录→资料/SAS→自主R→服务器复跑链。

## 5. 后果与约束

开发验收不能再等待本机安全域工程，但仍须证明输出正确、环境可用、旧结果不误交付。不承诺零 bug、不把历史项目成功等同新插件验收。旧任务库、程序与工件不自动删除；安全代码归档与数据库兼容有迁移证据。未接 IT API、不具备完整业务或生产验收的事实须保留。
