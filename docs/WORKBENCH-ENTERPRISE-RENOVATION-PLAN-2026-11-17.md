## 1. 核心论点

差距一半在平台（身份/隔离/部署权威/质量/成本），一半在产品体验。**A 线·平台可信基座** + **B 线·产品体验**是逻辑分层；治理前置（临床命门）。复用后端已有基座，不推倒重来。**诚实优先于"看起来企业"**——未真生效的授权不假装生效。

## 2. 决策门（先于阶段回答，决定重心与阻塞项）

| 门 | 问题 | 选项 | 阻塞什么 | 谁答 |
|---|---|---|---|---|
| **D0** | **首个真实用途是否受监管临床交付？** | 受监管交付 / 内部非监管试点 | 决定身份/审计/电子签名是 E0 阻塞项还是可后置；决定 MCES 构成 | 业务 + QA |
| D1 | 身份路线 | 真实企业 auth（按 IT 合同）/ 诚实单操作者 + 服务端真隔离 | E0c 做法；**禁假安全** | IT + 平台 |
| D2 | 部署形态 | 本地受管节点 / 中心权威 | E0d、E4 隔离、资料/R 可达 | IT |
| D3 | 基线冻结 | 冻结 commit 重绑后端 map | 承诺具体 endpoint 的前提 | 平台 |

**D0 是重心**：若首个用途是受监管交付，审计/复核/签名/身份从"后续增强"变成"首期阻塞"，整个计划重心前移；若是内部试点，可诚实单操作者起步，但仍需审计与任务闭环。**未答 D0/D1 前，E0c 不开工。**

## 3. 企业目标与原则

目标：从单操作者工程原型升级为可治理/可问责/可协作的企业 AI 平台（L3），为 L4 留合同。
原则：不降标准但按依赖排序；治理前置；复用基座；DSH 锁定 `0.2.2-rc.1`、不建第二套引擎/聊天/React、模块化单体；**诚实门禁**（未真生效不宣称，未达 L3 不称企业平台）。

## 4. 企业就绪门禁（L3 由具体测试定义，限首批应用）

| 维度 | 就绪判据（可测） | 当前 |
|---|---|---|
| 身份与隔离 | 按 D1 路线：真 auth 或诚实单操作者标注；授权在搜索/下载/事件/知识/分享**服务端**生效；跨项目负例拒绝 | L1/L0 |
| 审计与证据 | 每动作可查审计链；运行证据重启不丢；复核绑定确切版本；交付≠封存≠接收 | 后端 L2/UI L0 |
| 质量 | **首批应用**有评测代表集 + 独立预期 + 模型回归；不以模型自评代 QC | L0 |
| 成本/模型治理 | 用量可取得则归集到 Run（不可取得保持未知）；预算可拦截；模型审批/区域 | L0/L1 |
| 运营/恢复 | SLO/告警/doctor；备份恢复**实测**；权威单一 | L2/L1 |
| 协作 | 共享/分派/转交/评论；权限覆盖搜索/通知/导出；离职转交不删历史 | L1 |
| 任务/交付 | 基线 + 三指针 + 换批闭环 + 差异/影响 + 交付版本链 | L1 |

**不得提前宣称**：真实 SSO/多租户、容器/VM 隔离、电子签名、GxP/Part 11 合规——IT/QA 按用途独立验收。verify-all 只证明实际执行的检查。

## 5. 最小企业可信切片（MCES，由 D0 驱动）

不是 E0–E4 全量，是**首个真实用途的及格线**：

- **若 D0=受监管交付**：受控身份（D1）+ 审计链可查 + 复核/交付分离 + SC-03 两批交付 + 单应用评测代表集 + 备份恢复演练。电子签名按 QA 定级（可能阻塞）。
- **若 D0=内部试点**：诚实单操作者（明确标注无多用户隔离）+ 审计可查 + 任务工作台 + SC-03 + 去基础设施外泄。

**MCES 之外不得宣称企业就绪。** MCES 是开工目标，E0–E4 是演进路线。

## 6. 现状基线 + 基线冻结前置

**可复用资产**：审计 SHA-256 链+导出（`service.ts:1432`/`http.ts:317`）、审批/回滚（`service.ts:277–412`）、运行事件历史+SSE（`http.ts:599–644`）、追加式输入基线（`http.ts:480`）、复核（`http.ts:672`）、租约/outbox/子进程执行器、备份/恢复函数、metrics/doctor、身份策略库、知识服务（**无 HTTP 路由**）。

**成本可行性核实**：锁定 SDK `protocol/src/types.ts` 仅 `maxTokens`（请求参数），**未声明 usage 类型**；`usage` 块仅见测试夹具。→ 每运行 token 用量是否经公开协议暴露给 worker **不确定**，列为 E2-0 上游 spike；不可取得则成本保持未知（FR-15），运行时长可先用。

**D3 前置**：后端 map 是并行整改下的移动快照；承诺具体 endpoint 前冻结 commit 重绑，不据此宣称接口稳定。

## 7. E0 拆分（四个工作流，不再"一切堵 E0"）

| 工作流 | 内容 | sizing | 风险 | 依赖/退路 |
|---|---|---|---|---|
| **E0a · UX 止血** | 修三缺陷（`:2089`/`:2206`/`reports.ts:121`）+ 去外泄（专家抽屉）+ 首页续作 + 深链接（不扩授权）+ 向导修复 | **S** | 低 | 纯前端，**无依赖可立即开工** |
| **E0b · 审计/溯源** | 审计查看器（接 `audit/export`）+ 运行事件历史+SSE 替换轮询 | **M** | 低（后端已有） | 受监管则阻塞 MCES |
| **E0c · 身份/隔离** | 按 D1：真 auth 接线 **或** 诚实单操作者 + 服务端授权真生效（搜索/下载/事件/知识/分享） | **L** | 高（假安全/迁移） | **D1 未定→保持诚实单操作者标注，不接权限 UI** |
| **E0d · 部署权威** | 收敛 `control.sqlite`/`workbench.sqlite` + 会话存储/恢复限制标识 | **M–L** | 中（数据迁移） | 迁移有风险→先统一读写入口+标注，数据迁移单独评审 |

E0a 与 E0b 可先行；E0c 由 D1  gate；E0d 迁移单独评审。**禁假安全**：固定操作者上的权限显隐不是授权。

## 8. E1 · 任务/交付 + 临床证据闭环

| 编号 | 工作项 | 后端杠杆 | 验收事实 |
|---|---|---|---|
| E1-1 | 任务工作台：目标+基线+三指针+分页签；聊天降辅助（原生工厂） | 前端重构 | 三指针分开不统称"最新" |
| E1-2 | 换批次重跑闭环：新基线 I2（B1→B2）→继承 C1→新 Run→本批检查→新交付；D1 保留 | **已有** `POST …/input-baselines` | 漂移不假成功；返回 D1 不重跑 |
| E1-3 | 复核/交付分离：交付包（封存≠交付≠接收）+历史/替代/撤回 | 复核已有；需建 DeliveryPackage | 下载≠接收；旧审核不自动迁移 |
| E1-4 | 差异/影响视图（应用贡献业务键，不按行号） | 需建差异语义 | issue 按稳定键对齐；不可比较项标明 |
| E1-5 | 应用贡献结果视图：**先声明式结果视图**；平台 UI SDK + 信任模型（同源/iframe）**分期**；插件配合 | 机制**未建**，分期 | 结果结构化；平台无 if listing |
| E1-6 | 运行追踪：持久事件 + 工具调用/时长 | 已有 | 可回放、可定位 |

出口：SC-03 两批两次交付，证据链可查，旧交付不覆盖。E1-5 是平台机制工程 + 插件协调，非一个前端工作项。

## 9. E2 · 质量 + 模型/成本治理（按项目对待，spike 前置）

| 编号 | 工作项 | sizing | 前置/退路 |
|---|---|---|---|
| **E2-0** | **spike：验证锁定 SDK 用量暴露**（已核实 protocol 未声明 usage） | **S** | 决定 E2-2 可行/保持未知 |
| E2-1 | 评测：**单应用（Listing）代表集起步** + 独立预期 + 失败分类 + 模型回归 | **XL·项目** | 独立预期需业务专家（待公司事实）；专家不足→先确定性验证+人工 QC，评测延后 |
| E2-2 | 成本采集（若 E2-0 可行）；否则时长+未知 | **M·上游 gated** | 不伪造 0 |
| E2-3 | 预算/配额执行 | **M** | 需 IT/财务定规则；不静默切模型/区域 |
| E2-4 | 模型治理：审批/区域/辅助调用计量 | **M** | 复用 release approval 模式 |

评测不是"需建框架"四字，是依赖专家 gold set 的工程；**不追求"每应用"一次到位**，首批应用先闭环。

## 10. E3 · 运营 + 协作

E3-1 运营面板（SLO/p95/告警/doctor/outbox，metrics 已有）· E3-2 备份恢复**演练**（函数已有）· E3-3 团队协作（共享/分派/转交/评论，需建）· E3-4 统一待办（interaction kind 需扩展，当前仅 user-question）· E3-5 故障 runbook。
出口：跨项目拒绝、并发不串、离职转交不删历史、恢复实测。

## 11. E4 · 规模化 + 国际化 + 编排（按 IT 合同与真实负载）

DeliveryPackage · EvaluationSet/EvaluationRun · CostRecord（未知保持未知）· CollaborationGrant/Handoff · InteractionKind 扩展 · 隔离域与授权矩阵。沿用需求 FR-19–29/多插件 §9，不另建需求权威；受影响 schema/API 开发前冻结并评估迁移。

## 13. 工作量、关键路径与退路

**关键路径**：D0/D1 → E0c →（受监管）E0b/E1 证据 → MCES。**E0a 无依赖，可立即并行先做**（纯前端，不碰共享后端文件）。

**单写入串行**：A/B 线共享 `service/store/worker`，按需求 §12 **串行协调**——"双线"是逻辑分层，**不是并行承诺**。先检查既有并行整改差异，不覆盖未提交工作。

**退路（决策门 fallback）**：
- D1 未定 → 诚实单操作者 + 标注，不接权限 UI（不造假安全）。
- E2-0 上游不暴露用量 → 成本保持未知 + 时长，不伪造。
- E2-1 专家时间不足 → 确定性验证 + 人工 QC 先行，评测延后。
- E0d 迁移风险高 → 先统一读写入口 + 标注，数据迁移单独评审。
- D0 受监管但签名未就绪 → 明确"候选/未正式交付"，不冒充合规交付。

## 14. 可行性纪律与非目标

真约束：DSH 锁定、不建第二套引擎/聊天/React、模块化单体、执行域独立、受监管域。非目标：通用低代码/编排器、插件市场、按插件拆微服务、DOM 改写、第二套会话存储。数据授权由 IT/API/执行环境承担。

## 15. 验收

每阶段出口事实见 §7–§11；**MCES（§5）是首个用途及格线**；企业就绪门禁（§4）达 L3 才称企业平台。可用性目标：非开发员工无需 shell/密钥/ID/口头指点完成核心任务，≥80% 试点无协助，无项目/批次误认/旧交付误当新结果/未执行误当完成/草稿丢失。SSO/隔离/签名/合规独立验收；恢复要演练；规模要真实负载。

## 16. 下一步

1. **先答 D0/D1**（首个用途合规定级 + 身份路线）——决定重心与 E0c 做法。
2. **立即开工 E0a**（UX 止血，无依赖 quick win）+ **E0b**（审计/溯源，后端已有）。
3. E0c 按 D1；E0d 迁移单独评审；**D3 冻结基线**后再承诺 endpoint。
4. 以 SC-03 纵向切片取证 MCES；E2-0 spike 与单应用评测紧随。
