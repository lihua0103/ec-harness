2026-11-25 · v1.0 · 状态：方案待实施，全部工程用例 NOT_RUN。

## 2. 工作包与出口

### R0 — 可复现候选

- 记录 HEAD、工作树差异与未跟踪文件归属；经负责人确认生成完整候选快照，不 reset、stash 或提交他人改动。
- 记录上游 commit/工作树、Node/pnpm/R/OS、执行器入口、模型路由非秘密引用、配置及依赖锁摘要。不能只用 HEAD 标识脏工作树。
- 复扫 packages/plugins/scripts 的源码跨包引用；区分类型、值、动态导入和再导出，输出路径清单而非只保留“57”。
- 对评审安全定位做同快照只读复核；复验幂等、引擎字节核验、goal 可达性及知识库拓扑。为每项标注确认、未复现、待核对及证据。
- 执行受影响包、规范检查和 verify-all；首败与最终结果都保留，不把历史 22/22 当当前候选结果。

**出口 BASE-01**：完整候选可重建、证据与候选一致、未决和环境限制明确。未能冻结时后续仅设计/合成探索，不宣称验收。

### R1 — 主体不可自授，API 不信任本地来源

拟改：`platform-identity`、控制面 policy/http/cordis/api-cli、知识 HTTP/范围、工作台代理和审计迁移。

- 定义断言验证链：签名、issuer、audience、有效期、容差、重放及撤权。代理剥离客户端身份头，控制/知识服务不直接信任 `x-dsh-subject`。
- Principal 含经批准角色与租户项目范围；批准人/QC 主体由服务端派生，模型参数和请求体不能覆盖。发布、验证、业务批准按职责分离；管理工具移出员工执行入口。
- 默认企业入口缺有效凭据即拒绝；本地替身只能显式开启于隔离合成模式。浏览器凭据、服务间凭据、Worker Run 凭据、验证回执权限分别约束受众和用途。
- 数据安全开关、模型目录管理、死信重放、shared 写入、发布/撤回和投影查询纳入角色、范围及审计。`eventRef` 必须回指经授权的真实投影，不只通过结构校验。
- 审计保存真实主体、角色决策、项目/租户、对象修订及请求关联。若实现防篡改链，定义持久计算与验证机制；导出时临时算哈希不能宣称已防篡改。

**SEC-01**：请求体伪造 approvedBy、会话自授角色及同人跨职责审批被拒绝；合法第二身份审批可追溯。

**SEC-02**：直接 API、伪造身份头、错 audience、过期/重放凭据、缺身份和普通 Worker 管理请求均拒绝；列表/计数不泄露跨域对象。

**SEC-03**：撤权事件、时限和新动作拒绝可测；合成目录测试不计作真实 ID-01/02。正式撤权通道和目标环境时限待 IT 提供。

### R2 — 实际字节、有效配置与独占执行状态

拟改：runtime plan、release-manifest/registry/deployment、worker/child-worker、profile/部署生成脚本、执行监督入口。

- 制品清单绑定引擎 commit 与实际安装摘要、adapter、依赖闭包、包内容、bundle lock、有序 patch 和有效配置；固定序列化、相对路径及符号链接规则，秘密只记录受控引用。
- 部署与派发采用同一核验算法，在输入消费前重算实际制品与有效配置。防止预检后可写制品变化，执行身份只读；不只比较两个声明 digest。
- 多套按摘要登记的执行器支持旧/新版本；按 Run 冻结摘要路由。旧摘要不重写、不重新解释成完整字节证明；旧版本缺批准制品时阻断。
- 每个 Run 独立 home、job 与最小凭据；只读安装另存，重试状态按合同显式处理。环境白名单包含经批准的模型路由/凭据和运行所需变量，不展开控制面 process.env。凭据文件、Windows ACL 和网络隔离实测。
- 明确锁定 base + sdk-app profile；禁 tool-plugin-manager、schedule、tool-schedule、goal、command-goal、tool-goal 及 HMR 的实际路径。预检实际挂载集合，禁用 row 未命中报错。
- 按 plan 闭包生成 Run 装配，而非全量静态业务插件；无关插件升级不改变本应用组合摘要。相同真实闭包在不同部署路径应可重验。

**ASM-01**：分别篡改引擎、adapter、依赖、业务包、patch 次序/内容和 lock，消费输入前拒绝；缺制品无 fallback。

**ASM-02**：两批准组合并存，新默认不改变旧 Run；无关插件升级不使不相关应用审批失效。

**SEC-04**：两个 Run 不能读相邻 home/job/会话/凭据，不能使用管理 API；Run 环境无无关秘密。合成 canary 仅记是否可达，不输出凭据值。

**ASM-03**：真实挂载证明禁用项不生效、无自动恢复/goal 续跑；误写 row 或 sdk-minimal 替代基线明确失败。独立 home 本身不算 ISO-01。

### R3 — 员工 Web 不是治理旁路

拟改：employee-web patch、profile 生成/应用脚本、工作台代理与会话绑定；涉及行为改变先补 ADR-0003。

- 员工/运维采用不同命名 profile、配置权限与 home，不直接改共享出厂 web 来代表两个环境。
- 员工 Web 禁管理、持久任务/goal/HMR；排查命令、工具与恢复注入全部路径，不只隐藏侧栏树。
- 明确原生会话与 Run 会话写入所有权、员工身份映射和受治理业务执行路径。不允许没有 launch/知识/授权证据的 Web 领域执行旁路；若需保留另立等价合同。
- 保留中央原生 Chat、授权普通操作和问答体验；补原生设置、模型偏好、历史与窄屏入口。UI 隐藏不充当服务端授权。

**WEB-01**：在锁定宿主中直接工具/命令请求管理与定时/goal 均不可用，员工不能修改运维配置；记录真实挂载清单。

**WEB-02**：两员工会话列表、历史、直接 URL/API 和刷新隔离；同一工作返回同一会话，只有一个写入所有者。

**WEB-03**：浏览器实测单侧栏、设置、原生 Chat/问答/停止、刷新恢复及窄屏；保留浏览器证据，不用 patch 单测代替 UX-01。

### R4 — Worker 只消费服务端绑定知识

拟改：公开 KnowledgeAccess/代理、snapshot-readonly、知识 service/store/scope/http、控制面 bootstrap/绑定、插件知识消费者。

- 中心单库单写者，Worker 不按自己的 home 开活库；中心按已验证 Run 身份解析固定修订。模型传 snapshot/project/plugin 只能收窄，不能自选扩大授权集合。
- 必需知识绑定不可用时创建/派发明确失败；显式无知识策略只在获准应用/评测条件使用。候选查看与运行方法检索分离，禁止活库 fallback。
- 先修订批准清单与 project/shared 合成、受众权限、去重、上限/分页、撤回和替代语义；不直接以无过滤集合并扩大 scope。对非预期缩减预检并要求批准。
- 固定快照逐条授权、摘要和撤回检查，返回 excluded，不换新版；所有普通/短词/ID/固定检索路径一致。
- 完整分页查撤回影响 Run，已读内容在产物/复核面追加影响标记；回滚不复活撤回项。
- 迁移停写、备份、摘要/修订映射、授权对账和回退演练；禁止双写真源。

**KB-01**：控制/知识/Worker 使用不同 home，服务可跨进程；批准知识可消费、候选不可冒充方法、服务不可用无静默 fallback。

**KB-02**：双组织/区域、同名项目、shared、旧无归属及受众正反向覆盖所有读路径；crossScopeLeak=0。

**KB-03**：发布单条清单、缩减、撤回、替代、回滚、在途读取和超过现有分页上限的影响面均按批准语义处理。

**KB-04**：停写迁移/失败回退保持唯一写入者，快照修订摘要可对账。

### R5 — outbox 完成不等于学习完成

拟改：控制面 outbox/投影接线、知识分析台账/候选接口、指标与负责人的处理入口。

- 区分“事实已投递”“待分析”“已认领”“候选已生成”“不需沉淀/重复/证据不足”。状态字段设计先批准，不以 outbox delivered 计算知识积累。
- 分析主体经认证，绑定 run/投影/输入产物摘要及可信租户范围；无草稿保持待分析。允许不产出，但必须记录原因，不强求失败 Run 自动生成方法。
- 候选新建与重复处理幂等；项目经验跨项目另建并去项目化；台账按 tenant/project 授权。
- 指标包含投递数、待分析/老化、认领、候选产出率及明确不产出的分母。老化阈值先批准，未定不得记为达标。

**LEARN-01**：批量合成失败 Run 投递后候选为零时，台账和指标如实显示未完成；分析后可追溯候选或不产出原因，重试不重复建候选。

### R6 — 独立验证，不降种子门槛

拟改：验证目录、请求/回执/租约、独立执行器与部署、knowledge-accept 过渡脚本、种子贡献与 claims/coverage。

- 实现验证合同 K01–K08 的独立执行域：只运行批准制品和固定用例，锁定候选/验证器/套件/plan/bundle 摘要，隔离 epoch 与一次性回执身份。
- 中心核验身份、请求绑定、非空覆盖、逐用例执行与退出事实，事务 CAS；未知、过期、篡改、缺项不激活。普通模型 passed=true 不是有效回执。
- 本机验收脚本明确为过渡工具，补可信租户与主体并限制权限；不得把它称为生产独立执行器。迁移后不得保留绕过可信回执的激活路径。
- 种子正文拆成可验证 claims 并绑定批准覆盖；函数回归只写 TOOL_REGRESSION_ONLY。无 claims 的参考记录不进入已验证方法；不能靠“固定测试通过自动 ACTIVE”补数量。
- 技术激活与业务发布批准分别授权；发布记录绑定验证器制品、插件兼容范围和必要评估证据，受众不是自由字符串旁路。

**VAL-01**：执行 K01–K08 工程回归，覆盖伪造/重复/冲突回执、缺项、候选变更、执行器崩溃和跨租户请求。

**VAL-02**：无 claims 种子及函数测试通过仍不激活正文；全部内容 claims 有有效覆盖和回执才激活；第二主体完成业务发布。

**VAL-03**：一个来自 R5 的候选走完独立验证→中心激活→批准发布→新 Run 固定消费，旧 Run 不漂移；证据记录整链而非工具返回摘要。

### R7 — 可观测消费与可执行效果对照

拟改：黄金集/评测脚本、Run 评测策略、检索证据存储/引用对账、工作台 excluded 面板、公开检索接缝。

- 先冻结按插件、语言和查询类型分层的盲测夹具、相关性标注、recall@5/MRR/延迟阈值与评分预算；答案由独立 QC 保管，不给 Agent。
- 度量未命中诚实性、跨域泄漏、短词全量解码成本、索引容量和写入排队。性能注明数据量、分布、冷/热缓存、并发和环境，不引用无快照的 2ms。
- Run 持久保存检索返回修订、excluded、调用与引用关联；reconcile 生产调用。cite 只作为声明引用，未知采用不标成成功。
- 在批准隔离评测环境引入 B/K 策略；仅授权评测主体能关闭知识，不能让普通用户绕过必需知识。保持应用制品、输入、模型与预算一致，策略及上下文摘要不同如实记录，不能要求整份 Run 摘要不变。
- 报告同类错误率、质量/成本差、未决分母、失败和不确定性；无收益不写 PASS 收益。向量/后训练进入条件各有观测字段及批准记录。
- 设计检索 Service Definition/Provider/Consumer 接口，先以 FTS 实现回归；向量只评估派生索引，不改真源和作用域。

**USE-01**：C1 完整分层报告及冻结阈值可复验。

**USE-02**：C2 已声明引用/未引用/未知/撤回证据持久可查，模型自报不得升级为可证实效果。

**EVAL-K-01**：B/K 除批准知识策略外可比；盲测、预算、分母、指标差和失败报告完整。此用例不替代试点 EVAL-01。

### R8 — 发布工程与插件增长不改平台分支

拟改：各包 package/exports/build/locks、边界检查器、CI、应用描述转换与扩展验收脚本。

- 决定根 workspace 或逐包制品路径并记录 ADR；根 workspace 尚未建立前不能直接引入 workspace:*。
- 消除相对 src 跨包引用；纯库不依赖 UI，平台知识依赖经公开接口；类型和值入口都有打包后解析测试。private 包定义内部制品供给，消费者安装不依赖仓库布局。
- 检查器覆盖 packages/plugins/scripts 的导入、再导出、可确定动态导入与 exports；补锁文件与干净安装，不能只靠检查器绿证明独立升级。
- 双 OS 验证受影响包与消费者，涉及宿主入口/Client/profile 时做锁定宿主装配。全量候选验证留 hosted runner 报告；必需合并检查由仓库管理员设置并留策略证据，手动 workflow 存在不等于合并门禁。
- 不同类型合成应用经公开合同接入，不加插件 ID 分支；测试声明式展示与卸载。先压测 100–200 合成目录，再测实际闭包启动、schema 体积/冲突和目录过滤。

**ENG-01**：规范/self-test、包外干净安装与消费者构建通过，引用清单闭环，锁文件可重建。

**ENG-02**：同候选双 OS CI 与宿主报告，必需检查策略可查；未运行保持 NOT_RUN。

**EXT-SYN-01**：不同类型合成应用全链路及目录/启动报告，阈值预先冻结；不冒充真实业务插件或目标环境 EXT-01。

### R9 — 目标环境放行

严格执行[试点清单](ENTERPRISE-AGENT-PILOT-ACCEPTANCE.md)：ID-01/02、ISO-01、REL-01、RUN-01/02、UX-01、QC-01/02/03；扩大范围前执行 EXT-01/EVAL-01/OPS-01。

- IT 提供两名真实独立身份、项目/资料 API、会话映射、部署凭据和执行域，提前冻结撤权时限、网络/目录矩阵、RTO/RPO。
- 对账实际模型 provider/adapter/区域/留存及知识受众；未知用量不按零处理。
- 独立 QC 绑定当前输入、Run 和工件，不沿用旧批次结论；放行记录指定组织、项目、应用/模型版本、场景、数据类别与区域。
- 工程合成绿不冲抵试点 P0。适用 FAIL/BLOCKED/NOT_RUN 或缺证据即不放行；试点不是生产批准。

## 3. 迁移与回退统一要求

1. schema/凭据/摘要格式变更先版本化，备份旧库和不可变制品；旧 Run、releaseDigest、回执和工件不就地改写。
2. 知识迁移采用停写窗口、唯一所有者、摘要映射与正反向对账；失败恢复原所有者，不并库双写。
3. 部署回退只切新工作默认指针，核验原批准制品实际可用；不将已撤权或已撤回版本重新开放，不回退到无鉴权状态处理真实数据。
4. Worker 中断/清理未知保留 UNKNOWN 并对账，不自动重跑可能已有副作用的任务。
5. 每个工单注明回退命令、触发条件、验证人及备份引用；外部不可用标 BLOCKED，不发明“自动成功”替代路径。
