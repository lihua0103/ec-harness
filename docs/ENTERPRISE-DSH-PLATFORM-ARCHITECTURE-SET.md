## 1. 规划诉求与架构含义

| 规划 | 架构要求 |
|---|---|
| 临床业务全部插件化 | 领域语义留在插件；平台不加具体插件 ID 分支，不为每个插件起服务或建库。 |
| 按项目沉淀经验 | project 裁定绑定项目；跨项目复用需去项目化新建、重新验证和授权发布，禁止原地提级。 |
| 逐步开放给员工 | 用户、项目、应用、模型及数据授权都由可信服务端事实决定；安装包不等于员工可用。 |
| 几十到上百插件 | 应用目录与运行装配分离；按真实负载验证启动成本、工具 schema 体积、冲突和目录权限过滤。 |
| 国际化 | 语言是记录 facet；区域是物理部署与数据驻留边界；不默认跨区多活多写。 |

## 2. DSH 能力与平台责任

DSH 的 Cordis 插件、服务接缝、profile/bundle 和配置叠加机制作为基础。企业平台补授权、装配可验证性及知识治理，不 fork 上游来加入业务分支。

- **插件与 provider**：通过公开 Service Definition / Provider / Consumer 接口扩展；不假定所有目标接缝已存在。
- **配置分层**：profile、bundle 与有序 patch 会共同影响有效配置。禁用项必须命中实际 row id；警告或不存在的行不能当作禁用成功。
- **会话事实**：引擎会话日志归 DSH；控制面保存 Work/Run/Artifact 权威事实及会话引用，不建第二套可写会话库。
- **SDK 边界**：锁定版无 per-session close、无 prompt-cancel，不能假装细粒度取消；采用进程终止与监督证据。未知结局不转成成功。
- **授权边界**：工具不可见不是安全隔离；回环端口不是认证；独立进程或独立 home 不是沙箱。

### 3.1 两种执行域必须分别治理

**Web 原生会话是第二执行域**：当前中央会话在 Web 宿主执行，可触达 preset 带来的工具，不天然具有 Run 的 launchId、完成屏障或固定知识绑定。保留原生 Chat 不意味着允许它绕过控制面执行受治理业务。

目标为：员工宿主禁管理、schedule、goal 和 HMR 变更路径，校验会话所有权；受治理业务经控制面进入 Run。若仍允许宿主执行领域工具，必须另行定义同等授权、知识绑定、执行证据和隔离，未经 ADR 与验收不得启用该旁路。不得以禁用工具为由增加普通授权读取或普通 R 开发审批。

### 3.2 五对象分离

| 对象 | 含义与权威 |
|---|---|
| PluginPackage | 技术制品；安装或构建通过不等于业务批准。 |
| Capability | 版本化能力；计划绑定唯一 provider，不按名字猜实现。 |
| Application | 员工入口及纯数据描述；应用内部选项不污染平台分类。 |
| ApplicationRelease | 不可变发布；批准绑定 releaseDigest，不静默改在途 Run。 |
| RuntimeBundle | 引擎、依赖闭包、profile、有效配置与制品组合；不得与可写 home 混为一物。 |

### 3.3 一次 Run 的装配和执行

1. **发布期**：解析唯一 provider 与传递依赖闭包，冻结 planDigest 和制品清单；目标为 releaseDigest 只受本应用实际闭包影响。当前部署摘要含全部已扫描应用的包名版本，存在无关升级耦合。
2. **创建期**：冻结发布、计划、输入、模型及知识引用。幂等语义依运行合同；本轮未复验提交幂等路径，不凭摘要存在宣称其通过。
3. **派发期目标**：按摘要选执行器，核验安装字节与有效配置，再以独立 Run home、最小凭据启动。**当前**核对配置中的 runtimeBundleDigest 声明值并核对业务插件制品；未完整重算引擎、patch 和依赖字节，home 为部署级共享配置，profile 静态装配。
4. **执行期**：原生 Agent 自主规划，平台传目标、授权引用及验收事实，不指定工具顺序。Run 凭据只访问自身允许资源，知识参数只能收窄服务端派生范围。
5. **结算期**：按运行合同检查输入消费、后代结算、工件封存、清理及退出证据；缺失证据保持 UNKNOWN。进程监督机制有代码，但目标环境恢复与隔离仍须实测。

### 3.4 知识闭环：目标与断点

```text
Run 终结事实 → 持久 outbox → 投影/待分析台账
  → 有负责人的分析（产出候选或记录不产出的原因）
  → 项目经验去项目化新建（需要跨项目时）
  → 独立 ValidationExecutor 验证候选 claims 与覆盖绑定
  → 中心核验身份、摘要、用例、epoch、退出事实并 CAS 激活
  → 独立业务发布审批 + 受众授权 + 不可变清单
  → 新 Run 固定绑定 → 检索证据 / 引用对账 / B-K 效果评估
```

现状为带人工断点的开环：outbox 泵可把“待分析”投影记为交付完成而不产出候选；验证数据结构与本机验收脚本存在，但独立部署执行器与可信回执链路未实现；控制面直读本地库，Worker 可回落活库，跨 home/跨机固定绑定未闭环。

**不可越过**：知识不是授权；模型自报 PASS 不激活；ACTIVE 不是临床批准；项目裁定不自动跨项目；固定函数测试通过只形成 TOOL_REGRESSION_ONLY，不能自动激活正文方法。种子须具有明确 claims、批准覆盖和有效内容验证；无 claims 者只作参考，不以自动激活补可达率。

发布清单与 project/shared 的合成规则、受众读授权、缩减保护及替代清单要求需对齐知识专项合同。评审建议的“清单 ∪ project”不是本文新增算法：必须先证明只包含获准修订、处理去重/撤回/权限且不扩大 scope，再批准接口语义。历史快照不换新版；撤回/撤权逐条进入 excluded，对已使用内容追加影响标记和复核要求，不声称能抹掉模型已读上下文。

| 环节 | 现状 | 必须补齐的证据 |

向量默认不启用：黄金集 recall@5 低于预先批准阈值，或 FTS 超出目标负载下预先冻结的性能/写入预算，任一发生才启动评估，**不自动上线**。历史“20k 条 2ms”“p95 ≤ 120ms”未在本轮复测，不能当成已达标；120ms 可作为待确认预算，不是实测结论。短于 trigram 的查询必须独立评估回退成本。

权重后训练默认不启动，四个进入条件须同时有证据：多个独立项目重复同类错误；知识已被正确检索和采用；补知识/改表达/修工具仍无效；训练材料、模型与数据政策获准。用冻结盲测集比较 M 与 K，收益阈值先定再测。K 无改善时优先定位检索、采用与方法错误，不以换模型掩盖断点；K 有改善也不自动证明后训练有收益。

## 5. 优化设计与实施约束

### 5.1 包与依赖

采用显式有向无环依赖图，而不是“只允许相邻层、同层绝不互引”的不可执行规则。合同/纯库不得依赖 UI 或部署入口；业务插件之间不源码互引；平台消费者经公开接口访问知识；图表核心不得依赖工作台，公共知识类型/种子契约移到合适的低层接口。

根目录当前无统一 workspace。先确定唯一工程路径（根 workspace 或逐包发布/打包安装），补 exports、构建产物和依赖锁再迁移引用，不直接写 `workspace:*`。private 包的内部制品策略须明确；仅换 import 字符串不算独立发布成功。检查器扩展 packages、plugins 与 scripts，打包后在仓库外干净安装/导入验证。

### 5.2 三 profile 与 home 拓扑

| Profile | 现状 | 冻结目标 |
|---|---|---|
| employee-web | 仅侧栏 patch；脚本可修改出厂 web profile | 员工独立命名/配置，禁管理与原生持久任务/goal/HMR 旁路；会话隔离和原生设置入口实测。 |
| operations-web | 尚未证明与员工独立 | 独立入口、管理身份、配置写权限和 home；不复用员工可写 profile。 |
| worker | base + sdk-app，部署级静态 bundles，共享 home | 明确采用锁定 base + sdk-app 基线；goal/command-goal/tool-goal 等按实际 row 集合禁用，未知/未命中禁用项预检失败；按 plan 闭包装配。 |

三类 profile 使用同一清单格式和核验算法，**不同组合分别生成摘要**，不强迫共享一个 digest。Worker 的只读安装与可写 Run home 分离；重试尝试的状态复用按运行合同显式定义，禁止串 Run 共用可写 home。

### 5.3 身份、凭据与执行域

- 部署适配器验证签名、issuer、audience、有效期/时钟容差和重放策略，再派生 Principal；本机替身仅用于合成测试。
- 审批、QC 和管理角色来自服务端，忽略请求体自报身份；职责分离不能靠不同字符串模拟第二人。会话到员工映射及审计含真实主体、租户、项目、动作与对象。
- 代理剥离客户端身份头；控制/知识 API 强制验证受众受限凭据，普通 Worker 不持有管理、发布或激活权限。
- 环境白名单和短期 Run 凭据与网络/文件系统策略共同限制 Worker；模型密钥仅在获准执行链路提供，不继承控制面全部秘密。
- 独立进程/home 只是治理措施，容器、VM、远程执行或经证明有效的 OS 隔离由 IT 决定并实测。撤权时限、通道、密钥轮换、RTO/RPO 须在试验前批准，未知不记为零。

### 5.4 知识服务迁移

控制面/工作台/Worker 逐步收敛到公开 KnowledgeAccess。本地适配可过渡，但不能以文件路径作为跨机合同；必需绑定缺失或鉴权失败即阻断，获准无知识应用应显式记录“不适用”，不得静默回落活库/候选。

中心仍保持一个写入所有者；切换需停写、备份、修订与摘要映射、授权对账及可演练回退，不建两个可写权威库。验证器可执行代码留在独立批准执行域，不 import 进控制面来冒充跨进程验证。
