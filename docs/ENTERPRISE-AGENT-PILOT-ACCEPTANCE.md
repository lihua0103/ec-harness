# 企业智能体平台试点验收清单

**范围：** 同一受控目标环境内的 DSH 原生工作台、DM Listing、DM DVP 和公共控制面。**状态：** 验收模板；下列用例均为 `NOT_RUN`。此前本机 E2E、包级测试和备份演练可作为参考，不计为本次目标环境通过。

本清单执行现有[身份与数据](ENTERPRISE-IDENTITY-AND-DATA-CONTRACT.md)、[应用发布](PLATFORM-APPLICATION-RELEASE-CONTRACT.md)、[运行生命周期](PLATFORM-RUN-LIFECYCLE-CONTRACT.md)和[知识验证](PLATFORM-KNOWLEDGE-VALIDATION-CONTRACT.md)合同，不另设 Agent 工具调用顺序或普通读取、普通 R 开发审批。

## 1. 验收前登记

- **环境与范围：** 试点编号、时间（UTC）、目标环境、组织、项目、数据类别、允许的模型端点/区域/留存与外发政策。先使用合成或公开资料；真实资料须由 IT 和业务方确认既有授权与使用范围。
- **可复现基线：** 平台源码修订或完整源码摘要、部署制品与配置摘要（不含密钥）、DSH 版本及 commit、Node/R 及依赖版本、两应用的 `releaseDigest` / `planDigest`、模型目录版本、输入和 QC 夹具摘要。项目当前上游基线见 [UPSTREAM-BASELINE](UPSTREAM-BASELINE.md)；以目标环境实测为准。
- **人员和夹具：** IT/部署负责人、平台执行人、独立业务 QC、放行负责人；准备两名独立员工身份、两个隔离项目和可撤权的测试成员，另备结果期望表与空恢复环境。多组织若在放行范围内，再加入第二组织。约定撤权、恢复与备份的时限或 RTO/RPO，不在执行后倒填阈值。
- **记录方式：** 每条记录用例 ID、执行人/时间、环境与版本、实际结果、证据引用、缺陷与复验记录。状态用 `PASS` / `FAIL` / `BLOCKED` / `NOT_RUN` / `N/A`；`N/A` 须说明为何不适用并记明批准范围。证据放受控位置，不把真实临床正文、凭据或全量会话放进 Git、公开日志或验收附件。

## 2. P0 — 试点放行门槛

| ID / 主责 | 执行场景 | 通过条件与最低证据 | 状态 |
|---|---|---|---|
| ID-01 · IT / 平台 | 在目标环境用两名员工分别进入自己的项目，再尝试访问另一个项目的工作、会话、运行与工件，包括直接调用平台 API。若放行范围含多个组织，则重复做跨组织检查。 | 正向访问成功；跨范围服务端拒绝，搜索/列表不泄露对象；审计能辨识实际身份和项目。留访问矩阵、脱敏响应和审计引用；替身目录不计通过。 | NOT_RUN |
| ID-02 · IT / 平台 | 在测试 Run 执行中撤销成员或资料访问授权，观察新 Run、新输入/答复、下载和在途 Worker。 | 在约定时限内拒绝新动作，保存取消意图及监督器证据；不能证明终止则保持 `UNKNOWN` 并继续对账。留撤权时间线、授权决策及进程结局。 | NOT_RUN |
| ISO-01 · IT / 部署 | 在实际执行域，以合成资源检查 Worker 只能使用批准的目录、网络及执行凭据，并检查相邻 Run、控制面与证据日志的隔离。 | 获准数据与普通 R 操作正常；未授权资源不可访问；不向 Worker 或日志暴露无关凭据。留环境策略和正反向实测。独立进程或 profile 本身不算隔离证明。 | NOT_RUN |
| REL-01 · 部署 / 平台 | 在独立候选部署验证两插件的加载、调用、适用的 Client 挂载及卸载；用不匹配摘要或缺少必需能力的候选做拒绝检查，再演练回退。 | 未批准或不匹配候选不能接收业务输入；恢复后原批准版本可处理新 Run，旧 Run 和既有工件仍指向原摘要。留预检报告、激活/拒绝/回退记录与回退后实测结果。 | NOT_RUN |
| RUN-01 · 平台 / 部署 | 创建 Run 后更新候选发布、模型目录或适用配置，观察排队、在途与合法重试。 | Worker 核对其冻结的发布、计划、模型、输入及适用知识引用；不能取得原组合时明确失败，不静默换配。留提交快照、实际装配记录与对比结果。 | NOT_RUN |
| RUN-02 · 平台 / 部署 | 在试点中断 Worker 或重启控制面，覆盖发送结局不明及已可能产生副作用的运行；再用隔离恢复环境核对备份。 | 不把未证实结局写成成功或已取消，不自动重发/重跑未结尝试；对账后才能按合同处理。恢复到约定 RTO/RPO，抽查运行与工件索引、授权和摘要。留尝试时间线、恢复报告和摘要核对。 | NOT_RUN |
| UX-01 · 平台 / 业务 | 在原生工作台完成一次工作，刷新、断线重连、重进历史工作，再查看或下载交付物。 | 中心仍为原生 Chat；可回到同一工作和会话，不重复提交；运行与交付在右侧查看，明确区分对话结束、运行成功、业务复核。下载内容与已登记摘要一致。留工作/会话/Run/工件关联及交互记录。 | NOT_RUN |
| QC-01 · DVP 独立 QC | 用冻结的合成或公开方案和模板，按预先约定的抽样范围复核关键规则及例外。 | 可从规则定位到方案页/表，条件、阈值、单位和例外与来源一致；未知项明确标注，不当已确认规则。留输入及工件摘要、抽样口径、逐项预期/实测及签署结论；适用边界按 [DVP 模板合同](DVP-TEMPLATE-SCHEMA.md)。 | NOT_RUN |
| QC-02 · Listing 独立 QC | 用冻结的输入、批次和场景期望独立复跑交付 R 代码；覆盖空结果、关键边界和换批。 | 对照预先约定的场景合同核对行数、关键业务键、批次归属、规则命中、必要输出及复跑差异；旧批次产物不会被覆盖。留独立运行日志、实际对账及工件摘要；只批准实际验收的 Listing 类型。 | NOT_RUN |
| QC-03 · 业务 / 平台 | 对已复核的工作更换输入批次或产物，再尝试查看或沿用旧结论；从审计侧倒查交付。 | 旧结论只属于原版本；当前交付不显示为已经复核。可从工件追溯输入、发布、实际运行及独立 QC 记录，且四者不是同一个状态。 | NOT_RUN |

故障操作和排查参考[平台故障手册](PLATFORM-FAULT-RUNBOOK.md)。仅在专用试点环境使用合成资源演练，不在生产 profile 上试错。

## 3. P1 — 扩规模前验收

| ID / 主责 | 通过条件 | 状态 |
|---|---|---|
| EXT-01 · 平台 / 插件维护者 | 用一个不同类型插件验证：经公共契约完成登记、装配、运行、声明式结果展示与卸载；平台不加插件 ID 分支，不替换中心 Chat。留接入差异、装配证据和卸载结果。 | NOT_RUN |
| EVAL-01 · 平台 / 独立 QC | 将常规回归与保留用例分开，Agent 不接触评级答案；评估技能时用同模型、同预算进行有/无对照；知识候选以批准验证器和实际回执判定。留用例版本、评分证据和未覆盖项。 | NOT_RUN |
| OPS-01 · 平台 / IT | 能将试点运行的实际模型路由、耗时、可得用量、失败原因和 QC 结论关联；未知用量标 `unknown`，不按零计算。对拟上线地区核对路由、留存与数据位置；缺乏证据的地区不纳入放行。 | NOT_RUN |

## 4. 放行记录（每轮填写）

```text
试点编号／环境／验收日期：
批准范围（组织、项目、应用版本与场景、数据类别、模型与地区）：
P0 汇总（PASS / FAIL / BLOCKED / NOT_RUN / N/A）：
证据位置与未覆盖范围：
缺陷、限制、责任人、复验条件：
决定（不放行 / 仅限指定试点范围）：
平台、IT/部署、业务负责人确认及日期：
```

**判定规则：** 适用 P0 有 `FAIL`、`BLOCKED`、`NOT_RUN` 或缺证据，不放行对应范围；不能用 P1 通过、本机演示、模型自报或单元测试冲抵。未通过身份隔离的环境只可用于获准的合成/公开资料演练，不开放真实数据。试点放行不是生产批准；扩大数据、用户、区域或能力范围时重新评估受影响用例。
