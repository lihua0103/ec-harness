## 1. 当前系统究竟是什么

本轮只读核查，未启动、未运行测试，未读取临床资料、数据库、会话日志或秘密。源码存在其他会话并行整改，路径/行号为读取时证据，不是冻结发布基线。已有测试源码不等于本轮执行结果。

当前是**正式 Web 工作台 + 本地单 owner SQLite 控制面 + 可选 DSH profile/SDK Worker**，不是企业项目协作、受管桌面和业务审核全部完成的产品。不能只按旧设计中“尚未实现”判断现状，也不能按新按钮断言能力闭环。

## 2. 核心裁定

### 2.1 项目不等于文件夹，执行目录不等于存储权威

Project 是业务与授权对象。ResourceRevision 是获准资料版本。ExecutionWorkspace 是一个节点上可执行目录。DSH_HOME 承载配置和原生会话；profile 是装配定义；cwd 是本次工作文件上下文。四者不能混成一个“项目路径”。

本地 Worker 可以使用本机文件和 R，但仍可能把 prompt/工具结果发给远程模型。本地执行不等于无外发。中心 Worker 看不到员工电脑的 `D:/...`；不得把该字符串传给服务器冒充上传成功。

资料接入采用适用模式：受管本地引用、受控上传后快照、共享存储挂载、授权 API 版本。每种明确授权者、版本方式、传输和保留；不对普通已授权读取新增人工审批。

摘要不是快照：扫描与启动之间文件可能被替换，映射盘可能离线，跨节点同名目录可能指向不同内容。启动前核验与原子快照/稳定源版本绑定，读入过程也须避免混合版本；无法固定内容则标明不可复现并由适用用途决定能否使用。Run 工作目录与项目源目录分离，默认不写回源数据；产物写入自有运行目录并封存，不覆盖旧结果。历史复现还需可取得的内容、依赖/程序和环境，不能只留 hash。

### 2.2 持久项目空间与单次执行空间

补充参考[蓝图 §6.1–6.2](clinical-workbench-review/00-product-blueprint.md)，主需求FR-27–FR-29为待评审增量。

ProjectWorkspace持久归属项目，拥有稳定ID及配置修订，登记真实服务器项目目录/授权资源、可用节点、程序与输出位置；Work绑定该空间。ExecutionWorkspace是某次Run实际使用的cwd/写入区域，Run固定空间配置版本与解析后的节点/路径。两者不能混用，不能让员工每次重填路径。

已有服务器目录直接受控引用或挂载，不强制迁移/上传；Worker执行身份须实际可达，路径字符串不是授权。默认独立Run写区，通过明确映射呈现原资料和程序快照。已有相对路径布局需应用声明并实测；必要布局适配或独占写租约必须覆盖真实目录的全部写入者，不能仅锁一个Work就宣称防冲突。cwd不等于沙箱，也不另加普通读取审批。

项目页汇总空间下多项Listing及其他工作历史，完整会话共享仍另按权限判定。线下历史登记保留来源/导入人员/时间/未知项，不补造执行和批准；挂载点或目录名变更保留workspaceId，旧Run继续显示当时配置。项目创建初期记平台来源，企业接入后显式稳定ID绑定，不能按名称自动迁移归属。

### 2.3 推荐中心权威控制面，执行位置可选

```text
员工工作台（Web；桌面宿主后续单独验收）
  → 平台 API / 可信身份 / 项目和动作授权
  → 项目资料、Work/Run、交互、成果版本、复核、交付、审计
  → 调度与版本化 DSH Adapter
      → 中心受控 Worker
      → 企业受管本地 Worker（确有本地 R/文件需求时）
  → 锁定 DSH profile/SDK、公共能力、领域插件
```

首期模块化单体控制服务即可；执行域独立，进程分离不冒称沙箱。企业事实与模型路由由 IT/部署合同落实。Web 无法独立提供任意本地目录执行能力；选择桌面/本地代理须走受限 IPC、身份、签名更新及实际 OS 隔离验证，不先为美化 UI 套壳。

### 2.4 会话、工作、成果三种权威分开

| 对象 | 推荐权威 | 可保存在浏览器的内容 |
|---|---|---|
| 企业项目/成员 | 企业事实 API；控制面保存受控引用/版本 | 授权后的显示缓存 |
| Work/Run/输入提交/复核/交付 | 平台持久存储，中心部署后为服务端权威 | 非权威投影和草稿 |
| 原生模型/工具会话 | DSH 原生持久后端，运行节点或受管存储 | 按权限读取的投影，不复制为第二套 session schema |
| 输入/程序/结果 | 版本化资料/成果库，内容摘要及保留合同 | 有范围的本地缓存 |
| 密钥 | 企业 secret 设施/受管凭据引用 | 不保存 |

本地 Worker 的原生 session 若仅在本机，设备离线/损坏就不能保证服务端即时访问或恢复。换设备可以看中心 Work/Run 元数据，不等于完整会话可读或任务可恢复。企业部署前必须选择受管归档/备份或接受并标识限制；归档应有授权范围、完整清单/摘要、上传完成回执和保留策略，未确认完整不得显示已备份。原始会话可含临床数据，不能默认全量上报日志或知识库。

## 3. 领域无关的对象增量

以下为拟议合同，不是已有接口：

- **ProjectBinding**：稳定企业项目 ID、来源版本、阶段引用；不按目录名推断。
- **Work**：长期目标、应用、项目、责任/协作者、共享范围、生命周期；复用现有对象。
- **WorkBaselineRevision**：资料引用、数据批次、选项、程序/规则/SAP 等确切版本及来源；领域清单由应用贡献。
- **Run**：冻结基线、应用发布/执行计划、模型路由、运行配置、知识快照及输入提交；补齐现有记录。
- **EngineSessionBinding**：Run/执行域/session/home 引用、版本、游标、epoch、恢复能力；在执行前/建立时持久记录，不等成功才保存 ID。
- **ArtifactRevision**：不可变内容、来源 Run/基线/输入消费范围、类型、摘要、检查证据；已有封存能力继续使用。
- **Issue/Decision**：跨运行稳定问题、来源版本、迁移理由；不靠模型摘要制造人类裁定。
- **ReviewRecord**：实际人员、用途、成果摘要、范围、结论和时间；电子签名单独评估。
- **DeliveryPackage**：固定清单及摘要、复核引用、接收对象、交付事实、替代/撤回关系。

内容不变也不代表所有旧证据适用；输入变更后通过显式影响判断关联复用证据，不拷贝一个 approved=true。

## 4. 重跑、恢复和会话续接

| 操作 | 对象变化 | 保留条件 |
|---|---|---|
| 查看/网络重连 | 无新 Run | 按游标读取持久事实 |
| 同一活跃会话补充 | 同 Run 新 input commit | 持久接纳、排序、投递/消费证据；冻结发布/模型不偷偷变 |
| 引擎故障技术恢复 | 原 Run/session，新 launch epoch | 原持久记录、写入租约、配置和副作用已核对，支持恢复才执行 |
| 失败后重试 | 新 Run，retryOf | 明确选定完整输入基线，不仅包装旧初始 prompt |
| 换数据/需求/代码重跑 | 同 Work 新基线、新 Run | 新成果和本次检查；旧交付保留适用范围 |
| 换项目/应用 | 新 Work 或显式关联工作 | 不把旧权限、工具和裁定静默带入 |

锁定 DSH `0.2.2-rc.1` / `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的公共源码核查：`sdk/client/src/api.ts:99-119` 中 `session(id)` 不等于磁盘恢复，恢复走 `resumeSession`；未指定 sessionId 的 high-level run 创建新 root；close 是整个 runtime teardown，不是某个会话关闭。`sdk/server/src/server.ts:570-595` 恢复初始化可覆盖模型选择，因此必须用原冻结路由。不用当前 UI 默认模型恢复旧 Run。实施时再核实际锁定版本，不发明 SDK listModels RPC 或 AbortSignal 参数。

## 5. 模型管理与运行就绪

员工看到：允许模型、适用能力、路由地区/数据使用说明、可用性与最近探测时间、本次固定选择。管理员看到：provider/adapter、端点、凭据引用、版本、地区、预算和策略；不在浏览器显示秘密。

模型状态至少区分目录声明、已装配、探测成功/失败、最近真实调用；就绪不只检查“目录非空”。Run 冻结实际 route/model/参数、目录版本、profile/config 摘要及非秘密凭据版本引用。主调用、子智能体和辅助调用的实际路由范围一起核验，不能只限制下拉框。

执行就绪检查覆盖 Worker、profile/插件版本、数据可达、R 等能力、模型路由及存储；缺环境可保存草稿，不能宣称已执行。探测是技术事实，不要求每次普通开发新增业务批准。

## 6. 工作台信息架构

顶层稳定为：工作首页、项目、应用中心、待我处理、成果/记录；管理按权限展示。插件数量不增加顶层栏目。

**项目页**：阶段/职责、资料版本、执行环境、持续工作、里程碑与交付。 
**工作页**：目标和当前基线；运行历史；聊天/活动；程序与文件；差异和检查；待办/复核；交付历史。 
**新运行**：默认继承明确基线，突出“本次变了什么”，显示执行位置、资料范围和模型就绪。 
**历史版本**：只读并标明适用输入；查看不自动启动或切换当前成果。 
**空态/故障**：无项目、无授权数据、无 Worker、模型不可达分别给归属明确的诊断；“保存草稿”与“启动运行”分开。

不要求所有员工看到终端/Git；专家视图可看真实路径、代码、日志和配置来源。应用贡献专业参数、文件视图、差异与检查语义；通用平台不解析 DVP 规则或硬编码 Listing 类型。

## 8. 全生命周期对象补充与评审映射

已核对[独立产品蓝图](clinical-workbench-review/00-product-blueprint.md)、[现状快照](clinical-workbench-review/01-current-state-and-gaps.md)和[反例矩阵](clinical-workbench-review/02-scenario-acceptance-review.md)。它们是补充资料，不建立第二套需求权威。主需求新增 FR-19–FR-26；映射如下：

- 基线引用资料版本，同时保存应用解释的适用范围/生效依据，不用全局 latest 代替中心/对象有效版本。
- CoverageEvidence 保存本次目标的应收/已收/已查范围、分母来源和未覆盖原因；分母未知保持未知，不禁止有缺项草稿。
- Issue 是持续问题；Observation 是某Run/批次的观察。匹配键、规则身份和重评依据由应用贡献；通用平台不按行号猜测。
- ExternalHandoff 记录对外发送及回流的独立事实、外部ID和回执等级；超时保持未知，不盲目重复副作用；不在首期默认写回外部临床系统。
- Decision/Review/Verification补充用途、依据、适用范围、独立性和重评条件；不是再增加一个永久approved布尔值。
- ReadinessAssessment按用途汇总已确认条件和例外，不能代表平台有锁库权限；DefectImpact沿程序/规则/环境来源关联历史交付和通知。

这些是业务关系，不要求按名词机械拆包、建微服务或另造流程引擎。优先在现有控制面/应用贡献中落实；受影响schema/API在开发前冻结并评估迁移。历史 Worker E2E 的独立factory及固定路由不证明工作台模型选择端到端闭环，须在对应纵向切片重新取证。

## 9. 尚未冻结的部署决策

推荐中心控制面为企业权威，首个执行切片选真实需求最迫切的受管节点；不默认所有任务搬到云或强行都本地。IT 与业务需确认本地 R/资料要求、身份源与项目 API、模型地区/外发、管理员与盲态、会话存储/保留、RTO/RPO、复核与电子签名适用性。

本方案补齐既有多插件/运行合同的产品语义，不通过新文档悄悄取代 ADR。发现 ADR-0002 中恢复/重试命名与生命周期合同不同，列为评审决策；获准后由合同维护者同步，当前不修改其文件。
